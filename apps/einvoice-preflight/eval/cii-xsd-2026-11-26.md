# CII schema pass against xmllint (2026-11-26)

What was measured: whether `cii-xsd.mjs` (the CII D16B EN 16931 subset schema, read by
`build-cii-schema.mjs`) gives the same valid/invalid verdict as libxml2's schema validator on the
same XSD.

- Schema: ConnectingEurope/eInvoicing-EN16931 at `b17b2695e5e3e021945c38658326b78a76f80f84`,
  `cii/schema/D16B SCRDM (Subset)/uncoupled clm/CII/uncefact/data/standard/CrossIndustryInvoice_100pD16B.xsd`
  (163 complex and 89 simple types after reading). Licence: UN/CEFACT's notice in each file
  permits derivative works that assist implementation with the notice kept; the generated data
  module carries it. The XSD itself is not in the tree.
- Validator: `xmllint --noout --schema` (libxml2, the container's `/usr/bin/xmllint`).

## Unaltered files

| Files | Taken by the pass | xmllint valid | Pass reports nothing |
|---|---|---|---|
| CEN `cii/examples/*.xml` (15) | 12 (3 declare the old ZUGFeRD 1 COMFORT id and are skipped) | 15 | 12 of 12 |
| This folder's EN 16931 / CIUS CII examples and fixtures | 7 | 3 before the fixes, 7 after | 3 before, 7 after |

The four this folder's files that failed both validators before the fixes, same element each time:

- `examples/cii-invoice.xml` (and `examples/factur-x-invoice.pdf`, built from it):
  `PaymentReference` after `InvoiceCurrencyCode`; `AllowanceTotalAmount` before `ChargeTotalAmount`.
- `examples/xrechnung-cii-credit-note.xml`, `examples/xrechnung-cii-credit-note-with-defects.xml`,
  and the two Factur-X credit-note PDFs: `udt:DateTimeString` inside `FormattedIssueDateTime`
  (BT-26), where the schema requires `qdt:DateTimeString`.
- `examples/nlcius-cii-invoice-with-defects.xml`: `CountryID` after `CountrySubDivisionName`. Left
  as it is: the file is meant to fail.
