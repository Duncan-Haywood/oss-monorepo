Read-only Git branch hygiene

Know what can be cleaned up before you delete it.

Generate a Git branch cleanup report and recovery manifest for stale GitHub refs. Merged, active, shared, moved-tip, protected, and uncertain branches stay visibly different, so a tidy repository never comes at the cost of lost work.

python3 src/branch_hygiene.py --repo /path/to/checkout \
  --pr-json prs.json --report branch-report.txt \
  --manifest recovery-manifest.json --fail-on-risk

Common questions

Does exit status 0 mean every listed branch is cleared for deletion?

No. A zero exit status only means the snapshot contained no unresolved shared, moved-tip, or uncertain finding under --fail-on-risk. Every finding still carries a review_action such as review-delete-candidate, which is a routing label for a human review queue, not permission to delete a ref.

What does exit status 2 mean?

A human must review at least one finding classified shared, moved-tip, or uncertain before any cleanup proceeds. It never means a branch is confirmed clear for deletion — it flags exactly the cases the scanner cannot resolve on its own.

Why does a branch with no open pull request show as "uncertain" instead of safe?

In local mode there is no pull-request metadata by default, so a branch that is not merged and not explicitly marked protected is reported as uncertain rather than assumed abandoned. Pass --pr-json (exported once with the team's own gh CLI credentials) to resolve branches against their actual pull-request history instead of guessing from ref state alone.

Does this tool delete branches or run any Git write operation?

No. It only reads refs, commit ancestry, and the JSON files you pass it. It never fetches, pushes, or deletes, and the recovery manifest it writes explicitly marks itself read-only and approval-required.

Does repository data leave the machine it runs on?

No. The scanner makes no network requests and uploads nothing. The optional --usage-log records only an aggregate event name, a timestamp, and a finding count — never branch names, commit messages, repository names, or file contents.
