This checker vs. Lighthouse

Lighthouse is Google's open-source auditing tool for web pages, built into Chrome DevTools and also runnable from the command line, as an npm package, or through PageSpeed Insights. Point it at a URL and it drives a real Chrome (or Chromium) instance to score the page across several categories -- performance, accessibility, best practices, SEO, and, among its PWA-related audits, installable-manifest: the same manifest, name, display-mode, secure-origin, and icon checks this tool runs. Lighthouse's own documentation on web.dev describes that audit in detail.

That is a much broader tool doing a much broader job, and it needs a browser to do it: Lighthouse launches Chrome (via chrome-launcher or Puppeteer) to render the page before it can audit anything, which means a Chrome or Chromium binary has to exist on whatever machine runs it. This checker does one narrower thing without that dependency. It is a zero-dependency Node command that fetches your page's HTML, the <link rel="manifest"> it points at, the manifest JSON, and every icon the manifest lists, using plain HTTP requests -- no browser, no rendering, no screenshot. It classifies the result against the documented installability criteria and stops there. It has no performance timing, no accessibility rules, and no SEO score.

Which one answers your question

What you are trying to doWhere to do it
Get a full picture of a page -- performance, accessibility, best practices, SEO, and PWA checks together, rendered the way a visitor's browser sees it. Lighthouse -- this checker only ever answers the installability question.
Find out whether a page's manifest and icons clear Chrome's documented installability criteria, without installing or launching a browser. This checker -- one Node command, plain HTTP requests, a plain-English report.
Gate a deploy in CI on a manifest regression, on a runner image with no Chrome and no Puppeteer download budget. This checker -- zero dependencies beyond Node, and it never launches a browser.
Audit rendered performance, layout shift, or real accessibility violations that only show up once the page runs. Lighthouse -- this checker never renders the page, so it cannot see anything that depends on rendering.
See the install prompt fire in an actual browser session, or capture a full audit report with scores and a trace. Lighthouse (or Chrome DevTools' own Lighthouse panel) -- this checker only classifies a probe's JSON output, never a live page.

These compose rather than compete. A reasonable setup runs this checker on every commit that touches a manifest or an icon asset -- cheap, no browser, fails fast and names the exact field -- and keeps a full Lighthouse run for the broader audit that only a rendered page can answer. Neither one replaces the other.

Common questions

Should I use this checker or Lighthouse?

Reach for Lighthouse when you want the full picture: performance, accessibility, best practices, SEO, and PWA installability scored together against a page you name, using a real Chrome instance driving the page the way a visitor's browser would. Reach for this checker when you only want the installability question answered -- manifest present and parseable, a name, an installable display mode, a secure origin, a reachable icon -- without installing or launching Chrome at all, for example on a CI runner with no browser image or on a machine where Puppeteer's download is unwelcome.

Lighthouse is free too. What does this add?

Being free is not the difference -- Lighthouse is Google's open-source project under an Apache-2.0 licence, and running it costs nothing. What differs is the dependency and the scope. Lighthouse drives a real Chrome or Chromium instance (via chrome-launcher or Puppeteer) to produce its report, which is a real download and a real browser process to keep current. This checker is a zero-dependency Node script: it fetches your page's HTML, its manifest, and its icons with plain HTTP requests, classifies the result against the same documented installability criteria, and needs nothing beyond Node itself. It also does only that one job -- it has no performance, accessibility, or SEO score to produce or to keep out of your way.

Does this replace running Lighthouse?

No. Lighthouse's installable-manifest audit is one line item inside a much larger report, and that larger report is doing real work this checker does not attempt -- performance timing, accessibility rules, and the rest of Lighthouse's PWA and best-practices checks, all measured against a page rendered in an actual browser. This checker reads the same manifest and icon criteria Lighthouse's own documentation describes and reports on nothing else. Run Lighthouse for the full audit; run this when installability is the one question and a browser is the one thing you would rather not install.
