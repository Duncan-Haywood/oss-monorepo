Turn more free trials into paying customers

A trial with a card on file converts on its own, and the only job is an honest "you will be charged this much on this date". A trial without a card dies quietly unless the customer acts, so it needs a different plan. Pick your trial below to see the emails Trial Converter would send, then run the open-source server with your own Stripe key. No account with us, no per-conversion fee.

Run it yourself

    
git clone https://github.com/Duncan-Haywood/fp-monorepo && cd fp-monorepo/ventures/trial-converter
STRIPE_SECRET_KEY=rk_live_... STRIPE_WEBHOOK_SECRET=whsec_... \
ADMIN_KEY=$(openssl rand -hex 16) LINK_SECRET=$(openssl rand -hex 16) \
PUBLIC_URL=https://trials.example.com RESEND_API_KEY=re_... \
MAIL_FROM="Acme <hello@example.com>" COMPANY_NAME=Acme \
node server.mjs          # DRY_RUN=true until you set DRY_RUN=false

    
Point a Stripe webhook at /webhook/stripe for customer.subscription.created, customer.subscription.updated, customer.subscription.deleted, customer.subscription.paused, invoice.paid and payment_method.attached. One-click Render deploy and Docker are in the README.

  


  

    
Questions

    
Why not just use Stripe's own trial emails?

    
Stripe sends a trial_will_end webhook three days before the end and can send a reminder to customers with a card, but it does not ask card-less trials to add a card on a schedule, extend a trial once for someone who has not added one, or tell you your conversion rate with and without a card. Trial Converter does those three things and leaves the rest to Stripe.

    
Does it charge anyone?

    
No. It never creates a charge. Stripe converts the trial by itself; Trial Converter only emails the customer, links them to a fresh billing-portal session, and, only if you set EXTEND_DAYS, pushes a card-less trial's end date out once.

    
Is it safe to try?

    
It starts in dry-run mode: it records trials and logs every email and extension it would perform, but contacts neither Stripe nor your customers until you set DRY_RUN=false. Try it with a Stripe test-mode key first.

    
Where does my Stripe key live?

    
In the environment of the server you deploy in your own account. The author runs nothing in between and never sees your key or your customers.
