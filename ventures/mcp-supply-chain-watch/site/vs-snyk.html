This tool vs. Snyk's agent-scan

Two different shapes: agent-scan is a static security scanner that inspects an MCP server, agent, or skill's own code and configuration for known vulnerability classes, as part of a broader supply-chain scan. This page answers a narrower, different question — exactly what changed between two manifests you captured yourself, so a server that looked fine at approval can't quietly add instructions aimed at the calling model later.

What each tool is for

Snyk's agent-scan is an open-source security scanner for AI agents, MCP servers, and agent skills. It inspects a server or skill's own source and configuration to detect known vulnerability classes — prompt injection, tool poisoning, and toxic flows among them — as one check inside Snyk's broader supply-chain and developer-security tooling. It is built to be run against a server's code, typically before or during onboarding, to decide whether the server looks risky. Snyk's own current plan names and prices are not reachable from this session to confirm, so no dollar figure for it is invented here: only its well-documented identity and category — an open-source static security scanner for MCP servers and agent skills — are stated.

This tool does none of what agent-scan does. It never inspects a server's source code, never contacts a server, and never assigns a risk score. You capture a server's own declared tool manifest — each tool's name, description, and inputSchema — yourself, at whatever two points in time you choose, typically once at approval and again before trusting the server again. Paste or load both captures and the page lists exactly which tools were added or removed and which tool's description or inputSchema changed, with a separate alert-severity flag when a changed description newly reads like an instruction aimed at the calling model rather than a human reviewer — the shape of a tool-poisoning or rug-pull attempt that waits until after approval. It runs free in any browser, keeps no account, and uploads nothing you paste.

This page's own output is a drift record between two captures, not a vulnerability scan, a risk score, or a security certification.

This tool needs no account, no server access, and no code inspection: it is a static page, the comparison runs in your browser, and once it has loaded it keeps working with the connection off.

Common questions

Should I use this tool or Snyk's agent-scan?

They do different jobs. Snyk's agent-scan is an open-source static security scanner for AI agents, MCP servers, and agent skills: it inspects a server or skill's own source and configuration for known vulnerability classes such as prompt injection, tool poisoning, and toxic flows, as one check in a broader supply-chain security scan. It answers whether a server looks risky by examining what it is. This tool answers a narrower, different question: given two manifests you captured yourself at different times — typically once at approval and again later — exactly which tools were added or removed, and which tool's description or inputSchema changed, including a specific flag for a changed description that newly reads like an instruction aimed at the calling model rather than a human. It never contacts a server, never inspects source code, and never scores risk; it is evidence of drift between two captures, not a vulnerability scan of the server itself. A team that wants a static security scan of a server's code before first approving it is better served by agent-scan or a comparable scanner; a team that already approved a server and wants to know precisely what changed since is in the right place here.
