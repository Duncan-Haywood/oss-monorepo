How to find critical path drag in a P6 schedule

When a job is late and the owner asks what it would take to recover, total float is no help: every critical activity has the same float. Critical path drag answers the question directly. An activity's drag is how much earlier the project would finish if that activity took no time, everything else unchanged, so it is the most that accelerating it can ever win. Drag cost puts a price on it: drag in calendar days times what a day of finish costs you (liquidated damages, extended site overheads, or the value of opening earlier). Primavera P6 and Microsoft Project do not compute drag; the free tool here does, from the XER, in your browser.

Open the free schedule check (open the XER, then press Find critical path drag)

Steps

  1. Export the current update from P6 as XER (File, Export, Primavera PM XER), or use the file you were sent. A Microsoft Project XML file works too.
  2. Open it on the tool page. If the file holds several projects, pick one.
  3. Under Critical path drag, type what a calendar day of finish costs if you want drag cost, and press Find critical path drag.
  4. Read the table from the top: the activities with the most drag are where acceleration pays. Download the CSV for the full list, with lags.

The two board-and-tape activities are on the longest path but have no drag: they run side by side for the same length, so shortening either alone leaves the other holding the finish. That is the trap drag shows and float hides. The 80-hour lag between flooring and furniture has 6 days of drag of its own. Costs are per calendar day, so 10 working days of drag across two weekends is 14 calendar days, $35,000.

How it is worked out

For each activity with work left on the longest path (every chain of driving links into the activities that set the forecast finish), the tool sets its remaining duration to zero, reschedules the whole project with the same engine it uses for everything else (calendars, lags, SS/FF/SF links, constraints, progress and retained logic), and measures the change in the finish on the project calendar. It does the same for each lag between them. It then finds the least shortening that wins the whole drag, because on real calendars the gain can come in steps: in one public file an activity with 14.7 hours of drag wins only 8 hours when shortened by 14.7 hours, and all of it from 22.8 hours.

How it was tested

On 200 random networks (2,477 activities), the drag equals an independent longest-path calculation that shares no code with the scheduling engine, for every activity. On six public P6 files, shortening each activity by exactly its drag brings the finish in by exactly that much in 47 of 50 cases; the three others are explained (an expected finish date that overrides a shorter duration, an activity on a different calendar from the project, and a stepped gain). Details are in the project's eval/ notes.

Things to know

  • Drag is one activity at a time. Shortening two activities does not always win the sum of their drags: once one is shortened, a parallel path may take over.
  • An expected finish wins. If the project uses expected finish dates, a shorter duration does not count until the expected finish moves; the tool says so on that row.
  • Drag cost is not an acceleration quote. It is what that activity's hold on the finish costs you. Compare it with what the overtime or extra crew would cost.

Questions

What is critical path drag?

The amount of time one activity on the critical path adds to the project's duration: how much earlier the finish would be if that activity took no time. Stephen Devaux defined it in Total Project Control (1999). It is never more than the activity's remaining duration, and it is less when a parallel path with only a little float takes over once the activity is shortened.

Why not just shorten the activity with the longest duration?

Because duration is not what you win. Every critical activity has the same total float, and a 30-day activity running beside a path with 4 days of float can only ever bring the finish in by 4 days. Drag says what each one is really worth before you pay for overtime or a second crew.

Does Primavera P6 calculate drag?

No. P6 shows total float, free float and the longest path, and Microsoft Project shows slack; neither computes drag. You can find it by hand by setting one activity's remaining duration to zero, scheduling, noting the finish and undoing it, once per critical activity. This tool does exactly that for every activity on the longest path, on its own copy of the schedule.

What is reverse drag?

An activity that the critical path enters at its finish (a finish-to-finish link from its predecessor) and leaves at its start (a start-to-start link to its successor). Shortening it moves its start later, which pushes the successor, so the finish moves later. It is a sign the logic should be looked at, and the tool flags it.

Is the file uploaded?

No. The schedule is read and rescheduled in your browser tab. There is no server, account or upload.
