# Project custom fields to P6 user-defined fields, 2026-11-21

**Question.** A planner in Microsoft Project often keeps more than dates in
the schedule: a crew size, an allowance, a claimed-this-month amount, an
access date, in Project's Number, Cost and Date custom fields. When the owner
or general contractor asks for a P6 XER, does `p6xer.mjs` carry those fields
into P6, as P6's own activity user-defined fields (UDFs), so they show up as
named columns after the import? Until this change it did not: it counted
"custom number and date fields" as not carried and dropped them.

And the round trip: a P6 file sent through Project XML (`msproject.mjs`
writes its numeric, cost and date UDFs to Number, Cost and Date fields since
`eval/msproject-udfs-2026-11-21.md`) and back to XER lost all its UDFs on the
way back. Does it now return them?

P6 itself was not available (no seat). What stands in for it: P6's own field
lists for UDFTYPE and UDFVALUE (read from the public P6 6.0, 7.0 and 24.12
exports below), this tool's XER reader, and MPXJ 16.10, an independent
open-source reader of both formats.

## What changed

- `p6xer.mjs` writes UDFTYPE (with the global tables, before PROJECT, where
  P6 writes it) and UDFVALUE (last), from the Number, Cost and Date fields
  `mspdi.mjs` reads: titled by the field's Alias, else Project's field name
  (Number3); whole-number fields as integer UDFs, other numbers as decimal
  ones, Cost fields as cost UDFs (Project stores hundredths; P6 gets the
  amount), Date fields as start-date UDFs. Fields are the eight P6 6.0 to
  24.12 all write (24.12's extra `export_flag` is left out so older versions
  import it).
- P6 needs a UDF title unique within a subject area, so a second field with the
  same title (any case) gets " (2)"; titles are cut to 40 characters.
- `p6Problems` checks the UDF tables too: the type and activity every value
  points at exist, one value per activity per UDF, dates on date UDFs,
  numbers on number UDFs, whole numbers on integer UDFs, unique titles.
- The warnings say how many values were written; counts carry `udfFields`
  and `udfValues`.

## Data

- MPXJ's Microsoft Project XML test corpus (github.com/joniles/mpxj,
  `junit/data`, sparse clone 2026-11-21; read for measurement, not copied
  here): 143 MSPDI files. 19 use task custom fields: the `task-costs`,
  `task-dates` and `task-numbers` files saved by Project 2003, 2007, 2010,
  2013, 2016 and 2019 (every Cost1..10, Date1..10 and Number1..20 field set
  on a task), and `legacy/mspextattr.xml`.
- The six public P6 files of `eval/cpm-vs-p6-2026-11-19.md`; two carry
  activity UDFs: CCA (P6 6.0; 32 activity UDFs, 41,729 values, 13,174 of them
  numeric, cost or date) and Expressway (P6 7.0; 823 integer values).

Commands:

```
node eval/p6xer-check.mjs --mspdi <mpxj>/junit/data --xer <dir of the six XERs> --write <out> --json eval/p6xer-udfs-2026-11-21.json
python eval/p6xer-udfs-mpxj.py --json eval/p6xer-udfs-mpxj-2026-11-21.json <before> <after> ...
```

(the pairs: each of the 19 XML files with the XER written from it, and the
CCA and Expressway originals with their `-via-project.xer`.)

## Results

**Project to P6, this tool's reader** (`p6xer-check.mjs --mspdi`): 243 of 243
custom field values on the 19 files come back as UDF values on the right
activity with the right title and value, all 243 with the expected type, no
extra value. No file breaks P6's import rules (`p6Problems`, now including
the UDF checks). Everything checked before is unchanged: 2,520 of 2,520
activities intact, 65 of 65 links, 181 of 181 code assignments, schedule
equal on 2,509 of 2,509 open activities.

**P6 to Project to P6** (`--xer`): CCA 13,174 of 13,174 numeric, cost and
date UDF values return on the right activity ID, title and value; Expressway
823 of 823; no extra value. The other 28,555 CCA values are text UDFs:
`msproject.mjs` writes them to Project's Text fields, which come back as
activity codes, not UDFs (as they did before). All other round-trip counts
unchanged (21,739 of 21,739 IDs, 54,843 of 54,843 links, 276,042 of 276,042
codes, schedule 19,818 of 19,822).

**MPXJ, independent reader** (`p6xer-udfs-mpxj.py`): it reads every Number,
Cost and Date field from each Project XML and every UDF from the XER written
from it, and compares by activity ID and title: 14,240 of 14,240 values the
same (243 Project-side, 13,174 CCA, 823 Expressway), none extra.

**The type, on the round trip.** 7,104 of the 13,174 CCA values come back with
P6's own type. Project has one Number type, so the type is guessed on the way
back: a field of whole numbers becomes an integer UDF. Six of CCA's decimal
UDFs hold only whole numbers (`RENZ % COMPLETE`, `PERCENT COMPLETE`, `July2011
Target% Complete`, `U%`, `user_number7`, `user_number8`) and come back as
integer UDFs; the values are the same. The opposite default (always decimal)
would be wrong on as many fields: CCA and Expressway have six integer UDFs,
all whole numbers. And P6's finish-date subtype has no Project field, so
`FT_END_DATE` UDFs come back as start-date UDFs (CCA's two). Both are named
in `NEXT.md`.

## Limits

- Not imported into P6 itself: no P6 seat here. The field lists, order and
  value forms are those of the public P6 exports, and MPXJ (whose P6 reader
  is used by most converters) reads them.
- Text custom fields stay activity codes (as before), so a Project Text field
  used as free text lands in P6 as a code type of up to 60 characters per
  value, not a text UDF.
- Only task fields: Project's resource custom fields are not read.
