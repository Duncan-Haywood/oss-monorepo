# Resource user-defined fields through Microsoft Project XML and back, 2026-11-21

**What changed.** P6 lets a company hang its own fields on resources as well
as activities: a crew's capacity, employment type, day rate, the site a
contractor is cleared for, an induction date. `msproject.mjs` wrote activity
UDFs into the Project XML but dropped every resource UDF, and `p6xer.mjs`
read no resource custom field from a Project file. Now both directions carry
them:

| P6 resource UDF type | Project resource field | Back in P6 as |
|---|---|---|
| Text (FT_TEXT) | Text1..30 (all 30 free: resources have no activity ID or codes in Text fields) | text UDF |
| Integer, decimal | Number1..20 | integer UDF if every value is whole, else a 2-decimal UDF |
| Cost (FT_MONEY) | Cost1..10, in hundredths (as MPXJ writes a cost field) | cost UDF |
| Start date, finish date | Date1..10 | start-date UDF (Project has one date kind) |
| Indicator, code UDFs | none | counted in the warnings |

Each Project field is renamed (`Alias`) to the UDF's title, so a Project user
sees "Capacity" or "Day rate" as a resource sheet column. The resource field
ids (PjField) were read from MPXJ 16.10's `FieldTypeHelper` for
`ResourceField.TEXT1` to `DATE10`, not written from memory. P6 writes a
resource UDF value with an empty `proj_id` (resources are global; the public
24.12 file does), and `p6xer.mjs` does the same. `p6Problems` now checks each
UDF value's `fk_id` against its UDF's own subject area (TASK or RSRC) rather
than always TASK, so a title used on both an activity UDF and a resource UDF
is allowed, as in P6.

Only resources with an assignment in the project are written to the XML (as
before), so their UDFs are the ones carried.

## Method

`eval/rsrc-udfs.mjs` writes each XER as Project XML with `mspdiText`, turns
the XML back into an XER with `p6XerText`, and checks every resource UDF value
of a written resource: the XER that comes back must hold a resource UDF with
the same title and value on the same resource ID (numbers within 1e-9, costs
to the cent, dates to the minute, text exactly). It also runs `p6Problems` on
the XER that comes back. `eval/rsrc-udfs-mpxj.py` reads both the XML and the
XER that comes back with MPXJ 16.10.0, an independent open-source reader, and
`--mpxj` checks MPXJ's field aliases and every cell against what was meant.

Data: the six public XER files in `eval/cpm-vs-p6-2026-11-19.md`. Only one,
example_xer_file (P6 24.12, MIT), carries resource UDFs: three text UDFs
(Capacity, EmploymentType, ClientSite) on its 29 resources, 87 values. No
public file has a numeric, cost or date resource UDF, so `--plant` adds six
to that file's resources (day rate and a rate adjustment with negatives as
costs, induction and contract-end dates, an integer crew size and a decimal
productivity factor): 156 planted values, 243 with the three real ones.

```
node eval/rsrc-udfs.mjs --plant D/example_xer_file.xer D   # D/rsrc-udfs-planted.xer
node eval/rsrc-udfs.mjs D --xml-dir X                      # D holds the XER files
python eval/rsrc-udfs-mpxj.py X/<f>.xml X/<f>.back.xer X/<f>.rsrc.json   # each file with resource UDFs
node eval/rsrc-udfs.mjs D --mpxj X --json eval/rsrc-udfs-2026-11-21.json
```

## Results

| File | Values | Back the same | Types kept | MPXJ aliases | MPXJ cells (XML) | MPXJ cells (XER back) | p6Problems |
|---|---|---|---|---|---|---|---|
| example_xer_file | 87 text | 87 / 87 | 3 / 3 | 3 / 3 | 87 / 87 | 87 / 87 | 0 |
| planted | 87 text, 48 cost, 50 date, 58 number | 243 / 243 | 8 / 9 | 9 / 9 | 243 / 243 | 243 / 243 | 0 |
| **Total** | **330** | **330 / 330** | | **12 / 12** | **330 / 330** | **330 / 330** | 0 |

The five other public files have no resource UDFs, and their round trips
gain no UDF and no import problem. The one type change is the planted
finish-date UDF "Contract ends", which comes back as a start-date UDF: Project
has one kind of date field. Its 21 values keep their date and time.

Before this change the XML carried 0 of the 87 real resource UDF values.

## What this does not show

- Not opened in Microsoft Project or imported into P6 itself; MPXJ stands in
  for both readers.
- The only real resource UDFs seen are text. Numeric, cost and date ones are
  planted.
- A decimal resource UDF whose values are all whole numbers comes back as an
  integer UDF (as with activity UDFs, NEXT.md); none of the planted ones is.
- WBS UDFs are still not carried (Project's summary tasks would hold them).
