# Doubled quotes in XER values, 2026-11-21

**Question.** P6 writes a double quote inside a value as `""` (an unquoted
field: `Prestressing Cables -  0.6""`). `parseXer` kept both characters, so a
name showed `""Controlled Zone""` on the page, in the written review, in every
CSV and in the Gantt chart, while MPXJ (the open-source reader most
converters use) reads one quote. `msproject.mjs` undid it for the names it
wrote (`nm`), but nothing else did. Is P6's rule "every inner quote doubled",
and does reading `""` as `"` in every value match MPXJ without breaking
anything?

**Data.** The six public XER files of eval/cpm-vs-p6-2026-11-19.md (four
GitHub repositories, cloned for the check, not committed), plus the two small
test fixtures in those repositories.

**Survey** (every `%R` value holding a `"`):

| File | P6 | `""` inside an unquoted value | lone `"` | quoted multi-line |
|---|---|---|---|---|
| CCA_R03_dt_24Oct11SC | 6.0 | 12 (10 task names, an OBS description, resource notes) | 0 | 0 |
| Expressway_Project | 7.0 | 2 (a resource name `0.6""`, a WBS memo) | 0 | 0 |
| sample | 20.12 | 1 (OBS description HTML) | 0 | 0 |
| example_xer_file | 24.12 (Web) | 0 | 0 | 1 (clndr_data) |
| hotel, terminal, 2 fixtures | 5.0, 6.0 | 0 | 0 | 0 |

So P6 6.0, 7.0 and 20.12 double every inner quote, and no real export holds a
lone one. Lone quotes (`6" drain`) come from hand-made and converter files,
and are kept as written.

**Change.** `xer.mjs`: `splitRow` turns `""` into `"` in every value (a quoted
multi-line value also loses its wrapping quotes, as before); `xerText` writes
every `"` as `""` and still wraps a value holding a line break. `msproject.mjs`
`nm` no longer unescapes (it would halve a real `""`). `p6xer.mjs` goes through
`xerText`, so a Project name with a quote now reaches P6 doubled, as P6 writes it.

**Method.** `python eval/quotes-mpxj.py <dir>/*.xer > mpxj.jsonl` (MPXJ 16.10.0
via `pip install mpxj jpype1`, Java runtime), then
`node eval/quotes-check.mjs <dir> mpxj.jsonl --old <copy of the old xer.mjs>`.
Task names are matched by activity ID, resource names by resource ID, WBS
names by short name.

**Result.**

| File | Names compared with MPXJ | Agree after | Agree before | `%R` lines written back byte for byte |
|---|---|---|---|---|
| CCA (6.0) | 16,265 | 16,265 | 16,255 | 403,177 / 403,177 |
| Expressway (7.0) | 1,159 | 1,159 | 1,158 | 8,551 / 8,551 |
| example (24.12) | 464 | 464 | 464 | 3,343 / 3,344 |
| hotel (6.0) | 4,247 | 4,247 | 4,247 | 33,273 / 33,273 |
| sample (20.12) | 52 | 52 | 52 | 142 / 142 |
| terminal (5.0) | 73 | 73 | 73 | 348 / 348 |
| **Total** | **22,260** | **22,260** | 22,249 | 448,834 / 448,835 |

- All 15 changed values are the 15 doubled-quote values in the survey; no
  other value of 5.47 million changed, and no table gained or lost a row.
- The one line not written back byte for byte is the 24.12 file's multi-line
  calendar: its `%R` row spans several source lines, so the first-line
  comparison cannot match it; its value reads back exactly.
- `xerText(parseXer(f))` read again equals `parseXer(f)` on every value of
  all eight files.
- CPM against P6 is unchanged: 19,820 / 19,822 (eval/cpm-vs-p6.mjs).
- Project XML to XER (CCA and Expressway through `mspdiText`, then
  `p6XerText`): the 10 quoted task names and the quoted resource name come back
  with one quote through `parseXer`, and MPXJ reads all 11 the same way from
  the written XER.

**Left.** P6 Web (24.12) wraps multi-line values in quotes; whether it also
doubles a quote in a single-line value is unseen (the public 24.12 file has
none). A P6 Web export with a quoted name would settle it.
