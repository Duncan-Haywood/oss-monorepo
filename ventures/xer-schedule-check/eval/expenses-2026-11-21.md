# Expenses between P6 and Microsoft Project, 2026-11-21

**Question.** Cost-loaded schedules carry money that is not labour: concrete
supply, crane hire, permits, a subcontract lump sum. P6 keeps it as
**expenses** (table PROJCOST: an item on an activity with budgeted, actual
and remaining cost, a cost category, an accrual, a vendor, a PO number, a
quantity and a description). Microsoft Project keeps it as **cost resources**
(a resource of type Cost whose assignments carry only money) and as a task's
**fixed cost**. Until today both converters dropped it: XER to Project XML
counted expenses as "not carried", Project XML to XER counted cost resources
the same way. So a cost-loaded schedule lost every non-labour dollar in
either direction, and earned value on the far side came out wrong. Can both
directions carry them, and does the money come back to the cent?

## What changed

- **P6 to Project** (`msproject.mjs`): each expense name becomes a cost
  resource (Type 2), with the cost category (COSTTYPE) as its Group and its
  accrual as the resource's AccrueAt (CL_Start 1, CL_End 2, CL_Uniform 3,
  prorated). Each expense is an assignment of it: cost = actual + remaining
  (the budget when the file stores neither, as for resource assignments),
  actual cost, remaining cost, the budget as baseline cost, and the vendor,
  PO number, quantity and description as lines in the assignment's notes.
  - Project keeps category and accrual on the **resource**, not the
    assignment. A first version used one cost resource per name and lost them:
    on the planted files below, 63 to 79 of about 390 expenses per file came
    back in the wrong category and about 150 with the wrong accrual. Now a
    name used with a second category or accrual gets a resource of its own,
    named with them ("Rebar (Subcontract, at end)"), and its assignments carry
    the expense name in an `Expense:` line, so the name comes back too.
  - Project allows one assignment of a resource per task, so two expenses
    with the same name, category and accrual on one activity are added
    together. The warning counts them.
- **Project to P6** (`p6xer.mjs`): every assignment of a cost resource on a
  leaf task becomes an expense named after the resource (or the `Expense:`
  line), in a cost category named by the resource's Group (COSTTYPE, written
  with the global tables as P6 does), accrued as the resource accrues.
  Budgeted cost is the assignment's baseline cost when it has one, since P6's
  budget is the plan, and its cost otherwise. Actual and remaining are taken
  as stored. Budgeted units and price come from a `Quantity:` line, and
  without one it is 1 unit at the whole cost, so P6's units × price equals
  the budget. A task's **fixed cost** becomes an expense named "Fixed cost",
  with its actual set by Project's accrual: start = all of it once the task
  has started, end = all of it once finished, prorated = the % complete share.
  Cost resource assignments on summary tasks are counted and not carried,
  because a WBS node holds no expenses.
- PROJCOST's 19 fields are the list P6 20.12 and 23.12 write. Two public
  files on GitHub carry it identically (sudo8phoenix/Time_Agent's 20.12
  fixtures and hamzaabduljabbar/autoConst-boq-schedule's 23.12 file).
  `p6Problems` now checks that every expense names an activity and the
  project, and that a category, if given, is in COSTTYPE.

## Data

- **One public XER with expenses:** `examples/januaria/schedule.xer` in
  hamzaabduljabbar/autoConst-boq-schedule @ 7b9a471 (41 expenses with
  quantities, units and descriptions, BRL). A generator wrote it, not P6.
  It is not committed.
- **Six public P6 files** (`eval/cpm-vs-p6-2026-11-19.md`; none has an
  expense row) with expenses **planted** from a seed by
  `eval/expenses-check.mjs --plant 300`: on up to 300 activities, one or two
  expenses each, with a category (15% none), accrual, costs that fit the
  activity's status, and on some a vendor (including a comma and doubled
  quotes), PO number, quantity and description. About 3% repeat a name
  already on the activity.
- **102 Microsoft Project XML files** from MPXJ's test corpus (Project
  2002-2019; none has a cost resource or a non-zero fixed cost), with a cost
  resource assigned to one leaf task in four (cost, actual, and a baseline
  cost on half of them) and a fixed cost on one leaf task in ten, planted by
  `eval/expenses-check.mjs --mspdi`.

`eval/expenses-check-2026-11-21.json`). Expenses are matched by activity ID
and name, and same-named ones on one activity are compared as their sum:

Totals agree to the cent on every file (for example CCA: budget 9,080,312.10,
actual 1,583,791.16, remaining 7,651,666.53 before and after). No written
XER breaks `p6Problems`. None of the planted repeats had the same name,
category and accrual on one activity, so all 1,557 came back as separate
expenses. The merge case is covered by `msproject.test.mjs`.

**MPXJ, an independent reader** (`python eval/expenses-mpxj.py <out>`,
`eval/expenses-mpxj-2026-11-21.json`, MPXJ via `pip install mpxj jpype1`):
it read the expense items of the source XER and of the XER read back
(every project in a multi-project file, through PrimaveraXERFileReader.readAll)
and found the same 1,526 groups with the same planned, actual and remaining
cost. On the 1,495 single ones, category, accrual, vendor, document number,
units, unit of measure and description also match. In the Project XML it
read the cost resource assignments, and their cost, actual, remaining and
baseline cost equal the source expenses' at-completion, actual, remaining and
budget on 1,213 of 1,213 activities.

**Project to P6** (`node eval/expenses-check.mjs --mspdi <mpxj>/junit/data`,
`eval/expenses-mspdi-2026-11-21.json`): 102 files, 615 planted cost resource
assignments became 615 expenses and 246 fixed costs became 246 "Fixed cost"
expenses. On 102 of 102 files the budget (baseline cost where planted, else
cost), actual and remaining totals are equal, every fixed cost's actual plus
remaining equals it, every expense has the resource's accrual and category,
and no file breaks `p6Problems`.

## Limits

- **Not imported into P6 or opened in Project.** The checks are this tool's
  own readers, MPXJ, and P6's field lists. Still open: whether P6's import
  matches a cost category by name or adds a second one, and whether it keeps
  `cost_per_qty` or recomputes it from the budget.
- **The only real PROJCOST rows came from a generator.** A P6-written file
  with expenses (a vendor, a PO, actuals booked) is the next input.
- **Fixed cost actuals use the accrual rule above.** Project 2002-2019 files
  in MPXJ's corpus carry no non-zero fixed cost to check it against.
- The expense's account (`acct_id`), OBS (`pobs_id`) and "auto compute
  actuals" flag are not carried. Project has no field for the first two, and
  the flag is written as N.
