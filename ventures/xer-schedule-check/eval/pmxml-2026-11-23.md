# P6 XML (PMXML) reader and P6 XML to XER, checked 2026-11-23

`pmxml.mjs` reads Primavera P6's XML format (root `<APIBusinessObjects>`: P6
Professional's File, Export, Primavera PM (XML); P6 EPPM; Oracle Primavera
Cloud) into the tables `parseXer` gives, so every check, report and converter
in this tool runs on it, and `pmxmlToXer` writes it back as an XER.

## 1. Same schedule, written two ways (eval/pmxml-check.mjs)

No public pair of an XER and a P6 XML of the same project exists that we could
find, so the P6 XML side was written by MPXJ 15 (pip `mpxj`, the independent
open-source reader and writer most converters use) from the six public XERs
(`bash eval/corpus-fetch.sh DIR`, then `python eval/xer-to-pmxml.py OUT DIR/xer/*.xer`;
the hotel file holds four projects and gives four XML files).

| File | Activities | Links | Schedule equal | P6's dates (XER / XML) | XML -> XER round trip |
|---|---|---|---|---|---|
| CCA_R03_dt_24Oct11SC | 16,146 | 47,286 | 15,849 / 15,849 | 14,268 / 14,268 of 14,270 | 15,849 / 15,849 |
| Expressway_Project | 823 | 1,094 | 823 / 823 | 823 / 823 of 823 | 823 / 823 |
| example_xer_file | 435 | 555 | 425 / 425 | 404 / 404 of 404 | 425 / 425 |
| hotel-project (4 projects) | 4,236 | 7,586 | 4,236 / 4,236 | 4,217 / 4,215 of 4,217 | 4,236 / 4,236 |
| sample | 52 | 61 | 42 / 42 | 42 / 42 of 42 | 42 / 42 |
| terminal-building-airport | 66 | 84 | 66 / 66 | 66 / 66 of 66 | 66 / 66 |
| **Total** | **21,758** | **56,666** | **21,441 / 21,441** | **19,820 / 19,818 of 19,822** | **21,441 / 21,441** |

- Every activity matched by object id; every calendar the same work week and
  holidays as the engine reads them (21,758 / 21,758); every WBS path the same
  (21,758 / 21,758); every relationship found with its lag (56,666 / 56,666).
- Fields: 260,603 of 261,096 equal (type, status, ID, planned and remaining
  duration, actual dates, both constraints, expected finish). The 493 that
  differ are all durations MPXJ rounded to 2 decimals when writing
  (975.983333 h written 975.98); the schedule is equal anyway.
- "Schedule equal": early start, early finish, late finish and total float from
  this tool's engine on the XML equal those on the XER, every activity.
- P6's dates: the 2 XML misses on the hotel file are MPXJ writing P6's
  Remaining Early dates (XER `restart_date`, `reend_date`), which differ from
  the early dates on 21 of the hotel's activities; P6 XML stores only the
  Remaining Early dates for an activity, so those two are measured against a
  different stored date, not computed differently.
- Round trip: the XML written back as an XER by `pmxmlToXer`, read by
  `parseXer`, gives the original XER's schedule on 21,441 / 21,441.
- **MPXJ reads the round-tripped XERs as it reads the originals**
  (`eval/pmxml-xer-mpxj.py`): name, milestone, start, finish, remaining
  duration, actual start and finish, constraint and date, calendar and every
  predecessor with type and lag, 239,338 / 239,338 fields on 21,758 activities.
  Its first run found a real fault: P6 XML writes an activity code colour as
  `#0000FF`, XER as `0000FF`, and MPXJ refused the file; the reader now drops
  the `#`.

Generator faults found and worked around, not reader faults:

- example_xer_file keeps its calendar as P6 Web writes it, a quoted value over
  several lines. MPXJ 15 does not read that and wrote a default 08:00-16:00
  week into the XML (checked with MPXJ's own reading of the XER: Monday
  08:00-16:00 where the XER says 08:00-12:00 and 13:00-17:00). That file's XML
  was written from a copy with the same calendar on one line; with MPXJ's
  default week, 1 of 425 activities agreed.
- MPXJ writes the XER's project node as a top-level WBS (code = project ID), so
  the WBS paths are compared after dropping a leading code equal to the
  project's ID.
- MPXJ drops 13 duplicate links of CCA's when writing (47,273 rows written);
  the comparison matches links by predecessor, successor and type, so a
  duplicate collapses on both sides.

## 2. Files P6 itself wrote (eval/pmxml-p6-dates.mjs)

Public P6 XML files on GitHub with stored scheduled dates:

| File | Written by | Open activities P6 scheduled | ES, EF and LF equal P6's |
|---|---|---|---|
| myoualid/ifc-101-course EC00850_V2.xml (33 activities, 6 calendars, 24 assignments) | P6 | 32 | 32 |
| aspose-tasks BaselineProjects.xml | Aspose.Tasks | 1 | 1 |
| aspose-tasks MultiprojectWithExternal.xml (2 projects, an external link) | Aspose.Tasks | 2 | 2 |
| aspose-tasks-cloud p6_multiproject.xml | Aspose.Tasks, from a Project file | 5 | 0 |

The Aspose multiproject file contradicts itself: its calendar's work times are
08:00-11:00 and 13:00-16:00 (6 h, though HoursPerDay says 8) while its stored
dates run 08:00 to 17:00, so no reading of the calendar gives both. Not tuned
for. Eight more public P6 XML files read without error but carry no stored late
dates to compare (P6 never scheduled them, or another tool wrote them).
