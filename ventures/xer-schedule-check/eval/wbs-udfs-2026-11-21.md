# WBS user-defined fields through Microsoft Project XML and back, 2026-11-21

**What changed.** P6 lets a company hang its own fields on WBS nodes as well
as on activities and resources: a cost code, a budget, a floor area, a work
package number, a handover date. `msproject.mjs` wrote activity and resource
UDFs into the Project XML but dropped every WBS UDF, and neither
`mspdi.mjs` nor `p6xer.mjs` read a custom field off a summary task. Now both
directions carry them.

A WBS node becomes a summary task in Project, and Project's custom fields
belong to all tasks, summary or not. So a WBS UDF goes into the same task
fields the activity UDFs use:

| P6 WBS UDF type | Project task field on the summary task | Back in P6 as |
|---|---|---|
| Text | a Text field activity codes and activity text UDFs left free (Text2..30) | text WBS UDF |
| Integer, decimal | Number1..20 | integer WBS UDF if every value is whole, else 2-decimal |
| Cost | Cost1..10, in hundredths | cost WBS UDF |
| Start date, finish date | Date1..10 | start-date WBS UDF (Project has one date kind) |
| Indicator, code UDFs | none | counted in the warnings |

**A shared column.** When a WBS UDF has the same title and kind as an activity
UDF that was written (P6 keeps the two in separate subject areas, so a company
can have "Package" on both), the WBS UDF writes into that activity UDF's field
and takes no new one. A Project user sees one "Package" column on summary
tasks and tasks alike. On the way back, `mspdi.mjs` reads the values on
summary tasks as WBS UDFs and the values on tasks as activity UDFs, so the one
field splits back into two P6 UDFs with the same title.

Values on the project node have no summary task (the project's own row is
task 0, which `mspdi.mjs` skips) and are counted in the warnings, as are WBS
UDFs that find no free field.

`mspdi.mjs` also reads the Text fields of summary tasks (except the field
named Activity ID, which holds the WBS code). That applies to any Project
file, not only ones this tool wrote: a planner's text on a summary row now
reaches P6 as a WBS UDF.

## Method

`eval/wbs-udfs.mjs` writes each XER as Project XML with `mspdiText`, turns
the XML back into an XER with `p6XerText`, and checks every WBS UDF value on
a WBS node the XML writes. The XER that comes back must hold a WBS UDF with
the same title and value on the same node (matched by its path of WBS codes):
numbers within 1e-9, costs to the cent, dates to the minute, text exactly.
It also counts the activity UDF values that come back (a shared field must
not move a value between activities and WBS nodes) and runs `p6Problems` on
the XER that comes back. `eval/wbs-udfs-mpxj.py` reads the XML and that XER
with MPXJ 16.10, an independent open-source reader, and `--mpxj` checks
MPXJ's field aliases and every cell against what was meant.

Data: the six public XER files in `eval/cpm-vs-p6-2026-11-19.md`. **None of
them carries a WBS UDF** (CCA has 32 activity UDFs and one project UDF,
Expressway 4 activity UDFs, the 24.12 file 3 resource UDFs). So `--plant`
adds eight WBS UDFs to three of them: text, cost (some negative), decimal,
integer, start date and finish date, plus one titled like the file's first
integer activity UDF and one like its first text activity UDF, and one value
on the project node.

```
node eval/wbs-udfs.mjs --plant D/Expressway_Project.xer P     # and CCA_R03_dt_24Oct11SC, example_xer_file
node eval/wbs-udfs.mjs P D --xml-dir X
python eval/wbs-udfs-mpxj.py X/<f>.xml X/<f>.back.xer X/<f>.wbs.json   # each planted file
node eval/wbs-udfs.mjs P D --mpxj X --json eval/wbs-udfs-2026-11-21.json
```

MPXJ read 20 of 20 WBS field aliases under the names meant. Each file's one
project-node value is named in the warnings as not carried.

- **CCA is full.** Its 37 activity code types and 15 text UDFs already need
  more than Project's 29 spare Text fields, so both planted text WBS UDFs
  (Cost code, 985 values; user_text2, 493) find no room and are named in the
  warnings: "2 text WBS user-defined fields are used and Project has 0 Text
  fields activity codes and UDFs leave free". The Number, Cost and Date WBS
  UDFs fit in the fields the activity UDFs left (CCA uses 15 of 20 Number
  fields). The planted user_text2 could not share a field either: its
  activity namesake was one of the 10 text UDFs left out for room.
- **One type change**, as with resource UDFs: the planted finish-date UDF
  "Warranty ends" comes back as a start-date UDF. Its values keep their date
  and time.
- **Unplanted files are unchanged.** On the six public files the XML and the
  XER that comes back are byte for byte what the code before this change
  wrote (the export-date header aside).
- **Childless summary tasks.** MPXJ (like Project) makes a summary task with
  no children a plain task. 91 of CCA's 985 WBS nodes hold no activity, so in
  Project their WBS UDF values sit on plain tasks. They are still in the field
  the alias names, and `mspdi.mjs` reads them back as WBS UDFs because the XML
  marks them Summary. An empty WBS node shown as a task is how Project already
  showed these nodes before this change.

Before this change the XML carried 0 of the 6,383 values.

## What this does not show

- Not opened in Microsoft Project or imported into P6 itself; MPXJ stands in
  for both.
- Every WBS UDF here is planted. No public XER found has one; a real file
  with WBS UDFs is the next input worth having.
- Project's summary rows can show rolled-up values for a custom field set to
  roll up. A Project file saved that way could carry those rollups in the XML,
  which `mspdi.mjs` would read as WBS UDF values. No file at hand does.
- As with activity UDFs, a decimal WBS UDF whose values are all whole numbers
  comes back as an integer UDF.
