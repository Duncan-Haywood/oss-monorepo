Who can become root through your sudoers file?

A sudoers rule that allows one editor, one pager or one find allows a root shell. ALL, !/usr/bin/su stops nobody. A NOPASSWD line above %sudo never takes effect, and a drop-in named deploy.conf is never read. visudo accepts all of these without a word. Paste /etc/sudoers and the files in /etc/sudoers.d below: this page lists each risky rule with its file, line and fix, and who can get root and how.

Nothing is uploaded. What you paste is read in this browser and never leaves your device, and the tool makes no network calls of its own. It reads the files, not a running system: it is not visudo -c and not a security audit.

1. Paste your sudoers files

Name each block like its path. A block named sudoers is read first, and its @includedir /etc/sudoers.d pulls in every block named sudoers.d/something in sorted order, skipping names with a dot, the way sudo does. On the server, sudo cat /etc/sudoers /etc/sudoers.d/* shows them.

Who can become root

Every rule that grants ALL as root, or a command this tool rates a root shell. Group members are not expanded: check them with getent group sudo.

      What it checks

      • High: NOPASSWD: ALL; ALL for every user; ALL minus a command; editors (vim, nano), pagers (less, man, journalctl) and interactive clients with a shell escape; shells, interpreters and tools like find, tar, systemctl, docker with open arguments; file writers like tee, cp, chown with open arguments; programs or scripts under /home, /tmp, /var/www; a directory or pattern as the command; SETENV; !env_reset; env_keep of LD_PRELOAD, PYTHONPATH, BASH_ENV and similar; !authenticate; Defaults setenv.
      • Medium: file readers like cat with open arguments; other wildcard arguments; env_keep of PATH without secure_path; timestamp_timeout below zero. A rule whose target user is not root drops one level.
      • Low: a NOPASSWD rule a later rule overrides; a sudoers.d file sudo skips; no secure_path; shared or long credential caching; !use_pty; visiblepw; pwfeedback.

      Common questions

      Why does my NOPASSWD rule in sudoers not work?

      sudo uses the last rule that matches, not the most specific one. If your NOPASSWD line sits above %sudo ALL=(ALL:ALL) ALL (or %wheel) and you are in that group, the group rule matches later and asks for a password. Put the NOPASSWD rule after the group rule, which a file in /etc/sudoers.d does, because the @includedir line comes at the end of /etc/sudoers.

      Why is my file in /etc/sudoers.d ignored?

      sudo skips every file in an @includedir directory whose name contains a dot or ends in a tilde, so /etc/sudoers.d/deploy.conf is never read and none of its rules apply. Rename it to deploy or 90-deploy and check it with visudo -cf.

      Is ALL, !/bin/su a safe way to stop a user becoming root?

      No. The sudoers manual says subtracting commands from ALL is generally not effective: the user can copy su to another name, or start a shell from an editor or script. List the commands the user needs instead.

      Why is allowing vim, less or find through sudo dangerous?

      Those programs can start a shell or write any file. vim runs :!sh and can save over /etc/sudoers, less and man run !sh, and find runs any command with -exec, all as root. Use sudoedit for editing, a group such as adm or systemd-journal for reading logs, and pinned arguments or a root-owned wrapper script for the rest.

      Does a clean result mean my sudo setup is secure?

      No. It reads only the patterns listed on this page. It does not know your group memberships, the contents or permissions of the programs a rule allows, your sudo version, or LDAP and SSSD rules. Have a qualified person review anything that protects valuable data.
