What it checks, and the rule behind each

  • Inconsistent formula (high when it does the same operation with a different reference): the cells either side share one formula in R1C1 form and this one does not, or it ends a run of copies doing the same operation on different cells. Excel's own rule "Formulas inconsistent with other formulas in the region", applied to every cell at once.
  • Number typed over a formula (high): a typed number whose neighbours share a formula.
  • Range stops next to a number (medium): SUM, AVERAGE, COUNT, MIN, MAX, PRODUCT, SUBTOTAL or MEDIAN over a single row or column with a number just beyond either end. Excel's rule "Formulas that omit cells in a region". Subtotals, year headers (1900 to 2100) above a range and moving windows copied down are not flagged.
  • Circular reference (high): loops in the dependency graph of every formula, across sheets, three-dimensional references and named ranges (Tarjan's strongly connected components).
  • Where an error starts (high): error cells whose own inputs are not errors, so 300 #DIV/0! cells show as the one that causes them. Errors pasted as values are listed apart.
  • #REF! in a formula or a named range, and references to a sheet that does not exist (high).
  • Formulas pointing at empty cells (medium): Excel's rule "Formulas referring to empty cells", single-cell references only.
  • Numbers stored as text (medium when a formula reads them) and formulas stored as text (medium).
  • Constants typed into formulas (info, grouped by value) and formulas with numbers only (medium), per the FAST Standard and the ICAEW Financial Modelling Code: an assumption belongs in its own labelled input cell. Settings of a function, like the 2 in ROUND(x, 2) or the column number in VLOOKUP, are not counted.
  • Also listed: OFFSET, INDIRECT and other volatile functions, links to other workbooks, hidden and very hidden sheets, numbers in hidden rows and columns, named ranges no formula uses, formulas over 250 characters or nested more than 6 deep, iterative calculation on, manual calculation, VBA present.
  • Not checked: whether the logic, assumptions or inputs are right; what OFFSET and INDIRECT point at; VBA, Power Query, pivot tables, charts, conditional formatting and data validation; values Excel would calculate now (the audit reads the values saved in the file). Old .xls and .ods files are not read.

How it was checked: on four public test workbooks it reads 15,072 of 15,072 formulas the same as openpyxl, an independent Python reader. The 5 cells where they differ are text cells that start with "=", which openpyxl takes for formulas. The method and results are in the eval folder.

Common questions

How do I find inconsistent formulas in Excel?

Excel marks some with a green triangle, one cell at a time. This tool reads every formula in R1C1 form, the form in which a formula and its copies are identical, and lists each cell whose formula differs from the matching formulas either side of it, with the formula those neighbours imply for that cell.

What is a hard-coded number overwriting a formula?

A cell in a row or column of copied formulas where someone typed a value instead, often to force a total. It looks right on the day and stops updating when the inputs change. The tool lists every typed number whose neighbours share a formula, with the formula it would hold if copied along.

How do I find where a #REF! or #DIV/0! error starts?

An error spreads to every cell that reads it, so a sheet can show hundreds. The tool follows each error cell's references and lists only the cells where the error starts: those whose own inputs are not errors.

Can it find circular references across sheets?

Yes. It builds the dependency graph of every formula, including references through named ranges and other sheets, and lists each loop with the cells in it. It also says when iterative calculation is switched on, which hides Excel's own circular-reference warning.

Is my spreadsheet uploaded?

No. The .xlsx file is unzipped and read in your browser tab; a test in the code checks that the page makes no network calls. Financial models are confidential, so that matters.

Does a clean result mean my model is right?

No. It finds mechanical faults: formulas that break a pattern, values typed over formulas, ranges that stop short, loops and errors. It cannot know whether your logic, assumptions or inputs are right. A model review still needs a person who understands the business.
