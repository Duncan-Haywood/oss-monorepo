How to find inconsistent formulas in an Excel model

You have been sent a model: twelve months across, thirty rows down, three tabs. Somebody wants a sign-off by Friday. Raymond Panko's reviews of spreadsheet error research sort the errors found into mechanical slips (typing and pointing), logic errors and omissions. The mechanical ones are the kind a program can find: a reference dragged one cell too far, a number typed over a formula to make a total agree, a SUM that stops a row short after a row was inserted. Each looks exactly like its correct neighbours until you click on it.

Why R1C1 makes this findable

In the usual A1 view, =C4*C5 in column C and =D4*D5 in column D look like different formulas. In R1C1 form, which Excel can show under File → Options → Formulas, both are =R[-2]C*R[-1]C: "two rows up times one row up, same column". A copied formula has the same R1C1 text in every cell it was copied to. So the job is to find the cell whose R1C1 text differs from the cells around it. Excel's own green triangle ("inconsistent formula") uses the same idea, one cell at a time, and only for the rule set its error checking has switched on.

A worked example

The tool's example workbook is a made-up 12-month plan: customers growing 4% a month at 49 per customer, a variable cost per customer, fixed costs, interest on the cash balance and a cash line. Seven faults are planted in it. The audit returns these (you can run it yourself and download the same file):

Seven planted faults, ten findings at high or medium: M7 shows twice (a pattern break and an empty reference) and so does E9 (a pattern break and the loop). It also counts 108 formulas of which 17 are distinct. Those 17 are what a reviewer actually has to read; the other 91 are copies, and the audit checks that each copy really is one.

What Excel's own tools do

  • Error checking (Formulas → Error Checking) walks the green triangles one at a time. It covers inconsistent formulas, formulas that omit adjacent cells, numbers stored as text and references to empty cells, each a setting that can be switched off.
  • Trace Precedents / Dependents draws arrows for one cell. Good for a question about one number, slow for a whole model.
  • Go To Special → Constants selects every typed value, which is a quick way to see plugs by eye in a small sheet.
  • Inquire (in some Microsoft 365 editions) compares two workbooks and reports on one.

None of them traces an error to the cell where it starts, lists typed-over formulas in one pass, or shows the formula a broken cell should have. Those are what this tool adds. Paid add-ins for professional model reviewers go further: version comparison, sign-off workflows, team licences. When a model carries a lending or investment decision, use one of them, or a person who reviews models for a living. This free tool does the first pass.

What to do with the findings

  1. Start with high: inconsistent copies, typed-over formulas, loops, error sources, #REF!. Each one either is a bug or needs a one-line note saying why it differs.
  2. Then medium: short ranges, empty references, text numbers. Most are real; some are layout (a label row with a number in it).
  3. Then skim info: typed constants and volatile functions. Moving a constant into a labelled input cell is cheap and makes the next review faster.
  4. Save and audit again. The command-line version (node cli.mjs model.xlsx --csv findings.csv) exits non-zero when a high finding remains, so it can run over a shared folder before a model is sent out.
