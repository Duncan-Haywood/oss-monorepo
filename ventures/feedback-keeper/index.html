Visitors vote and post without an account. You moderate, change statuses and publish changelog entries through the admin API (Authorization: Bearer $ADMIN_KEY). Moving an idea to planned, in progress or shipped emails the people who followed it once you set DRY_RUN=false and a Resend key. One-click Render deploy and Docker are in the README.

Questions

Why not just use Canny, Frill, Featurebase or Fider?

Hosted boards are polished and quick to start, but they price by tracked users or seats and keep your customers' requests on their platform. Fider is open source too but is licensed AGPL and needs Postgres. Feedback Keeper is MIT, one Node process with a JSON state file, runs in your own account, and adds duplicate detection and trending sort out of the box. If a hosted board already works for you, keep it.

How does duplicate detection work?

Every idea is turned into a TF-IDF vector over its title and details, and a new idea is compared with the board by cosine similarity. As someone types a title, the board suggests close matches so they vote instead of posting a copy, and you can merge existing duplicates, which keeps each vote once and carries over subscribers and comments. It is word-based, not semantic, so it catches reworded duplicates that share vocabulary and will miss ones that do not.

Do voters need an account?

No. A first-party cookie holds a random id so each browser counts once per idea. That stops accidental double votes, not a determined person clearing cookies, so new ideas are moderated by default and the form has a honeypot and a rate limit.

Does it send email?

Only if you set it up. It starts in dry-run mode and logs who would be emailed. With a Resend key and DRY_RUN=false it emails the people who voted with an email or followed an idea when you move it to planned, in progress, shipped or declined, with a one-click unsubscribe link.

Where is the data?

In one JSON file on your own disk. Back it up with cp. There is no telemetry, and the author never sees your board.
