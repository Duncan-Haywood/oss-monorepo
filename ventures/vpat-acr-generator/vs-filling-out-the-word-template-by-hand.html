VPAT / ACR Generator vs. filling out the Word template by hand

ITI's own VPAT 2.5 Word template names no company and belongs to nobody's product — it is the generic starting point most vendors already work from. This page names no competitor and no consultancy; it compares this generator against typing the same 50 rows into that same template directly.

What filling out the template by hand gets right

The table shape. ITI's template already has the right column headings, the right 50 WCAG 2.1 Level A/AA rows in the right order, and the right four conformance values to choose between. A vendor who works through it carefully produces a document that looks exactly like the one this generator exports — the shape was never the hard part, and this page is not arguing otherwise.

A concrete example. Take a vendor who marked 40 of the 50 criteria "Supports," then ran out of time: three rows got marked "Partially Supports" or "Does Not Support" with no remarks typed in, the Report Date and Evaluation Methods Used fields stayed blank, and the last 9 criteria were never touched. In a Word table, that document looks finished — every visible cell has something or nothing in it, and nothing distinguishes "fine" from "not done." Run the same answers through this generator and it reports:

  • 1.4.3 Contrast (Minimum): marked "Partially Supports" with no remarks
  • 2.4.7 Focus Visible: marked "Does Not Support" with no remarks
  • 3.3.1 Error Identification: marked "Partially Supports" with no remarks
  • Report Date is blank
  • Evaluation Methods Used is blank

5 completeness issues, and a running count — 41 of 50 criteria evaluated, 9 still "Not Evaluated" — that a hand-filled Word table never surfaces on its own.

When you still need your own testing, not this generator

Nothing here tests your product. Every conformance level and every remark is typed in by the vendor, from their own accessibility testing, exactly as it would be in Word. This generator never scans, crawls, or decides a level on anyone's behalf, and it never picks a value for you — it only checks that the answers already entered are complete enough for a reviewer to trust. Passing every check here is not an accessibility audit and does not mean the product conforms; it means the document explains itself.

Common questions

What does filling out the Word template by hand actually get right?

The table shape. ITI's VPAT 2.5 template already has the right column headings, the right 50 WCAG 2.1 A/AA rows in the right order, and the right four conformance values to choose from. A vendor who works through it carefully produces a document that looks exactly like the ones this generator exports -- the shape was never the hard part.

Why is a blank Remarks cell so easy to miss in Word?

Because an empty cell in a 50-row table looks the same whether it is empty because the criterion is fine, empty because nobody tested it yet, or empty because someone marked "Partially Supports" and meant to come back and explain why. Word has no rule that a Partially Supports or Does Not Support row needs a sentence next to it -- that rule lives in WebAIM's procurement guidance, not in the template file, so nothing in the document itself ever points at the gap.

How does a criterion get silently skipped?

The same way any row in a long table gets skipped under deadline: the reviewer works top to bottom, gets interrupted, and the last several rows never get touched. In a Word table an untouched row is just a row with no value chosen in a dropdown -- there is nothing that distinguishes it from a completed row until someone scrolls back through all 50 and checks. This generator defaults every unanswered criterion to "Not Evaluated," one of the template's own four values, so an untouched row is visibly and honestly labelled rather than blank.

Does this generator decide any conformance level for us?

No. Every Supports, Partially Supports, Does Not Support, Not Applicable, and Not Evaluated choice is typed in by the vendor, from their own testing, exactly as it would be in Word. The generator never scans, crawls, or assesses the product, and it never picks a level on anyone's behalf -- it only checks that the answers already entered are complete enough for a reviewer to trust.

Is a completeness check the same as an accessibility audit?

No, and this page is not claiming that. Completeness only asks whether the document explains itself -- a remark on every partial row, a filled-in report date, every criterion visibly addressed. It says nothing about whether the underlying conformance levels are accurate. A report can pass every completeness check here and still misrepresent the product if the testing behind it was wrong.
