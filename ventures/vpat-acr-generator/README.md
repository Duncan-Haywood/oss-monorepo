# VPAT / Accessibility Conformance Report Generator

**Live tool:** <https://duncan-haywood.github.io/monorepo-projects/vpat-acr-generator/>

Software vendors responding to a federal (Section 508) or enterprise procurement RFP are usually asked for a VPAT (Voluntary Product Accessibility Template) -- a completed one is called an Accessibility Conformance Report (ACR). This tool turns your own WCAG 2.1 Level A/AA self-assessment (which criterion you determined "Supports", "Partially Supports", "Does Not Support", or "Not Applicable", and your remarks on each) into a correctly formatted VPAT 2.5-shaped ACR document, ready to attach to a proposal.

**It does not test your product.** You choose every conformance level and write every remark yourself, from your own testing (automated tools, manual keyboard/screen-reader testing, or both). This tool only assembles those answers into the standard table and flags the specific completeness problems that make an ACR look untrustworthy to a procurement reviewer -- a Partially Supports or Does Not Support row with no remarks explaining it, and a missing header field.

## Run it

Open `index.html`. Fill in the report header (product name, version, report date, evaluation methods used), then go down the table of 50 WCAG 2.1 Level A/AA success criteria choosing a conformance level and, where relevant, writing a remark for each. Choose **Generate ACR** to see the assembled document, the completeness-issue list, and a live summary count. **Download .txt** or **Copy report** to get the text; **Print / Save as PDF** opens the browser's own print dialog on just the generated report. A 50-row form is real work, so an optional local-only draft auto-save (a checkbox, on by default) keeps your progress in this browser across a reload -- turn it off any time, and nothing it saves ever leaves your machine.

Everything runs client-side. Nothing you type is uploaded, there is no account, and there is no network call. Usage counting is an anonymous local event tally (`report_generated`, `report_downloaded`, `report_copied`, `report_printed`) with a visible opt-out, honoring `Do Not Track`/Global Privacy Control automatically.

## Opportunity assessment

The buyer is a software vendor's proposal, sales-engineering, or accessibility lead preparing a response to an RFP that requires a VPAT/ACR -- every U.S. federal software procurement under Section 508 asks for one, and it has spread to state, university, and large-enterprise procurement beyond government. This is a different niche and buyer from every accessibility product already in this portfolio: `shopify-a11y-evidence` and `ada-title-ii-evidence` both turn an `axe-core` scan into a dated evidence record for a *website operator's own site* (a merchant, a government webmaster); this tool formats a *vendor's self-declared, per-criterion conformance table* in the specific standardized shape procurement reviewers expect, for any software product, not any one platform's storefront or a government entity's own site. `eaa-remediation-pipeline` sells a paid remediation/triage service; this ships nothing paid. Checked against `portfolio/pipeline/duplicate_check.py` before writing this up -- the closest match was `shopify-a11y-evidence` at 0.10, far under the 0.45 review bar.

**Distribution channel.** "VPAT" and "VPAT template" are established, high-intent search terms with real, demonstrable commercial competition -- Level Access, ITIC's own site, BarrierBreak, Accessibility.Works, and WCAG.com all publish SEO-targeted guides and paid-service pages for exactly this query, which is evidence of real, sustained search volume rather than a niche nobody searches. The more specific channel is the **WebAIM Discussion List** (`webaim.org/discussion`), a long-running, high-traffic mailing list read by accessibility professionals, in-house accessibility leads, and consultants -- searched and archived threads exist specifically about VPAT mechanics and pain points (e.g. thread 8773, "VPATs for Word, PPT, Excel, etc"; thread 10051, "VPAT for U508"), confirming this is a recurring, actively discussed topic on that list rather than an inferred one. WebAIM's own article "Making VPATs and ACRs More Effective in Procurement" (`webaim.org/articles/procurement/vpat/`) independently documents the exact failure mode this tool's completeness check targets: incomplete ACRs across the vendor pool, and remarks that are too generic for a reviewer to use, especially on partial-support rows. That is a named, sourced problem statement from the audience's own reference source, not an invented one.

**Liability containment stays high by construction, which is the reason this shape was chosen over an assessment or scanning tool.** The tool never reads a product, never runs a scan, and never selects a conformance level -- every substantive claim in the output is the vendor's own, entered by the vendor. Being wrong here costs a formatting mistake in the vendor's own document, not a false assessment attributed to this tool; that is a materially different liability shape from `eaa-remediation-pipeline` (which does render an automated audit) or from a hypothetical "AI-assessed VPAT" this portfolio explicitly does not build. Ethical robustness: this makes an otherwise $2-5k-consulting-fee document (per public accessibility-consultancy pricing pages) freely producible by any vendor, including small ones currently priced out and most likely to skip 508 documentation altogether -- more vendors documenting real self-tested conformance, honestly, is a better outcome for buyers than fewer vendors documenting anything.

Low variable cost: a static page, no server, no per-user cost, no AI dependency at all (deterministic formatting has no need for a model). Future path, if this finds a buyer, is a hosted multi-product/version history or a WCAG 2.2-criteria edition -- not needed for the free core to be useful today.
