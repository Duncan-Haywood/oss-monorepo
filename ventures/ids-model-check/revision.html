How changes are graded

Specifications are paired by name, then by an identical applicability (a rename), then by a leading section number such as 3.3 or (3.3). Inside a pair, facets are paired by what they ask about: a property by its set and name, an attribute by its name, a classification by its system.

  • asks more a new required facet, optional to required, fewer allowed values, a narrower range, a data type added, or an applicability condition removed (more elements are checked).
  • asks less the reverse.
  • different neither contains the other: another value, a pattern that lets through some new values and refuses some old ones, another class, or a change to or from prohibited.
  • Patterns are compared by the values they let through, read as XML Schema regular expressions (the reading IfcTester uses): D-[0-9]+ to D-[0-9]{2} asks more, [0-9]{2} to [0-9][0-9] is the same. A graded pattern change names the shortest value that matched before and not now, and the reverse, so you know what to search the model for.
  • metadata names, descriptions, instructions, IFC versions and bSDD links only.

Run on 69 committed revisions of 27 public IDS files in 13 GitHub repositories: no file it could read failed to compare, and 185 of the 233 changes were graded asks more or asks less exactly (how it was checked). Command line: node cli.mjs --diff OLD.ids NEW.ids [MODEL.ifc] [--json], exit 1 when the revision asks more.
