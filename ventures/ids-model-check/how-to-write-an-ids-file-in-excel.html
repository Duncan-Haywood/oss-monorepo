How to write an IDS file in Excel or as a CSV

Most information requirements start life in a spreadsheet: a row per element type, a column per property. An IDS file holds the same thing as XML. The free checker turns a spreadsheet with one row per facet into a valid IDS 1.0 file, audits it, and turns any IDS back into the same spreadsheet for review. You can also drop the spreadsheet straight on the checker in place of an .ids.

Download the example spreadsheet (open it in Excel or LibreOffice)

The layout: one row per facet

Each specification is a specification row (its name, IFC version and whether it is required, optional or prohibited), then applicability rows saying which elements it covers, then requirements rows saying what they must have. The spec column ties the rows together. The example has two specifications:

specsectionfacetname / entitypropertySetpropertydataTypevalue
infotitleDoor and wall data
1specificationDoors carry a fire rating
1applicabilityentityIFCDOOR
1requirementspropertyPset_DoorCommonFireRatingIFCLABEL
2specificationExternal walls say whether they carry load
2applicabilityentityIFCWALL
2applicabilitypropertyPset_WallCommonIsExternalIFCBOOLEANTRUE
2requirementspropertyPset_WallCommonLoadBearingIFCBOOLEAN

A value cell can hold a restriction instead of a single value: one of: EI30 | EI60, pattern: [A-Z]{2}-\d{3}, >= 2.4 or max length: 20. Facets other than property take their own columns: attribute, system for classification, relation for part-of.

Steps

  1. Start from the example, or from an IDS you already have: on the checker, Audit the IDS only and then Download as a spreadsheet (.xlsx) gives the same layout with drop-down lists of classes and property sets.
  2. Fill the rows. Property set and property names must match the IFC standard or your project's own sets exactly; the IDS editor lists each class's standard sets if you are unsure.
  3. Drop the saved .xlsx or .csv on the checker's IDS box, or run node cli.mjs --from-sheet sheet.csv -o requirements.ids. Every row the reader cannot use is reported with its row number.
  4. Press Audit the IDS only, then check a model with it.

The TRUE/FALSE trap

IDS writes booleans in lower case, true or false. Excel and LibreOffice turn a typed true into a boolean cell and save it to CSV as TRUE, which matches no element: an IDS written that way says the external-wall specification applies to nothing. The reader lower-cases TRUE and FALSE on a boolean-typed property and prints a warning naming the row, so the example's row 8 comes out as true. Text properties keep their case.

Checked against the sample house, the example IDS passes 0 of 2: the door D-01 has no Pset_DoorCommon, and of the two external walls, W-01 says it is load-bearing and W-02 does not say.

Already using the Excel2IDS template?

buildingSMART-community's Excel2IDS template (asset categories in columns, an X where a category needs a requirement) is a different layout. Drop the filled workbook on the checker as it is: it is read without the Windows tool, and the page lists every cell where that tool would write a different IDS.

Questions

Can I write an IDS file without XML?

Yes. Fill a spreadsheet with one row per facet and the free checker writes the IDS XML for you, then audits it against the IDS rules and the IFC schema.

Why does my IDS match no elements?

The most common reasons are a boolean saved as TRUE instead of true, a class name for the wrong IFC version, and a property set name that differs from the export by one character. Audit the IDS first: it reports the first two.

Can I turn an existing IDS back into a spreadsheet?

Yes. Audit it on the checker and choose Download as a spreadsheet (.xlsx) or (.csv), or run node cli.mjs --to-sheet spec.ids -o spec.xlsx.

Does it work with LibreOffice and Google Sheets?

Any tool that saves .xlsx or .csv can be used: the reader takes the cells, not the program that wrote them.
