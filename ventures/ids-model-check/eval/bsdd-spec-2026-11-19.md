# An IDS from a bSDD class's property list (2026-11-19)

What was built: `bsdd-spec.mjs` and `node cli.mjs --from-bsdd CLASS_URI...`.
For each class it asks bSDD
(`/api/Class/v1?Uri=...&IncludeClassProperties=true`) and writes one IDS
specification: entity (and, outside IFC, classification) applicability, the
class's `uri` on a requirement classification facet, and one property facet per
class property with its bSDD `uri`, a dataType, the allowed values, a fixed
value or bounds, and `isRequired` as the cardinality (README, "An IDS from a
bSDD class"). Also: the editor now keeps a facet's `uri` when it opens a file
and writes it back.

## The editor dropped every bSDD link (fixed)

`ids.mjs` never kept a facet's `uri`, so the editor (editor.html) wrote back a
file with every link gone. `node eval/editor-uri-roundtrip.mjs` opens each of
the 58 distinct public IDS files with bSDD links (`sh eval/fetch-bsdd-ids.sh`,
eval/bsdd-links-2026-11-19.md) the way the page does and compares the
(specification, facet kind, uri) triples before and after:

| | uris written back | files with every uri kept |
| --- | --- | --- |
| before (main at 2026-11-19 10:40 UTC) | 0 of 344 | 0 of 53 |
| after | 344 of 344 | 53 of 53 |

Output: `eval/editor-uri-roundtrip.txt`.

## Generated files across bSDD

`node eval/bsdd-spec-corpus.mjs --cache DIR` takes every Active,
latest-version public dictionary in bSDD (63, plus IFC 4.3), the first four
classes in each dictionary's own order (of its first 24) that list
properties, and 40 IFC 4.3 classes (every seventh), builds one IDS per
dictionary, and checks each file with the audit (ids.xsd structure and the IFC4X3
templates) and the bSDD link check (bsdd.mjs). Output: `eval/bsdd-spec-corpus.txt`.

- 42 of 64 dictionaries have a class with properties among their first 24
  (the nine SCFclass dictionaries, GSA Space Entities and others are
  classification lists with no properties).
- 185 classes, 9,198 requirement facets, 8,829 property facets.
- **Audit:** 38 of 42 files have no error (33 no warning either).
- **bSDD link check:** 42 of 42 files have no error and 41 no warning:
  every class and property link the generator wrote resolves to the entry it
  names, with the name and allowed values that entry has.

The sample is "the first classes that answered": bSDD answers some bursts with
429 or not at all, so a class that failed one run can be picked in the next.
Three runs picked 170, 181 and 185 classes. The numbers above are from the last run.

### What the remaining errors are (read by hand)

All are the dictionaries' own data. The IDS says what the dictionary says, so
the audit finds the dictionary's faults:

| errors | dictionary | what |
| --- | --- | --- |
| 6 | FM waveware Spital 2.0 | its own set is named `Pset_FM`; IDS reserves `Pset_` for standard sets |
| 2 | ICC Test 01 1.1 | same, `Pset_ICCGreen` |
| 3 | DM BIM Information Requirements 1.0.4 | `Qto_BeamBaseQuantities.Area`: the IFC template has no `Area` |
| 1 | UniversalTypes 1.0 | a Boolean property whose allowed values are languages ("Deutsch") |

Warnings: 44 `value-no-datatype` (allowed values on properties bSDD gives no
data type, mostly "Klassen und Merkmale der Vorgehängten Hinterlüfteten
Fassade" and "Building equipments"), 9 `class-abstract` (related IFC entities
that are abstract), 1 `pset-performance`.

The 6 bSDD warnings are all on IFC 4.3: the IFC templates and bSDD's IFC
dictionary disagree on a type (`NominalHeight`, `NominalLength`,
`NominalWidth`: templates IfcNonNegativeLengthMeasure, bSDD
IfcPositiveLengthMeasure; `NominalEfficiency`). The generator writes the
template's type because the audit holds a facet to it, and the bSDD check says so.

## Five generator faults found and fixed while measuring

The first run (170 classes, 39 dictionaries) had 9 of 39 files with an audit
error (189 errors) and 1 with a bSDD error:

1. **predefinedValue "None".** 165 class properties in 9 dictionaries answer
   `"predefinedValue": "None"`, on Real and Boolean properties too. It was
   written as a required value; 162 `value-format` errors and 28 `bsdd-value`
   warnings. "None" now means no value, and a predefined value outside the
   property's own allowed values is left out with a note (2 cases).
2. **Quantities and text typed from bSDD's data type.** bSDD's IFC class
   lists leave the "takes 'IfcX' as value" note off `Qto_` quantities and some
   text properties, so `GrossSideArea` came out IFCREAL and
   `WarrantyContent` IFCLABEL. A standard set's template type now wins (31
   errors on IfcWall alone, before the first corpus run).
3. **`ElementType` on IfcWall.** bSDD lists the type objects' attribute on
   occurrence classes; an attribute facet is now written only where every
   applicable entity has that explicit attribute (35 left out).
4. **A set named as a pattern.** Dura Vermeer's dictionary names sets
   `Pset_.*Common` and `Qto_.*BaseQuantities`. Written as a literal name, they drew 20
   `pset-custom` errors. They are now written as `xs:pattern`.
5. **A set name cut short and a property with no code.** bSDD's IFC 4.3
   dictionary gives `Pset_AudioVisualApplianceTypeRailwayCommunicationT`. A
   `Pset_`/`Qto_` name that starts exactly one template set is completed to that set.
   Two properties with an empty code (an empty `<baseName>`, an ids.xsd error) are
   left out.

## What is not carried over (said on stderr)

535 complex properties (`IfcComplexProperty`: no IDS 1.0 facet reaches
inside one); 406 properties of value kind Range or List, written as plain
property facets (IDS 1.0 has no bounded or list value); 129 properties with no
bSDD data type, written with no dataType; related IFC entities missing from
IFC4X3 (22).

## Limits

- CLI only: bSDD's API still sends no CORS header (checked 2026-11-19 with an
  `Origin` header and a preflight), so the page cannot ask it.
- Real properties outside IFC were written as IFCREAL; since the same day
  their unit picks the IFC measure, values in SI (eval/bsdd-units-2026-11-19.md).
- No model was checked against a generated IDS here; the measure is that the
  files are valid, audit clean and agree with bSDD, not that real models pass.
