# IDS patterns read as XML Schema regex (2026-11-18)

IDS says an `<xs:pattern value="..."/>` is an XML Schema regular expression
(XSD Part 2, Appendix F), and IfcTester reads it that way: `ifctester/facet.py`
calls elementpath's `translate_pattern(p, back_references=False,
lazy_quantifiers=False, anchors=False)` and then `re.fullmatch`. This checker
used to hand the text to JavaScript's `RegExp` with `^(?:...)$` around it. The
two readings part on text people really write:

| written | XSD (IfcTester) | old reading here |
|---|---|---|
| `^IFC.*SYSTEM` | `^` is a plain character, so no class name matches | anchor: matches IFCPIPESYSTEM |
| `^\d{2}\.\d{2}\.\d{3}$` | looks for a `^` and a `$` in the value | anchors |
| `(?:0[1-9]\|1[0-2])` | not a regex: elementpath raises and IfcTester stops | non-capturing group |
| `\w+` | anything but punctuation, separators, controls (`Wall+`, `Våtrom`) | A-Z, a-z, 0-9, `_` |
| `\d` | any Unicode decimal digit | 0-9 |

So the same IDS file gave a different verdict here than in IfcTester, and the
page said nothing about why.

## What changed

- `xsdregex.mjs`: a parser for the XSD 1.0 regex grammar. It either names the
  first place a pattern breaks it (with what to write instead), or returns a
  JavaScript regex (`v` flag) with the XSD meaning: whole-value match, `^` and
  `$` as characters, `.` excluding line breaks, `\d` = `\p{Nd}`, `\w` = not
  `\p{P}`/`\p{Z}`/`\p{C}`, `\s` = space, tab, LF, CR, `\i`/`\c` as XML name
  characters, `[a-z-[aeiou]]` subtraction, the Unicode 3.1 `\p{IsBlock}` names.
- The checker matches with it (`ids.mjs` `xsdRegex`). A pattern that is not
  XSD still runs on the old reading, but the audit makes it an error, so the
  specification reports INVALID, as it effectively is in IfcTester.
- The audit (`audit.mjs` `patternIssues`), on every facet's patterns:
  `pattern-not-xsd` (error), `pattern-anchor` (warning: `^`/`$` are
  characters), `pattern-escape` (warning: `\/`, `\$` and other escaped
  punctuation XSD 1.0 does not define; elementpath reads them as the
  character, and buildingSMART's own test files write `\/`),
  `pattern-word-class` (warning: a bare `\w`, see "elementpath departs" below).
- The repair (`fix.mjs`, page "Download repaired IDS", `cli.mjs --fix`):
  `(?:` to `(`, anchors dropped from the pattern or its top-level branches,
  needless backslashes dropped, `{,n}` to `{0,n}`; offered only when the result
  parses as XSD.

## Same answers as elementpath

`node eval/xsd-regex.mjs [seed] [count]` (needs `eval/fetch-audit-corpus.sh`,
`eval/fetch-testcases.sh` and a Python with elementpath, `eval/xsd-regex-truth.py`)
compares verdicts (valid or not) and, for valid patterns, the full-match
answer on 30+ probe strings each (random strings over `ab1-^$. /{}é_+٣Ωz`,
line breaks and tabs, plus fixed ones). Output for seed 20261118:
`eval/xsd-regex.txt`. elementpath 5.1.4, IfcTester 0.9.0.

| set | patterns | same verdict | same verdict and every probe |
|---|---|---|---|
| every distinct pattern in the 65 public IDS files, the IDS-Audit-tool test files and buildingSMART's test cases | 78 | 78 | 77 |
| repairs of those (the repaired pattern read as XSD must answer as the original did as a JavaScript regex, on the probes plus 21 values the originals target) | 10 | 10 | 10 |
| random patterns from 69 tokens, seed 20261118 (rules tuned on this set) | 3,000 | 2,933 | 2,902 |
| seed 7 (run once, after) | 3,000 | 2,927 | 2,902 |
| seed 31 (run once, after) | 3,000 | 2,930 | 2,904 |

Every disagreement in all five rows falls in one of two places where
elementpath departs from the XSD text, so these were left as XSD says:

- **A bare `\w` or `\W`** (outside `[...]`) becomes Python's `\w` (letters,
  digits, underscore), not XSD's "not punctuation, separator or other"; inside
  `[...]` elementpath uses the XSD set. So `\w+` takes `Wall+` in XSD and not
  in IfcTester. 32, 26 and 27 of the random patterns, and `\w+` (16 of
  buildingSMART's test files) in the corpus. The audit warns on a bare `\w` and
  suggests `[\p{L}\p{Nd}_]` or `[^\p{P}\p{Z}\p{C}]`, which every reader agrees on
  (both are in the random token set). buildingSMART's suite scores the same
  either way: 334 of 334.
- **A range from a multi-character escape**, `[\d-z]`: not XSD (a range needs
  single characters at both ends), and elementpath copies it to Python, where
  it becomes a backslash-to-`z` range. 67, 73 and 70 of the random patterns;
  none in the corpus.

One original, `^Ambienti|Servizi|Terziario|Parti comuni${1}`, is not a
JavaScript regex at all (`${1}` repeats nothing), so its repair was compared
with elementpath only.

Three behaviours were set by elementpath where the XSD texts differ: a lone
`}` is a character (XSD 1.0 Char; XSD 1.1 disallows it), a lone `{` is an
error, and escaped punctuation is the character (with the `pattern-escape`
note).

## What it finds

37 of the 65 public IDS files use patterns (219 pattern values). 4 of them,
plus 3 IDS-Audit-tool issue files, have one that reads differently in
different tools:

| pattern | file | finding |
|---|---|---|
| `^2[ab]` | BIM2SIM `check_2LSB.ids`, `ifc_bps.ids` | anchor: matches nothing in XSD |
| `^did:web:...$` | digital-nexus-ontology `Casa Martirana.ids` | anchors |
| `20\d{2}-(?:0[1-9]\|1[0-2])-...` | DFE `Grouped_Stage_5_5_08_17-18-Object.ids` | not XSD (`(?:`): IfcTester stops |
| `[^n].*\|n([^/].*)?\|n\/...` | same DFE file | `\/` escape |
| `^IFC.*SYSTEM` (47 times) | IDS-Audit-tool Issue 61, Mechanical | anchor |
| `^(?:123 - UU-toalett\|...)$` and two more | IDS-Audit-tool Issue 61, Architectural | not XSD, anchors |
| `^Ambienti\|...${1}` | IDS-Audit-tool Issue 08 | anchor |
| `[Name`, `[Some` | IDS-Audit-tool InvalidIfcEntityPattern, Issue 08 | not a regex in any reader (already an error) |

The repair rewrites 60 patterns in 7 files. `node eval/fix-structure.mjs` on all
145 corpus files: 107 files with no fault come back byte for byte, 7 change
only in `xs:pattern` values and read the same as the original with those
patterns rewritten, and the 14 files with ids.xsd faults still read the same
after repair (14 of 14).

On the sample house (walls W-01, W-02, P-01), a Name pattern requirement gives
the same verdict as IfcTester 0.9.0: `(?:.*)` IfcTester raises, here INVALID
with `pattern-not-xsd`; `^W.*` and `^.*$` fail in both, with a `pattern-anchor`
warning here; `[WP]-.*` and `(W-01|W-02|P-01)` pass in both
(`xsdregex.test.mjs`). buildingSMART's suite: 334 of 334 before and after;
the IDS-Audit-tool valid files: 1 of 9 flagged before and after (the same file,
for an unrelated attribute).

## Limits

- The `v` flag needs Chrome 112, Firefox 116 or Safari 17. An older browser
  falls back to the old reading for every pattern.
- Unicode categories and blocks follow the browser's Unicode version, not
  XSD 1.0's Unicode 3.1; the blocks are the Unicode 3.1 ranges.
- The grammar is XSD 1.0's; of XSD 1.1's changes only the `\$` escape is read.
