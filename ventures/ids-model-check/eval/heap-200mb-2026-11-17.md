# Heap use on a 200 MB model: read arguments when a check needs them (2026-11-17)

The README's Limitations said "about 1 GB of heap for a 200 MB model". Measured,
it was 2.5 GB, and the page's tab died under a 1 GB heap. This run makes the
STEP reader lazy and measures the result on real exports.

## Setup

No single public IFC export near 200 MB was found, so `eval/federate.mjs`
joins real exports the way a coordination model holds several disciplines:
each file's entity numbers are shifted past the previous file's, and `#n`
references outside strings with them. Inputs, from `opensourceBIM/IFC-files`
at `cb96c50` (fetch steps in `model-attr-codes-2026-11-17.md`): HHS Office
`MEP.ifc`, `MEP2.ifc`, `architect.ifc`, `architect2.ifc`, `construction.ifc`,
`construction2.ifc`, OpeningDesign's `Schultz_Residence.ifc`, then `MEP.ifc`
and `MEP2.ifc` a second time.

```
node eval/federate.mjs fed200.ifc "HHS Office/MEP.ifc" "HHS Office/MEP2.ifc" \
  "HHS Office/architect.ifc" "HHS Office/architect2.ifc" "HHS Office/construction.ifc" \
  "HHS Office/construction2.ifc" OpeningDesign.com/Schultz_Residence.ifc \
  "HHS Office/MEP.ifc" "HHS Office/MEP2.ifc"
```

Result: 219,033,563 bytes, IFC2X3, 3,671,279 entities. The repeated MEP files
repeat GlobalIds; nothing below depends on GlobalIds being unique.

IDS sets: the three starter files in `samples/`, and those three plus the 65
public IDS files `eval/fetch-audit-corpus.sh` fetches (68 files; one public
file is not a readable IDS and fails the same way on both sides).
`eval/heap-compare.mjs` parses the model once, checks it against each IDS with
`maxFailed: 1000` (the CI default), and prints wall time, `maxRSS` and a
SHA-256 of every report with `seconds` removed. "main" is `origin/main` at
`7c80eb72c`, unpacked with `git archive`. Node 22.23.4, 4 vCPU, 16 GB.

## What changed

- `step.mjs`: the scan records each entity's number, type and where its
  argument list starts, finding the record's end by its `;` (skipping strings
  and comments). `args` is a getter that parses on first read. A record the
  file ends inside is still read at once, so a truncated export still names
  what was left open. A record that cannot be read records its error when first
  read and has no arguments (main dropped it from the model).
- Type names are interned: one `"IFCCARTESIANPOINT"` string, not 1.2 million.
- `ids.mjs` (`Model`): arguments of `IfcRepresentationItem` and its subtypes
  (points, loops, faces: 75% of the HHS MEP export's entities) are parsed on
  each read and not kept. Only a specification with no entity facet reads
  them, once or twice per entity.
- `parseStep(text, { eager: true })` keeps the old behaviour; a test checks
  the lazy and eager reads give equal arguments for every entity of the
  sample.

## What it does not fix

- The 68-file run on the 219 MB model is 21% slower and still peaks at 4.7 GB:
  public IDS files with no entity facet apply to all 3.7 million entities, and
  geometry is parsed again for each read. On a 16 GB machine Node's default
  heap limit (about 4 GB) is below that, so that run still needs
  `--max-old-space-size`. With the starter files it fits in 1 GB.
- The small construction export peaks 55 MB higher: it is mostly non-geometry
  entities, so the per-entity record costs more than it saves.
- The ifcXML reader (`ifcxml.mjs`) still builds every entity up front.
- The model's text stays in memory (219 MB here) for the lazy reads.
