# Decibel properties as sound pressure or sound power levels (2026-11-19)

What was built: `levelOf` in `bsdd-units.mjs`. `--from-bsdd` used to keep
every bSDD Real in `dB` as `IFCREAL`, because QUDT's `DeciB` is both a
SoundPressureLevel and a SoundPowerLevel (eval/bsdd-units-2026-11-19.md,
"Limits"). IDS compares a property's IFC type exactly, so a model that
stores an acoustic level the way IFC means it, as
`IfcSoundPressureLevelMeasure` or `IfcSoundPowerLevelMeasure`, failed every
such facet.

## The rule

A dB property gets a level measure only when the property itself says which
one:

1. **Words** in `physicalQuantity`, the name or the code: "sound power"
   (Schallleistung, geluidsvermogen, puissance acoustique, potencia acústica,
   potenza sonora) gives the power level, "sound pressure" (Schalldruck,
   geluidsdruk, pression acoustique, presión acústica/sonora, pressione sonora)
   the pressure level. Both named: no pick.
2. **The ISO symbol** the code starts with, split on `_ , . ' ′ -` and
   spaces:
   - `L_W`, `LW`, `Lw`, `LWA`, `L_WA`: sound power level (ISO 3740 series).
   - `LA`, `LC`, `LZ`, `Lp`, `Leq`, `LAeq`, `Ln`, `LnT`, `LAFmax`, `Lden`
     and so on, or a bare `L` followed by another token (`L'nT,w`): sound
     pressure level. This covers the maximum A- and C-weighted levels of
     ISO 16032 and ISO 10052 (`LA_Fmax_nT`, `LC_Smax`), which is how
     CEN/TC 126's SERVICE_EQUIPMENT properties are named, and the impact
     levels of ISO 717-2 and ISO 16283-2 (`L'n,w`: the lower-case `w` after
     `n` is "weighted", not power).
   - Anything else, including the weighted sound reduction index `R_w`,
     level differences `DnT,w`, `ΔL_w` and spectrum adaptation terms `C`,
     `C_tr`: no measure. They are in dB but are differences of levels, and
     IFC has no measure for them; IFCREAL stays, with the reason on stderr.

The stated-dimension check still runs after the pick, so the CEN/TC 126
properties whose `dimension` holds a counter in the length slot
(`1 0 0 0 0 0 0` ... `11 0 0 0 0 0 0`, eval/bsdd-units-2026-11-19.md) stay
IFCREAL as before. The two level measures are IFC4 and later; on IFC2X3 the
property stays IFCREAL ("not in the chosen IFC schema").

## Checked on a built model

`node eval/bsdd-db-model.mjs --write DIR` writes one bSDD-style class with
three dB properties (`LA_Fmax_nT` at most 30, `LWA` at most 45, `R_w` at least
50) as an IDS before and after, and adds them to three walls of
`samples/tiny-house.ifc`. Output: `eval/bsdd-db-model.txt`.

| IDS | fails, this checker | fails, IfcTester 0.9.0 |
| --- | --- | --- |
| before: all three IFCREAL | W-01 (type only), W-02 | W-01, W-02 |
| after: pressure level, power level, IFCREAL | W-02 (35 > 30, 50 > 45, 45 < 50), P-01 (type) | W-02, P-01 |

W-01 stores both levels as IFC means and is within every limit: it failed the
old file on type alone and passes the new one. P-01 stores plain IfcReals and
now fails on type, as a wall with an `IfcReal` thickness fails a length
facet. IfcTester agrees on all 6 verdicts
(`python -I eval/bsdd-units-ifctester.py DIR/model.ifc DIR/before.ids
DIR/after.ids`, ifctester 0.9.0, ifcopenshell 0.9.0.post1).

## Not measured

- **The bSDD corpus.** The last cache (eval/bsdd-units-2026-11-19.md) had
  265 Real properties kept as IFCREAL for `dB`; `api.bsdd.buildingsmart.org`
  refused this session's connections, the cache was not committed, and only
  the 10 property names in `eval/bsdd-units-corpus.txt` are known here (all
  10 stay IFCREAL on their stated dimension). The next session with bSDD
  access: `node eval/bsdd-spec-corpus.mjs --cache DIR` then `node
  eval/bsdd-units-corpus.mjs DIR` counts how many dB properties now get a
  level, and every name the symbol rule reads should be checked by eye.
- **What real exports write.** IFC's own property sets type four dB
  properties in IFC 4.3 as `IfcSoundPowerLevelMeasure`, including
  `Pset_EnvironmentalEmissions.NoiseEmissions` and two attenuations
  (`MaximumTransmissionAttenuation`, `SoundAbsorptionLimit`) that are not
  power levels in the ISO sense; none is a bSDD own-set property, so the
  template's type still wins for them. Whether Revit or ARCHICAD write an
  acoustic level as the measure or as IfcReal was not checked: a model that
  writes IfcReal fails the new facet, as it would a length.
