# IDS editor: every offered choice audited, and what that turned up (2026-11-16)

`editor.html` builds an IDS 1.0 file from the IFC schema and buildingSMART's
property set templates (`schema/psets-*.json`): an author picks a class, a
standard set that class can carry and one of its properties, and the editor
writes the template's `dataType`. The logic is `editor.mjs`; the page only
draws it.

## 1. Every choice, through the audit

`node eval/editor-roundtrip.mjs` writes, for each schema, every class the editor
offers, every set it offers for that class and every property of the set: one
specification requiring the property, and one more with a value of the right
kind (an enumeration member, `true`, a lower bound, a pattern). It parses each
IDS back and audits it.

| Schema | Classes offered | Specifications | Presence-only properties (no template dataType) | Errors | Warnings |
| --- | ---: | ---: | ---: | ---: | ---: |
| IFC2X3 | 247 | 32,823 | 2,537 | 0 | 0 |
| IFC4 | 298 | 46,516 | 810 | 0 | 0 |
| IFC4X3 ADD2 | 384 | 124,094 | 2,090 | 0 | 0 |

4.7-5.4 s on one core. Presence-only properties are those whose template gives
no single data type (bounded values, tables, lists, references); the page
offers no value for them, because a value without a `dataType` is the audit's
`value-no-datatype` warning (the first run, with values on them, gave 5,350
such warnings and no errors).

The first IFC2X3 run after IFC2X3 type-mapping names (`IFCACTUATOR` = an
`IfcDistributionControlElement` typed by `IfcActuatorType`) were allowed to
carry their type's sets gave **1,725 `pset-class` errors**: the audit said
`Pset_ActuatorTypeCommon` cannot be required on `IFCACTUATOR` in IFC2X3. It can:
the property facet reads type properties, and the type mapping is how IDS names
those elements. The audit now also accepts the mapped type class
(`audit.mjs`, `templateIssues`). That was an audit false positive no test
case or public IDS had shown.

## 2. A sample, through buildingSMART's XML schema

The audit does not validate against `ids.xsd`. `node eval/editor-xsd-sample.mjs
DIR` writes one IDS per schema: one specification per offered (class, set)
pair with a valued first property, every `Pset_WallCommon` property with every
cardinality, every facet kind, value kind, partOf relation and optionality the
page writes, and escaped `&`, `<` and `"`. `python3 eval/editor-xsd-check.py
DIR/*.ids` opens each with IfcTester 0.9.0 (`ifctester.ids.open(path,
validate=True)`, against the `ids.xsd` bundled with IfcTester).

First run: **3 errors per file**, two real gaps:

- **`relation="IFCRELVOIDSELEMENT"` and `relation="IFCRELFILLSELEMENT"` are not
  IDS 1.0 values.** `ids.xsd` allows one value for voids and fills, the token
  pair `IFCRELVOIDSELEMENT IFCRELFILLSELEMENT` (the user manual, `partof-facet.md`:
  "how element relates to another element through the opening"). The editor,
  the audit and the checker all had the split tokens: the audit called the
  correct pair `relation-unknown` (INVALID, so never run) and accepted the
  split ones that IfcTester refuses to open. buildingSMART's 334 test cases
  have no voids/fills case (relations used: aggregates 12, groups 6,
  containment 9, nests 7), so 334 of 334 did not show it.
  Fixed: the checker reads the pair as IfcTester does (a door filling an
  opening in a wall is part of the wall; the opening is the path, not the
  whole), the audit accepts the pair and flags the split tokens
  (`relation-voids-fills`), the editor writes the pair.
- **A classification facet needs a `system`** (`ids.xsd`: `minOccurs="1"`).
  The audit now flags one without (`classification-no-system`); on the 64
  public IDS files it fires on two, `NL_BIM_Basis_ILS.ids` (OpenAEC
  BIM-validator fixtures) and the Molio example in buildingSMART's
  Community-Sample-Test-Files, and both are refused by `ids.xsd` for that
  reason among others.

After the fixes: 3,379 + 3,104 + 8,619 = **15,102 specifications valid against
`ids.xsd`**, read back by IfcTester.

Unchanged by the fixes: 334 of 334 test cases, no valid test IDS flagged, the
IDS-Audit-tool and public-corpus results except the two new findings above.
