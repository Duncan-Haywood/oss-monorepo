# The GitHub Action on four real exports (2026-11-17)

`action.yml` and `ci-cli.mjs` check every model matching a glob against every
IDS matching another and write JUnit XML, a Markdown job summary, GitHub
annotations, BCF files and step outputs (`ci.mjs` renders them). This run
asks whether that holds up on real exports, not only the sample house.

## Setup

The four exports from `opensourceBIM/IFC-files` at `cb96c50` used by
`model-values-2026-11-17.md` (not committed; fetch steps in
`model-attr-codes-2026-11-17.md`): HHS Office `MEP.ifc` (39.6 MB),
`architect.ifc` (13.1 MB), `construction.ifc` (3.9 MB) and OpeningDesign's
`Schultz_Residence.ifc` (22.5 MB), symlinked into `models/`; the two starter
IDS files from `samples/` in `req/`. Node 22.23.4, this container.

```
node ci-cli.mjs --models "models/*.ifc" --ids "req/*.ids.xml" --annotations \
  --junit j.xml --summary s.md --json r.json
```

The composite step itself was run by extracting `runs.steps[0].run` from
`action.yml` and running it under `bash -e` with the `IDS_*` variables,
`GITHUB_ACTIONS=true`, `GITHUB_OUTPUT` and `GITHUB_ACTION_PATH` set as the
runner sets them (two models, `fail-on: never`, `bcf-dir: bcf`): exit 0, the
nine outputs written, four BCF files. It has not yet run on GitHub's own
runner.

## What the real run caught

- **A count capped at 500.** The engine lists at most 500 elements of a
  prohibited specification (`ids.mjs`, to bound the report), but every match
  fails it. The first run printed "500 of 574 element(s) fail" for the MEP
  model's 574 building element proxies. `failCount` in `ci.mjs` now counts a
  failed prohibited specification by its applicable count, and the JUnit text
  says "... and 524 more"; a test pins it.
- **Symlinked models were skipped.** The directory walk took only regular
  files, so models linked into the folder (as here, and as in repositories that
  link exports from a shared drive) matched nothing. Linked files are now
  followed; linked directories are not, so a link loop cannot hang the walk.
- **Line numbers inside a zip.** An `.ifczip` is STEP text once unzipped, so the
  first version put a line number on the zip file. Lines are now given only for
  `.ifc` paths.
- **`{a,b}` in a comma list.** Inputs are comma or newline separated, which
  first split `*.{ifc,ifczip}` in two. Commas inside braces now stay in the
  pattern.

## Not claimed

- Not yet run on a GitHub-hosted runner or by a team on its own repository.
- GitHub displays at most ten error and ten warning annotations per step; the
  rest are in the job summary and the JUnit file. Seven of the 16 here have no
  element to point at and land on the file's first line.
- Each model is parsed once per IDS file (N x M parses); parsing once per
  model is the next speed-up for repositories with several IDS files.
