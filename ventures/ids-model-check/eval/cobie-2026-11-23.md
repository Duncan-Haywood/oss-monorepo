# COBie 2.4 workbook from IFC, and a COBie QC: checked on 25 public exports, 2026-11-23

**Question.** Owners ask for a COBie 2.4 workbook at handover (NBIMS-US V3
4.2: Contact, Facility, Floor, Space, Zone, Type, Component, System,
Attribute) and their FM teams reject one with blank required cells, template
placeholders or references that point nowhere. Can the checker write that
workbook from any IFC export, in the browser, without inventing values; can it
put components in rooms when the export does not; and does its QC find what an
owner's check finds?

**Data.** `ThatOpen/engine_web-ifc` `tests/ifcfiles/public/` (blob-less sparse
clone, not committed): the 25 STEP `.ifc` files other than the three largest
or roomless (`ISSUE_098` 73 MB, `Viadotto Acerno`, `ISSUE_129`; written
without geometry below), Revit 2011 to 2022, ARCHICAD, Tekla, Rhino and
others. The Duplex, Office, Clinic and FM_ARC_DigitalHub models are the
NBIMS common BIM files, set up for COBie (Duplex carries every COBie field as
a Revit parameter).

**Method.** `node eval/cobie-placement.mjs FILES... --json
eval/cobie-placement-2026-11-23.json` (output
`eval/cobie-placement-2026-11-23.txt`):

1. **Doors and windows.** The truth is the file's own `IfcRelSpaceBoundary`
   rows pairing each door or window with an `IfcSpace` (written by the
   authoring tool). The prediction is ifc-quantity-takeoff's `openingSides()`:
   both sides of the body tested against each room's solid, boundaries never
   consulted.
2. **Other components.** The truth is the space a file contains a
   maintainable component in (`cobie.mjs isAsset`). That containment is hidden
   and `assignRooms()` places the element by where its body stands.
3. **The export.** `cobieFromModel` with that placement, then `cobieQc`
   (design stage): rows per sheet, errors, warnings, time.

A second tool for comparison: IfcOpenShell's `ifcfm` 0.9.0 (pip, LGPL),
`python -m ifcfm -p cobie24 -i duplex.ifc -f csv`. Its `cobie24` preset stops
with `TypeError: can only concatenate list (not "tuple") to list` on Duplex
and on AC20-FZK-Haus; its `cobie24legacy` preset writes.

## Result

| | count |
| --- | --- |
| files written | 25 of 25 (and the 3 left out, written without geometry: 0, 10 and 28 floors; ISSUE_098's 2,657 components in 11 s) |
| doors and windows with file boundaries, body read | 869 |
| ... geometry gives exactly the file's rooms | 791 (91.0%) |
| ... one of its two rooms | 37 |
| ... a room the file does not name (13 extra, 6 different) | 19 (2.2%) |
| ... no room | 22 (16 in ISSUE_171, whose rooms have no solid) |
| components a file puts in a room, containment hidden | 1,227 |
| ... placed in the same room | 935 (76.2%) |
| ... another room | 89 (7.3%; 85 are ARK_NUS furniture) |
| ... none (left blank) | 203 (174 have no body the takeoff reads, 136 of them flow terminals) |

Per file: AC20-FZK-Haus 16/16, C20-Institute 282/283, FM_ARC_DigitalHub
108/109, Office_A 92/93, Duplex 25/28 (3 one side of two), dental_clinic
203/254 (32 one of two, 17 wrong), schependomlaan 49/54.

When the placement answers, its room is one the file names in 828 of 847 door
and window cases (97.8%) and 935 of 1,024 component cases (91.3%). A blank is
left where it does not answer, and the QC lists it.

**Duplex against ifcfm.** Both write 4 floors, 21 spaces, 126 zone rows, 20
types and 99 components (here after 17 Revit type objects that repeat
another's name and class are merged into it). ifcfm leaves `Component.Space` `n/a` on the 38 components Revit put
on a storey; here all 38 are placed (doors and windows on both sides). The QC
run on ifcfm's own CSV output (`--cobie-qc DIR`) finds 4,569 errors: `n/a` in
every `CreatedBy` (the model names no email), the 38 rooms, 9 attribute rows
whose `RowName` is `n/a`, and the template values the model itself carries
(`SerialNumber` = "SerialNumber" on all 99 components; 908 attribute values
equal to their own name). On this tool's workbook, with an email given for
`CreatedBy`, the QC finds 3,888 errors, all template placeholders and blank
required cells the model does not fill (Type.Category and AssetType on all 20
types, CurrencyUnit, AreaMeasurement).

**Why rows lack an email.** None of the 25 files names an email in an
`IfcOwnerHistory` (they carry a login such as `cskender`, or nothing), so
`CreatedBy` is blank on every row unless the person delivering the workbook
gives one (`--contact`, the page's email box). `CreatedOn` is blank where the
owner history's CreationDate is 0 (all Revit 2011 files).

## What is left

- ARK_NUS's 85 furniture items placed in another room: the file's containment
  may follow Revit's room calculation point, not the body's centre; read
  `IfcSpace` overlaps there.
- The 174 components (136 flow terminals) with no readable body: their placement point
  could stand in for the body (`row.world` origin).
- A real owner's COBie QC report on a real deliverable, to set this QC's
  rules against theirs.
- COBie's Document, Spare, Resource, Job, Impact, Connection, Assembly and
  Issue sheets are not written (exports rarely carry them).

Reproduce: clone `ThatOpen/engine_web-ifc` (sparse, `tests/ifcfiles/public`),
then `node eval/cobie-placement.mjs <files> --json out.json`.
