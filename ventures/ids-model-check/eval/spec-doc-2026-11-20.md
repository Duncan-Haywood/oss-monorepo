# The IDS as a readable document, checked against IfcTester's reading (2026-11-20)

`spec-doc.mjs` writes an IDS as a document people read (page: *Download as a
readable document* after an audit; CLI `node cli.mjs --to-doc spec.ids -o
spec.html|.md`). The risk in any such rendering is that the English says
something other than the XML: a value dropped from an enumeration, a bound
left out, an optional facet read as required. This run measures that against
an independent reader of the same files, IfcTester 0.9.0 (IfcOpenShell).

## How

```
sh eval/fetch-audit-corpus.sh                       # 64 public IDS + buildingSMART's IDS-Audit-tool test files
node eval/spec-doc.mjs eval/corpus/real eval/corpus/IDS-Audit-tool/testing.shared > doc.jsonl
pip install ifctester==0.9.0
python3 eval/spec_doc_ifctester.py doc.jsonl
```

`eval/spec-doc.mjs` writes each file's specifications with one plain-text
sentence per facet. `eval/spec_doc_ifctester.py` opens the same file with
IfcTester and, specification by specification, compares:

- the number, kind and order of applicability and requirement facets;
- each requirement's cardinality (required, optional, prohibited);
- the specification's optionality from minOccurs/maxOccurs;
- every name and value IfcTester holds for the facet (simple values, each
  enumeration member, patterns, bounds, lengths, the dataType, partOf's class
  and predefined type), which must appear verbatim in that facet's sentence.
  Class names are compared without case, since the document writes `IFCWALL`
  as `IfcWall`.

## Result

```
ifctester 0.9.0
files 144, opened by IfcTester 113, specifications 1224, facets 4458, names and values 10892
shape misses: 0
cardinality misses: 0
optionality misses: 0
token misses: 0
```

Of 144 files, 7 are not readable XML or not IDS (buildingSMART's invalid-file
tests and one public file with an unclosed tag): this reader refuses them with
the reason, as the audit does. IfcTester does not open 24 more (it decodes
through ids.xsd and stops on files that break it); those were rendered but
have nothing to compare with.

**Does the comparison bite?** The same output with every `Pset_WallCommon`
renamed and the first optional cardinality on each line flipped to required:

```
cardinality misses: 11
token misses: 83
```

## What the sentences look like

Requirement sentences across all 144 files fall into 128 shapes once every
name and value is replaced by V (109 when lists of any length count as one);
the most common:

| count | sentence |
| ---: | --- |
| 519 | It must have the property V in the set V, of data type V, with a value. |
| 496 | Its attribute V must hold the value V. |
| 393 | Its attribute V must be filled in (not empty). |
| 117 | It must be classified in the system V with a code matching the pattern V. |
| 105 | It must have the property V in the set V, of data type V, holding the value V. |
| 84 | It must have a material. |
| 81 | Its attribute V must hold a value that is at least V. |
| 44 | It must have the property V in the set V, of data type V, holding a value matching the pattern V. |
| 14 | It must be part of (IfcRelAggregates) an V. |

All 128 shapes were read by eye for grammar and meaning; the fixes made from
that read: "that is matching" (patterns now read "a code matching the pattern"),
"every ... that have" (now singular), "It must be as a part of" (relation
phrases rewritten to follow "is"), and a value restriction with no facets
(which admits any value) now reads "with a value" instead of "holding any
value", with no unit note.

## Limits

- The check proves the sentences carry every name and value and the right
  cardinality; it cannot prove the English is the clearest wording. Nobody
  who receives IDS appendices has read it yet.
- Numbers keep the IDS's lexical form (`0.1`, not "100 mm"); the unit note
  says which SI unit applies for 27 common measures, and says nothing for the
  rest.
- A facet's `uri` (bSDD link) is not printed.
