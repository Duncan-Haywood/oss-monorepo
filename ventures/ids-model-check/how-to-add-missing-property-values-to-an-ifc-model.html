How to add missing property values to an IFC model

When an IDS check fails because the export left out a property, the lasting fix is in the authoring tool's export mapping. But the model is often due today, the authoring file belongs to someone else, or the value was never in it. The free checker can write the missing values into a copy of the .ifc: the ones the IDS fixes by itself, and the ones you type into a table. Every value is checked against the IDS before it is written, and every other line of the file stays as it was.

Open the free checker (check a model, then scroll to Write the missing values into the model)

Steps

  1. Check the model against the IDS. When a property, quantity or attribute requirement fails, the result ends with a panel, Write the missing values into the model.
  2. Values the IDS fixes (a requirement that allows one value only) are written for you. For the rest, press Download the to-fill table (CSV): a row per missing value with the element's GlobalId, class, name, property set, property, data type and the values the IDS allows.
  3. Type each value in the Value column in Excel, LibreOffice or a text editor. A * as the GlobalId gives every listed element that value.
  4. Choose the filled table on the page and press Download the filled model. The copy is checked against the IDS again before you download it.

A worked example

The sample house fails three specifications of the starter IDS on values: wall W-02 has no LoadBearing, space 001 has no LongName, and partition P-01 has no material. The to-fill table lists the first two (materials are listed by the check, not written):

NamePropertySetPropertyDataTypeValue (typed)
W-02Pset_WallCommonLoadBearingIFCBOOLEANtrue
001(attribute)LongNameIFCLABELLiving room

With those two values typed, the filled copy passes 5 of 7 specifications instead of 3, and both written values pass the requirement that failed. The change to the file is three lines: the space's LongName set in place, the wall's existing Pset_WallCommon given one more property, and that property added as a new line at the end. The same on the command line:

node cli.mjs --fill model.ifc spec.ids -o filled.ifc --to-fill todo.csv
node cli.mjs --fill model.ifc spec.ids -o filled.ifc --values todo.csv

What it will not do

  • Overwrite an attribute that already holds a value, or invent a value: anything the IDS does not fix and you did not type stays listed for a person.
  • Write classifications or materials. Those are listed, because which classification code or material is right is a design decision.
  • Fix the source. The authoring model still lacks the values, so the next export will too; send the to-fill table to whoever owns the export mapping.

Quantities are a special case: a missing Qto_ quantity the element already holds in another set (an IFC2X3 export's BaseQuantities) is copied, and with Measure missing Qto_ volumes, areas and lengths from each element's geometry ticked, missing volumes, areas and lengths (a slab's thickness and perimeter among them) are measured from the element's geometry. A door's or window's width, height, area and perimeter are read from the opening it fills, in ARCHICAD exports, where that is exactly what ARCHICAD stores; Revit's exports store different figures from version to version, so those stay in the to-fill table.

Questions

Can I edit IFC properties without Revit or ArchiCAD?

Yes, for missing values. The free checker writes property, quantity and attribute values into a copy of the IFC file in your browser, checked against the IDS before and after they are written.

Does it change anything else in the file?

No. Every line it does not need to change stays byte for byte as it was, so a diff of the two files shows only the written values.

What if my model is ifcXML or IFC5?

It is written as a STEP .ifc first and that copy is filled, so the download is a .ifc file.

Is the model uploaded?

No. Reading, checking and writing all happen in your browser tab.
