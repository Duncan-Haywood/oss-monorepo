# UBL 2.1 schema pass against xmllint and Xerces (2026-11-26)

What was measured: whether `ubl-xsd.mjs` (rules UBL-XSD-01..07, table read by
`build-ubl-schema.mjs` from the OASIS UBL 2.1 OS package) gives the same pass/fail
verdict as a real XSD validator on UBL Invoice and CreditNote files.

Schema: https://docs.oasis-open.org/ubl/os-UBL-2.1/UBL-2.1.zip, SHA-256
`60b80d76394a8a2add90723ecb8e0e2e9d826775de9749df37a72d60703f86ed`, `xsd/maindoc/UBL-Invoice-2.1.xsd`
and `UBL-CreditNote-2.1.xsd`. Validators: xmllint (libxml2, Debian package in the build
container) and, for the disagreements, the JDK's built-in Xerces (`javax.xml.validation`),
which is what the Java validators (KoSIT, phive) run on.

## Whole files

38 UBL Invoice/CreditNote files: the 27 in `examples/`, 2 in `fixtures/fr-fnfe/`, and the
9 Invoice/CreditNote examples in the OASIS package's `xml/` folder (2.0 and 2.1 examples,
enveloped and detached signatures). xmllint accepts 36 and refuses 2
(`ro-invoice-with-defects.xml`: IssueDate `24.08.2026`; `nlcius-invoice-with-defects.xml`:
PostalZone after CountrySubentity). `ubl-xsd.mjs` gives the same verdict on all 38, with
the same element named on the two refused files.

## Seeded mutations

```
unzip -q UBL-2.1.zip 'xsd/*' 'xml/*'
node eval/ubl-xsd-diff.mjs xsd xml --seed 1 --per 12
node eval/ubl-xsd-diff.mjs xsd xml --seed 7 --per 40
```

16 kinds: a cbc leaf deleted, duplicated, swapped with a different neighbour, an unknown
cbc element inserted, a cac block (one with no cac inside) deleted or duplicated, a cbc
element written as cac:, an attribute dropped, an undeclared attribute added, a value
emptied, made text, given a euro sign, made -1, a date cut to year-month, a time made
25:00:00, a boolean made "yes". Nothing inside ExtensionContent is mutated (not checked;
see below).

| run | seeds | mutations | agree | we pass, xmllint refuses | we refuse, xmllint accepts |
|---|---|---|---|---|---|
| seed 1, per 12 | 36 | 5,017 | 5,017 | 0 | 0 |
| seed 7, per 40 | 36 | 16,709 | 16,702 | 0 | 7 |

All 7 disagreements are one case: a euro sign appended to base64 data in
`EmbeddedDocumentBinaryObject` (ZATCA examples). libxml2 skips characters outside the base64
alphabet; XSD 1.0 Part 2 (3.2.16) does not allow them, and Xerces refuses the same values
(`cvc-datatype-valid.1.2.1: 'QUJD?' is not a valid value for 'base64Binary'`, checked on
`QUJD€`, `€€€€` and `QUJD!`; `QUJD` it accepts). We follow the spec and Xerces.

## Fixes the measurement forced

- The base64 padding pattern first wanted three characters before `==`; it refused every
  ZATCA QR code. Corrected to one character, measured again (above).
- The harness itself first lost xmllint's verdicts on all-valid batches (xmllint writes
  "validates" to stderr); it now reads both streams.

## Limits

- ExtensionContent (`xsd:any namespace="##other" processContents="lax"`) is checked only
  for holding exactly one element outside the ext: namespace; what that element holds is
  not looked into. xmllint validates it laxly when it knows the element (the UBL signature
  module); we do not.
- `xsi:type` is not modelled. Mixed text inside an aggregate (cac:) element is not flagged.
- The seeds are examples and test files, not invoices businesses sent; no real refused
  file was available.
- CII D16B is a separate item (`cii-xsd-schema`, claimed by another run).
