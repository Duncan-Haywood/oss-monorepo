Common questions

Why does a Bash allow-all rule matter?

Claude Code's permission rules scope a tool by an optional pattern, e.g. Bash(git diff:*). A bare "Bash", or a pattern whose scope is itself a wildcard, grants every shell command with no prompt at all — functionally the same as disabling permission prompts for the one tool an agent can use to do almost anything else on the machine, including reading other credentials, modifying git history, or making arbitrary network requests via curl.

Why flag a plain http:// MCP server URL?

An MCP server reached over http:// sends every request, including any bearer token or API key in its headers, unencrypted on the wire. Anyone on the same network path can read or tamper with it. This is worth catching mechanically because a config that started as a local http://localhost dev server during setup is easy to copy into a shared or committed file without ever switching to https://.

Does this tool run, connect to, or attack anything the config describes?

No. It only reads the JSON text you give it (pasted, or a local file when using the CLI) and looks for known-risky shapes in it — it never launches an MCP server's command, never makes a network request to a server's url, and never sends a value anywhere to test whether it is a real, live credential.

How confident is the hardcoded-secret check?

A value matching a known token format (an Anthropic, OpenAI, GitHub, Slack, AWS, Google, GitLab, or npm token prefix) is reported at high confidence. A long, space-free, unrecognised literal is reported at medium confidence — flagged because it looks more like a token than a normal setting, not because it is proven to be a secret. Either way, verify by reading the value yourself before rotating anything.
