This checker vs. checking it by hand

Reading an instructions file and clicking through its links is a normal way to catch drift once, and it works fine for a short file checked right after you edit it. It is a different job from confirming the file is still accurate today, after every commit that touched anything the file names -- most of which nobody thinks to re-check, because they didn't touch the instructions file itself.

Common questions

What's wrong with just opening the file and clicking every link myself?

Nothing, for a short file, checked once. It stops scaling the way these files actually grow: a CLAUDE.md or AGENTS.md that accumulates dozens of file references and npm-script mentions over months means clicking through all of them, correctly, every time anything else in the repo moves -- and nobody re-checks a paragraph they didn't just edit. This tool resolves every reference in the file the same way, every time you run it, in the time it takes to paste the file in.

I can just run each referenced npm script once to see if it exists -- isn't that enough?

It confirms the scripts that exist today. It does not get re-run the next time a script gets renamed in an unrelated PR, so the instructions file drifts again as soon as you stop checking -- which is exactly when an agent following it hits the stale name. This tool checks every npm run reference against package.json's scripts map in one pass, so re-checking after any change costs nothing extra.

Wouldn't a human reviewer just notice a bare pytest in a code review?

Only if the reviewer already knows the specific footgun exists -- that an isolated tool install (a uv tool install, a pipx install) can put pytest or mypy on PATH pointed at a different interpreter than the repo's own dependencies. Without that context, pytest tests -q and python3 -m pytest tests -q read as interchangeable phrasing, not a real difference, and the one-word gap is easy to skim past even for someone looking. This tool applies the same two rules every time, so it does not depend on the reviewer already knowing the failure mode.

Is anything I check here uploaded anywhere?

No. The browser page parses the text you paste and the file names it reads from a folder you pick entirely in your own browser, and never sends any of it anywhere -- exactly like the rest of this tool. The CLI reads only local files, with no network call, ever.

Try it

node cli.mjs check AGENTS.md
node cli.mjs check CLAUDE.md --package package.json

Exits 1 if anything is found, so it works as a CI gate on the same PR that renames a file or a script. See why these files rot, and this checker's own named limits.
