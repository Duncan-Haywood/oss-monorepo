    Questions

    Why does my ! negation in .gitignore not work?

    Almost always because a folder above the file is ignored. Git does not look inside an ignored folder at all, so it never reads a rule about a file inside it. With build/ followed by !build/keep.txt, the folder build is ignored and keep.txt is never considered. Ignore the folder's contents instead, with build/* followed by !build/keep.txt, and re-open each deeper folder on the way down with a rule like !build/sub/.

    Which rule is ignoring my file?

    Git checks the rules from the last line up and the first one that matches decides. A .gitignore in a deeper folder is checked before the one above it, and .git/info/exclude and your global excludes file come last. The command git check-ignore -v path prints the deciding rule for one path; this tool does the same for every path in your list at once, and explains folder-by-folder when an ignored parent folder is the reason.

    Why is a file still showing up in git status after I added it to .gitignore?

    Because it is already tracked. Ignore rules only apply to files git is not tracking yet. Run git rm --cached on the file to stop tracking it while keeping it on disk, then commit. Paste your git ls-files output into the tracked box and the tool lists every tracked file your rules match.

    When does a .gitignore pattern match only at the top level?

    When it contains a slash anywhere except at the very end. docs/*.pdf matches only docs at the top of the folder the .gitignore lives in, while *.pdf or a pattern with only a trailing slash, like logs/, matches at any depth. To match a path with a slash at any depth, start it with **/, as in **/docs/*.pdf.

    What does ** mean in .gitignore?

    Two asterisks cross folders only when they fill a whole path segment: **/name matches name in any folder, name/** matches everything inside name, and a/**/b matches b at any depth below a, including directly inside it. Glued to other characters, as in src/**.js, the two asterisks act like one and stop at the next slash.

    Can I put a comment at the end of a .gitignore line?

    No. A line is a comment only when it starts with #. Anything after a pattern, including # and the words after it, becomes part of the pattern, so the rule stops matching what you meant. Trailing spaces are trimmed but tabs are not, and leading spaces count. The tool flags all of these.
