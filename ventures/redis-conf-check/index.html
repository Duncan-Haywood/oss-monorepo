REDIS.CONF CHECK · RUNS IN YOUR BROWSER

Will Redis start, and who can get in without a password?

Redis reads redis.conf top to bottom, and the last line for a setting wins, includes counted where their line stands. A # after a value is not a comment: requirepass s3cret # change me stops Redis from starting. And when the bad line is in an included file, Redis prints its line number without naming the file.

Paste redis.conf and the files it includes below. This page reads them the way Redis 7.0 does and shows whether Redis starts (with its own error and the real file and line), who can connect without a password from another machine, from 127.0.0.1 and over the socket, the line that set each value, and settings that let a client write files, load modules or run DEBUG.

Nothing is uploaded. What you paste is read in this browser and never leaves your device, and the tool makes no network calls. It is a static read of the files you give it, not a security audit and not a connection test against your server. Passwords are masked in the report.

1. Paste redis.conf and any included files

The first box is /etc/redis/redis.conf. Name other files by their path, absolute (/etc/redis/conf.d/10-app.conf) or relative to that directory (conf.d/10-app.conf). Relative include lines are read from the directory Redis starts in, which this page takes to be /etc/redis unless you set it below.

      What it checks

      Every line Redis 7.0 refuses, with its own message: unknown directives, a # after a value, unbalanced quotes and a closing quote followed by a letter, values out of range (databases 0), enum and yes/no typos, user lines with bad rules or a second definition, rename-command of a missing command or onto an existing name; includes that cannot be opened, wildcard includes that match nothing, and included files without a final newline (Redis glues their last line to the next file's first); then the start-up failures after the file loads: no listener (port 0, bind ""), bind addresses the machine lacks, tls-port without certificates, an aclfile beside user lines, unknown commands in user rules and module settings without loadmodule.

      Then who gets in: whether a client from another machine, from 127.0.0.1 or over the unix socket connects with no password, is turned away by protected mode, or must log in, after requirepass, user default lines and rename-command; whether such a client can CONFIG SET dir (enable-protected-configs), DEBUG or MODULE LOAD. And: a user default line that silently replaces requirepass, short or common passwords, cleartext passwords in the file, a plaintext port left open beside TLS, a world-writable socket, every interface bound, settings an earlier line set that a later one overrides, rename-command in place of ACL rules, and maxmemory 2g meaning 2,000,000,000 bytes.

      The reading follows Redis 7.0.15's config.c (with sds.c and acl.c) and the redis.conf documentation. It was compared with a real redis-server 7.0.15: 800 generated files, whether each started and with which error and line, CONFIG GET for every setting of the ones that started, and what unauthenticated clients got from another address, from 127.0.0.1 and over the socket (parity run).       Common questions

      Can I put a comment after a value in redis.conf?

      No. A # starts a comment only at the start of a line. In requirepass secret # change me the # and the words after it are extra arguments, so Redis refuses to start with wrong number of arguments. In a bind line they are read as more addresses.

      Which redis.conf line wins when a setting appears twice?

      The last one Redis reads. An include is read where its line stands, so a setting in a file included at the top is overridden by the same setting further down redis.conf, and a file included at the end overrides everything above it.

      Why does Redis say the error is at line 3 when line 3 of redis.conf is fine?

      The line number is counted in the file being read, which may be an included file, and the message does not name the file. For a wildcard include such as conf.d/*.conf, Redis joins the matching files into one text first, so the number counts across all of them.

      Is protected mode enough to keep Redis private?

      Protected mode refuses clients that are not on 127.0.0.1 or ::1 while the default user has no password. It is not authentication: it stops working the moment a password is set for some other reason or protected-mode is switched off, and it does nothing for local processes or a server-side request forgery that reaches 127.0.0.1. Use a long password or ACL users, and bind only the addresses clients need.

      Does a clean result mean my Redis is secure?

      No. It reads only the patterns listed on this page, from the files you paste. It does not see your firewall, which addresses are public, the ACL file unless you paste it, command-line options, or CONFIG SET changes made since start-up. Confirm on the server with CONFIG GET and ACL LIST, and have a qualified person review anything that protects valuable data.
