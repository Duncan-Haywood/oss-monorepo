GraphQL Introspection Exposure Checker vs. sending the query by hand

Pasting a short introspection query into curl, or into whatever GraphQL client is already open, is a real and fast way to confirm the single obvious case: does introspection answer at all. Most developers who suspect a problem reach for this first, and it genuinely works for that case. This page names no specific GraphQL client or IDE — the comparison is against the generic habit of crafting and sending the query yourself, not any one product.

When to still just send the query yourself

If you already suspect a specific endpoint is wide open and just want to confirm it once, a short hand-crafted query is fine — it's free and you already know the URL. The gap this tool closes is doing that completely: the full-schema query typed correctly every time, the mutation-surface and sensitive-name classification read off automatically instead of by eye, and an exit code the same check can gate a deploy on next time.

Common questions

What does sending an introspection query by hand actually show you?

Pasting a short query like { __schema { queryType { name } } } into curl or a GraphQL client is a real, fast way to confirm the single obvious case — whether introspection answers at all. Anyone who knows the endpoint URL can do this in one request, with no tooling beyond curl.

Where does the by-hand query fall short?

Three ways this scripted check catches and a hand-crafted query easily misses. (1) The short query that is easiest to paste by hand only proves introspection is on — it does not name the mutation surface or scan field names, so confirming the actual severity means either accepting an incomplete answer or typing out GraphQL's much longer full-schema introspection query by hand. (2) That full query is long enough, with nested fragments, that a single dropped brace or misspelled meta-field produces a GraphQL syntax error — which looks identical to introspection being disabled unless you read the error body closely enough to tell the two apart. (3) A real schema can name hundreds of fields; scanning that JSON by eye for a non-null mutationType or a sensitive-sounding name like admin, delete, or secret is slow and easy to get wrong at that size.

Why does this matter for CI, not just a one-time check?

A hand-crafted request is a point-in-time, manual look at one endpoint you remembered to try. A framework upgrade, a config change, or a new environment that reintroduces the default can turn introspection back on at any point after the last time someone thought to check. The CLI here returns a real exit code, so it can gate a deploy the same way a linter or test suite does — catching the regression the day it ships rather than the next time someone happens to run a query by hand.
