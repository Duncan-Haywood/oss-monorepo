How few stations can this line run on at takt?

Type each task, its time and the tasks that must come before it. Give the takt (or the demand and the shift time) and the page finds the fewest workstations, or give the number of stations and it finds the shortest cycle. It proves the answer optimal when it can, and says so when it cannot. Free, and it runs in your browser.

How it works, and how it did on Scholl's 269 benchmark lines

1. Tasks

One task per line: id, time, predecessors, description. Separate several predecessors with spaces. Only direct predecessors are needed. Any time unit works if you use the same one for the cycle time.

Also opens a CSV, a JSON task list or a Scholl .IN2 file.

2. What to find

Typing available time and demand fills the cycle time: available ÷ demand.

Questions

What is assembly line balancing?

Assigning the tasks of an assembly to workstations in order, so that no station's work exceeds the cycle time (takt) and every task comes after the tasks it depends on. Type 1 asks for the fewest stations at a given cycle time; type 2 asks for the shortest cycle time with a given number of stations.

How is the cycle time worked out from demand?

Takt time is the production time available in a period divided by the units needed in that period. 7.5 hours (27,000 seconds) for 450 units is a 60-second takt. The line has to finish a unit every cycle, so no station may hold more than that much work.

Is the answer optimal?

When the page says proved, yes: the search has shown no balance with fewer stations (or a shorter cycle) exists for the times and precedences typed. When the time limit runs out first, it shows the best balance found and the proved lower bound. On Scholl's 269 benchmark problems it matched the published optimum on 258 within four seconds each; the how-it-works page lists every result.

Is my line uploaded?

No. Every calculation runs in your browser. An optional anonymous counter in this browser's local storage records only that a balance ran and the day.
