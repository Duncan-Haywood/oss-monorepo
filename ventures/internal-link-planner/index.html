How it works

Each page is parsed for its title, headline, text and links. Links in the page body count fully; links in menus, headers, footers and sidebars count a quarter, and nofollow links count nothing. PageRank is computed over that graph. Suggestions are phrases already present in a source page that match a target page's headline or title (singular or plural), ranked by TF-IDF similarity, the source's own equity and phrase specificity. The plan is then applied to the graph and PageRank recomputed, so you see before and after.

Not modelled: JavaScript-rendered links, canonical tags pointing elsewhere, robots.txt, anchor-text relevance to a search engine, and real crawl budget. noindex pages are left out of the graph. Use the command line version (node cli.mjs https://your-site.com/sitemap.xml) to read a live site from its sitemap.

Usage counting is local to this browser and records only these events, never your pages: site_analyzed, example_loaded, report_downloaded.

Questions

What is an orphan page?

A page that no other page on the site links to. Visitors cannot navigate to it and search engines can only find it through a sitemap, so it gets little or no internal link equity.

How are the link suggestions chosen?

For each page that needs links, the tool looks for pages that already mention its title or headline words in their text but do not link to it. It ranks those by topical similarity (TF-IDF cosine), the source page's own link equity, and how specific the matched phrase is. The anchor text is the words already on the page.

Does it upload my site?

No. The page reads the files you choose in your browser and makes no network requests. The command line version only fetches the sitemap URL you give it.

Will the links improve my rankings?

Nobody can promise that. The tool reports how link equity inside your own site would move under a simplified PageRank model. Whether that changes rankings or traffic depends on much more than internal links.
