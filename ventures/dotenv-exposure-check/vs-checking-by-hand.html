When to still just look

If you only need a one-off sanity check on a URL you're already typing into the address bar, looking is fine — it's free and you're already there. The gap this tool closes is coverage and confidence: all five relevant filenames, not just the one you thought to try, each verified against the real file shape rather than eyeballed, every time a deploy happens, with an exit code a CI pipeline can act on.

Common questions

What does typing the URL into a browser tab actually show you?

Typing yoursite.com/.env into a browser tab is a fast, real check for the single obvious case: a plainly readable file full of KEY=VALUE lines. If that's what comes back, you don't need a tool to tell you it's exposed -- though you may not notice which of the lines is actually a live credential versus an innocuous setting.

Where does the by-hand check fall short?

Three ways this scripted check catches and a quick manual look easily misses: (1) a server that returns its normal 200 page (a single-page app's fallback route, a themed 404) for literally any path -- glancing at a response that looks like plausible text can be misread either way without checking its actual line shape. (2) Checking only the bare .env and not the four other common filenames (.env.local, .env.production, .env.production.local, .env.development.local) that frameworks like Next.js define and that often carry the developer's own real secrets rather than committed defaults. (3) A page full of variable names is easy to skim past without noticing which ones look like a real credential -- this tool names them explicitly by pattern (SECRET, TOKEN, PASSWORD, API_KEY, and similar) as a separate, higher severity.

Why does this matter for CI, not just a one-time check?

A manual check is a point-in-time look. A new deploy script, a server migration, or a CDN configuration change can reintroduce this exposure at any point after the last time someone happened to check. The CLI here returns a real exit code, so it can gate a deploy the same way a linter or test suite does -- catching a regression the day it ships rather than the next time someone thinks to check by hand.
