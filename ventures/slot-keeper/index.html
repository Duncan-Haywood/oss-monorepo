Let people book time with you, without a per-seat plan.

Slot Keeper is the open-source booking page for a consultant, coach, tutor, clinic or small studio. You set your hours once; visitors see free times in their own time zone, pick one, and both of you get a confirmation with a calendar file and a link to move or cancel. Below is the availability engine the server uses, running on your own hours. Everything on this page runs in your browser; nothing you type is uploaded.

Try the availability engine

Hours are wall-clock times in your zone, so they hold across daylight saving. Each bookable time keeps the buffer free on both sides. The server also blocks your existing bookings and re-checks the time the moment someone confirms.

Run it yourself

git clone https://github.com/Duncan-Haywood/oss-monorepo && cd oss-monorepo/ventures/slot-keeper
node --test
ADMIN_KEY=$(openssl rand -hex 16) HOST_TZ=America/New_York node server.mjs

Open http://localhost:8080/admin (any user name, ADMIN_KEY as the password), set your hours, add a meeting type and share /e/<meeting>. One-click Render deploy, Fly.io and Docker are in the README.

Questions

Why not just use Calendly, Cal.com or SavvyCal?

Those are polished and the right call if you need team round-robin, payments, CRM hooks or a mobile app. Calendly charges per seat for the features most people want (several event types, reminders, removing branding), and your invitees' details live on its servers. Cal.com is open source but is a large application with a database to run. Slot Keeper is one small Node server in your own account: unlimited meeting types and bookings, reminders, calendar-feed conflict blocking and an embed, with no per-seat fee. It covers one person or one small business with one calendar; if you need more, keep the hosted tool.

How does it avoid double-booking me?

Three ways. Every offered time is recomputed on the server at the moment someone confirms, so two visitors cannot take the same slot. Existing bookings block time including the buffer you set before and after. And if you paste your calendar's secret .ics address into the admin, events from Google Calendar, Outlook or Apple Calendar block those times too, including repeating events. The feed is read every five minutes, so a meeting you add in the last few minutes may not block yet.

Does it get time zones and daylight saving right?

It works in UTC internally and converts with the browser's own time zone database. Hours you set are wall-clock hours in your zone, so 09:00 stays 09:00 across a clock change; times that do not exist on the spring-forward night are skipped rather than shifted. Visitors see times in their own zone, detected from their browser and changeable on the page. The test suite includes the New York spring and autumn changes.

How are emails sent?

Through your own Resend account with your verified sending domain. It starts in dry-run mode: nothing is emailed until you set DRY_RUN=false with RESEND_API_KEY and MAIL_FROM. Invitees get a confirmation with an add-to-calendar file and a private link to move or cancel; you get a note for each booking, and a reminder goes to the invitee before the meeting. A Slack or Discord webhook can ping you as well.

Can I put it on my own website?

Yes. Each meeting type has a plain link and an iframe snippet in the admin. Set EMBED_ORIGINS to your site's address so browsers allow the frame. There is also a JSON endpoint, /api/slots/, if you want to build your own front end.

What does it store?

Meeting types, your hours, and for each booking the invitee's name, email address, notes and chosen time zone, in one JSON file you control. IP addresses are held in memory only for rate limiting. Set RETENTION_DAYS to delete old bookings. You run it, so you are responsible for your privacy notice and data-protection duties.
