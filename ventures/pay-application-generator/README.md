# Pay Application Generator

Free, private browser tool for subcontractors and small general contractors: paste a schedule of values with what was billed before and this period, set retainage, and get the contract sum, change orders, retainage held, previous certificates, current payment due and balance to finish, a line-by-line table, and a CSV. Flags lines billed over their value and front-loaded billing.

**Your Excel workbook, as it is (2026-11-25):** choose the .xlsx you already keep the continuation sheet in. `sheet.mjs` unzips it in the browser (the built-in `DecompressionStream`, no library, no upload), looks through each sheet for the table by its column names (a sheet named G703, continuation or schedule first), reads past the title block, two- or three-row headers and the row of column letters, skips division headings and subtotals, reads a "Change orders" section as change orders, and stops at the totals row. It then checks the sheet's own arithmetic rather than trusting it: a total completed and stored that no longer equals previous + this period + stored (a formula typed over), a balance to finish that is off, a totals row that differs from its lines (a line inserted outside the SUM range), and a retainage cell that disagrees with the rate entered. Formula results are rounded to the cent; a formula with no saved result is reported, never read as zero; an old .xls is asked for as .xlsx or CSV. A CSV saved from such a workbook, title block and all, is found the same way. Tested on fixtures written by openpyxl and by LibreOffice Calc (`fixtures/README.md`) as well as on workbooks the test builds. Also tested on the portfolio's own free schedule of values template (`pay-app-guides`). That test caught a bug fixed on 2026-11-25. The template has "Retainage on work, %" labels and an instruction row just above its header. When two candidate headers scored the same, the search took the deeper one, which glued those rows onto the Item column. Item numbers were then read as per-line retainage rates, and the CO-1 line was read as base contract. A tie now goes to the shallower header, and a row holding a sentence is never part of a header.

**Next month (2026-11-24):** roll an application forward. Previous becomes previous plus this period, this period goes to zero, stored materials stay stored, the application number goes up by one, the period end moves a month, and previous certificates become this application's total earned less retainage (line 6), so next month's payment due is exact instead of estimated. Start it on the page or download the CSV. Tests check that a rolled month with no new work is due exactly $0 and that three chained months pay out exactly the total earned less retainage (`calc.test.mjs`).

**Excel workbook and blank template (2026-11-25):** download the worked application as an `.xlsx` (`workbook.mjs`, no dependencies) with an application summary linked to a lettered continuation sheet, every total a formula, and ten spare rows the totals already cover; or download a blank 30-line template from the page. Cached values come from `compute()`, so a previewer that does not recalculate still shows the numbers, and LibreOffice's recalculation of the sample (with a reduced work rate, a line with its own rate and a deductive change order) matched `compute()` to the cent. Typed text is written as inline strings, so a description starting with `=` never becomes a formula. Tests: `workbook.test.mjs` (the formulas' text and cached values) and `recalc.test.mjs` (what they evaluate to: every cached value is stripped, LibreOffice recalculates, and lines 1 to 9 plus each line's retainage must equal `compute()` to the cent, read as raw values so a sub-cent error is not hidden by the cell format; three cases including different work and stored rates; skipped where `soffice` is missing, so run it locally after touching `workbook.mjs`). `pay-application-template.html` is the template's own page for the "pay application template excel" search: what each formula does and how to fill it in month by month.

**Retainage reduced only on later work (2026-11-25):** a contract that cuts retainage at a percent complete either re-rates everything billed (the default, which releases part of what was held) or keeps what was held and applies the reduced rate only to work completed past the point ("no further retainage after 50%" is a reduced rate of 0). Choose which under "The reduced rate applies to". In the second mode the first part of the contract sum keeps the full rate, and the amount past it is spread across the lines in proportion to their work billed, which is exact in total when there are no stored materials or per-line rates. The previous-certificates estimate uses the same split, and next month's application carries the mode. The Excel download writes the split as formulas, with the reduced rate in D6 and the point in F6. Tests: `calc.test.mjs` checks hand-worked totals and per-line shares; `recalc.test.mjs` checks that LibreOffice's recalculation matches to the cent, with stored materials, a line with its own rate and a reduction to 0. Both new test sets fail on the previous code.

It is the free front door for the pay-app suite in development (saved jobs, retainage until release, lien waivers, change orders; `docs/posts/2026-11-24-pay-applications-the-monthly-paperwork-subcontractors-pay-to-escape.md`). The page asks for early access through the site's public feedback form and quotes no price.
