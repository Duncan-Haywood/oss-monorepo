Common questions

Why does my GitHub Actions scheduled workflow run late or not at all?

GitHub documents that scheduled workflows can be delayed, and may be dropped, during periods of high load, and names the start of every hour as a high-load time. A cron of minute 0 lands on that peak; moving to an off-peak minute such as 17 is the documented mitigation.

What is the shortest interval a GitHub Actions cron can run at?

5 minutes. An entry such as * * * * * or */1 * * * * asks for more than GitHub supports, so it cannot run as often as written.

Why is my schedule cron rejected or ignored?

GitHub cron takes exactly five fields: minute, hour, day of month, month and day of week. A six-field cron with a seconds column, or a number outside a field's range such as minute 61, is invalid.

Does this tool fetch anything from GitHub for me?

No. It makes no network calls at all. Paste your workflow YAML and the scan runs entirely in this page.

Does a clean scan mean my workflows are safe?

No. This checks one specific pattern, the cron expressions, in each file you paste. It is not a security audit and it does not tell you when a run will actually start. Cron times are UTC.
