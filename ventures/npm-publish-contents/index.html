Questions

Why did npm publish a file that is in my .gitignore?

Because a .npmignore in the same folder replaces the .gitignore; npm reads one or the other, never both. The same happens at the package root when package.json has a files field: neither ignore file at the root is read. Copy the lines you still need into .npmignore, or list what should ship in files. The tool lists every file your .gitignore excludes that would now be published.

Which files does npm always include or always leave out?

Always included: package.json, and at the package root any README, LICENSE, LICENCE or COPYING file, plus the files named by main, browser and bin. Always left out: .git, the root node_modules, package-lock.json, yarn.lock, pnpm-lock.yaml and .npmrc, and by default .DS_Store, *.orig, npm-debug.log, editor swap files and the ignore files themselves. A node_modules folder below the root is not left out.

Why is my main file missing from the published package?

npm forces main into the package only when it is written without a leading ./ (for example dist/index.js, not ./dist/index.js). With the ./ the forcing rule never matches, so the file ships only if files or your ignore rules let it through. bin paths are cleaned first, so ./bin/cli.js works there. The tool reports both cases.

How do .npmignore patterns differ from .gitignore patterns?

npm matches with minimatch, not git's rules: case is ignored, a pattern without a slash matches the name at any depth, and leading and trailing spaces are trimmed. A rule like Docs also removes docs/ and lib/DOCS, even on a case-sensitive disk. The tool shows the file and line of the rule that decided each path.

How do I see what npm publish will upload before publishing?

Run npm pack --dry-run, which lists the files but not why. Paste that list, or your full file list, here to get the reason for each file, or run the command-line version in the package folder with --verify to compare its answer with npm pack's and --fail-on high to stop a CI job that would leak a secret.
