Write release notes once. Get a changelog page, feeds and a What's new button.

Draft an entry, publish it, and it appears on a public page, in an RSS and JSON feed, and in a small button you embed in your app that shows a red dot until the visitor has looked. It runs on your own server with the data in one file, so there are no tiers, no seat fees and no entry caps. Read the source or deploy it below.

The button your users would see sample data

These entries are invented to show the layout. Click the button: the dot goes away, and stays gone in your browser until a newer entry is published.

Run it yourself

git clone https://github.com/Duncan-Haywood/oss-monorepo && cd oss-monorepo/ventures/changelog-keeper
ADMIN_KEY=$(openssl rand -hex 16) PUBLIC_URL=https://changelog.example.com COMPANY_NAME=Acme node server.mjs

# write at /admin, read at /, feeds at /feed.xml and /feed.json
# embed:   <script src="https://changelog.example.com/embed.js" defer></script>

Questions

Is a draft visible to anyone?

No. Entries are drafts until you publish them. Drafts never appear on the page, the feeds or the embed.

Where does the data live?

In one JSON file on the server you deploy in your own account. The author runs nothing in between and never sees your users.

Can an entry hijack my site?

No. Entries are escaped before the small Markdown subset is applied, only http and https links are allowed, and the embed renders in a shadow root using textContent.

Can my users subscribe?

Yes, by RSS or JSON Feed at /feed.xml and /feed.json. There is no email subscription yet; pair it with Drip Keeper if you want to email announcements.

Does it support images or video?

Not yet. Entries are text with bullets, bold, code and links, which keeps the whole product small enough to read in an evening.
