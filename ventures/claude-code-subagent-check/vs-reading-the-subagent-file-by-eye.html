Where reading it yourself stops being enough

Anyone writing a subagent definition already does this: read the frontmatter and the prompt body and decide whether it looks right before trusting the orchestrator to pick it up. For a file with an obviously empty tools field, that read catches it. Common questions

Can't I just read the subagent file myself?

For a file with an obviously empty tools list or a missing description, yes -- that case is visible on a single read. What reading does not reliably catch is a description that reads as perfectly good prose to a person but carries no concrete trigger cue an orchestrator matches on, a tool name duplicated inside a long comma-separated list, a name that doesn't match its own filename, or an unrecognized model alias that looks like a real one. Those need the same fixed checks run against the frontmatter every time, not judged by eye.

Why is a description that reads fine but won't trigger delegation hard to catch by eye?

Because "this subagent handles code review" and "use PROACTIVELY when a PR is opened" are both grammatically fine, readable sentences -- the difference is whether the wording gives the orchestrator a concrete condition to match a request against, not whether it reads well. A person skimming the frontmatter judges the sentence as prose; this tool checks it for length, a trigger-cue pattern, and distinctive vocabulary, the same way for every subagent.

Why is a duplicate tool name in a long list easy to miss?

A tools field with a dozen comma-separated names is read left to right for the names that matter, not compared entry by entry against itself. A name repeated once in the middle of the list -- often from copying and editing a sibling subagent's frontmatter -- does not stand out visually the way a missing or malformed field does.

What about a name that doesn't match its own filename?

The frontmatter's name field and the file's own filename are two separate strings in two separate places -- one inside the YAML block, one in the file browser or path -- and nothing forces a reader comparing them from memory to notice a mismatch, especially after a rename. This tool checks the two strings against each other directly.
