Fix the Ollama CORS error

You point a web tool at http://localhost:11434 and it fails with a CORS error, a 403, or just "Failed to fetch", while curl from a terminal works fine. Ollama is running. It is refusing the web page.

Check your setup in one click

Why it happens

Ollama answers web pages only from origins it trusts. By default that is pages served from your own computer (localhost, 127.0.0.1) and a few app schemes. A page on any other site, including a tool you opened at an https address, is refused. A terminal request has no origin, which is why curl works.

The browser reports a refused origin the same way as a server that is not running, so the error alone does not tell you which you have. The connection check tells them apart.

The fix: allow the page's origin in OLLAMA_ORIGINS

The origin is the page's scheme and host with no path, for example https://duncan-haywood.github.io. Separate several with commas. Then restart Ollama: it reads the setting only at start.

macOS (the Ollama app)

launchctl setenv OLLAMA_ORIGINS "https://duncan-haywood.github.io"

Quit Ollama from the menu bar and open it again. launchctl setenv lasts until you log out; to keep it, run it again after logging in or set it in a login item.

Linux (systemd service)

sudo systemctl edit ollama.service

Add these lines in the editor and save:

[Service]
Environment="OLLAMA_ORIGINS=https://duncan-haywood.github.io"
sudo systemctl daemon-reload && sudo systemctl restart ollama

Windows

setx OLLAMA_ORIGINS "https://duncan-haywood.github.io"

Quit Ollama from the system tray and start it again, so it picks up the new variable.

Any system, from a terminal

OLLAMA_ORIGINS="https://duncan-haywood.github.io" ollama serve

Only allow sites you trust

An allowed origin can use your model, and see what it answers, whenever Ollama is running. Allow the specific sites you use. Avoid *, which lets every site you visit do the same, and especially on a machine where Ollama listens on the network (OLLAMA_HOST=0.0.0.0).

Still failing after the fix?

  • Chrome asked about "local network access" and you dismissed it. Recent Chrome versions ask before a public site can reach your computer. Allow it in the site settings (the icon left of the address bar).
  • The model runs on another machine. An https page cannot call a plain-http address on your network (mixed content), whatever Ollama allows. Use the tool on the machine with the model, put Ollama behind https, or forward the port: ssh -N -L 11434:localhost:11434 you@that-machine.
  • It is LM Studio, not Ollama. Turn on "Enable CORS" in the Developer tab's server settings, or start it with lms server start --cors.
  • No model yet. ollama pull llama3.2, then check again.
