Actions Injection Check vs. zizmor

They overlap on two specific findings and differ in everything else. zizmor is an open-source CLI that audits an entire GitHub Actions repository across dozens of issue categories, pwn requests and script injection among them. This page runs only those two checks, on one pasted workflow file, free, in your browser, with nothing to install and no repository checkout.

What each tool is for

zizmor is an open-source static-analysis tool for GitHub Actions and GitLab CI workflows. Per its own documentation, it runs a broad set of audits against every workflow file in a repository you point it at -- among them dangerous-triggers (the pull_request_target / workflow_run pwn-request pattern this checker also flags), template-injection (the untrusted-expression-in-a-shell pattern this checker calls script injection), excessive permissions, unpinned actions, and cache/artifact-poisoning risk. It installs as a CLI via pip, pipx, cargo, or Homebrew, and ships an official GitHub Action and a pre-commit hook for running it continuously in CI. It is free and open source, with no account or paid tier documented for the tool itself.

This checker does only the two things in its name. You paste the YAML of one workflow file, and it lists every pull_request_target/workflow_run checkout of an untrusted ref, and every run: step that interpolates an untrusted ${{ github.event.* }} expression -- file, line, and the exact fix. It runs entirely in your browser, needs no install and no repository checkout, and makes no network call of its own, so it works the same on a pull-request diff, a gist, or a private repository you have not cloned anywhere.

Common questions

Should I use this checker or zizmor?

They overlap on two specific findings and differ everywhere else. zizmor is an open-source static-analysis CLI for GitHub Actions (and GitLab CI) workflows: point it at a repository checkout and, per its own documentation, it runs a broad set of audits covering far more than injection risk -- excessive permissions, unpinned actions, cache and artifact poisoning, and known-vulnerable actions are among the categories it documents, alongside the dangerous-trigger (pwn request) and template-injection (script injection) checks this page compares against. It installs via pip, pipx, cargo, or Homebrew, and ships a GitHub Action and a pre-commit hook for wiring it into CI. This checker does only the two things in its name -- pwn-request checkouts and shell script injection -- on the one workflow file you paste, entirely in your browser, with nothing to install and no repository checkout required. If you want one CLI that audits an entire repository across many workflow-security categories, zizmor is built for that. If you want a fast, no-install, no-checkout answer to these two specific and well-documented patterns for a single file, this is the narrower tool for that.

Does zizmor check for the same things this tool does?

Two of its many audits overlap with this page: zizmor documents a dangerous-triggers audit for the pull_request_target/workflow_run pwn-request pattern, and a template-injection audit for untrusted expressions spliced into a run: step, which is the same underlying issue this tool calls script injection. Where they differ is scope and shape: zizmor runs those checks as part of a much larger audit set against every workflow file in a repository you have checked out, and reports its own finding format from the CLI or its GitHub Action. This tool checks only those two patterns, on whatever YAML you paste, with no checkout and no other audits attempted.

Why use a two-pattern browser tool when zizmor already covers more ground?

Three reasons this tool exists alongside it. First, zizmor is a CLI you install and run against a repository on disk; this tool is a page you open and paste one file into, with nothing to set up. Second, that makes this tool usable on a single workflow file pulled from anywhere -- a pull request diff, a gist, a private repository you are not set up to check out locally -- without cloning anything. Third, this checker makes no network calls of its own and nothing you paste is uploaded, which matters when the file itself is the sensitive part. Neither reason makes this tool a substitute for the other audits zizmor runs; a repository that wants comprehensive workflow-security coverage should run zizmor, not stop at these two checks.
