Which of your Peppol invoices will be rejected in February?

Access points must apply Peppol BIS Billing 3.1.0 from 24 February 2027. It adds 130 rules to the UBL set and tightens others, so a file that your access point accepts today can bounce then. Drop a batch of invoices you have sent (UBL or CII XML, or a whole folder) and each one is checked against both releases: the files that pass 3.0.22 now and fail 3.1.0 are the ones to fix, and the rules they break are listed with what to change.

Free, no account, and the files stay on your machine: the rules come with this page and run in your browser.

What changes in 3.1.0

Every rule that 3.1.0 adds, removes, raises from warning to fatal, or whose test changes, compared rule by rule between the compiled 3.0.22 and 3.1.0 sets this page runs (wording-only edits such as "should" to "SHOULD" are left out). The short version:

  • Scheme 0088 is GLN-only (PEPPOL-COMMON-R040): exactly 13 digits with a valid GS1 check digit. 3.0.22 took any length that passed the check digit.
  • Dutch identifiers become rejections (R054, R055, R056-1, R056-2, R057): KVK, OIN, Dutch VAT and establishment numbers in the wrong format were warnings.
  • Belgian and Luxembourg numbers: a Belgian enterprise number (0208) must start with 0 or 1 (R043); new warnings check Belgian VAT (R062), Luxembourg VAT (R058) and the Luxembourg Matricule, scheme 0240 (R059).
  • "Exactly one" rules for UBL (PEPPOL-EN16931-R141 to R276): each element that may occur once under its parent must occur exactly once, so a repeated element that 3.0.22 let through is now fatal.
  • National rules: German BT-124 URLs (DE-R-T02) and Danish UNSPSC versions in CII (DK-R-003) become fatal; Danish buyers' CVR scheme in CII (DK-R-017) and Slovak address rules (SK-R-001 to SK-R-007) are new; Norwegian and Swedish VAT checks in CII now look for scheme code VA, so they fire for the first time.

Common questions

When does Peppol BIS Billing 3.1.0 apply?

OpenPeppol's release notes for 3.1.0 (branch 2026-Q4-QA2 of OpenPEPPOL/peppol-bis-invoice-3) give 23 November 2026 for publication and 24 February 2027 as the date access points must apply it. From that day a file that passes 3.0.22 can be rejected. On 24 November 2026 the release was not yet tagged on OpenPeppol's GitHub, so the rules here are compiled from that release-candidate branch at commit 90f078a; they pass all 1,138 of OpenPeppol's own unit-test asserts. They will be rebuilt from the tag when it appears.

Are my invoices uploaded?

No. The rules are downloaded with the page and every file is checked in your browser. Nothing you drop leaves your machine.

What breaks most often?

On OpenPeppol's own published examples, five of seventeen files that passed 3.0.22 failed 3.1.0, all on PEPPOL-COMMON-R040: scheme 0088 now takes a 13-digit GLN only. Your files may break on other rules; the check lists them.

Can I check thousands of files at once?

The same check runs from a terminal on a folder of any size and writes a CSV: node peppol-readiness-cli.mjs ./sent-invoices --csv readiness.csv (all rights reserved, in the source). To check a single file against every rule, not only what changes, use the full checker.
