## What the three schema versions say

| Package | Published | tpAutor | Item group |
|---|---|---|---|
| v1.20 | 2025-08-18 | 1 only | `gCredPres`: `vBC`, `gIBS` and `gCBS`, each with its own `cCredPres` |
| v1.30 | 2025-10-07 | 2 only | same as v1.20 |
| v1.40 | 2026-07-27 | 1 or 2 | `gCredPresOper`: `vBCCredPres`, one `cCredPres`, `gIBSCredPres`, `gCBSCredPres` |

`nfephp-org/sped-nfe` master ships the v1.20 file in `schemes/PL_010g`, `PL_010_V1.30`
and `PL_010_V1` (all three byte-identical), so a library validating against it accepts
only tpAutor 1, which the v1.30 package then banned. Unimake's Uninfe example
(`Evento_211110-ped-eve.xml`) is in the v1.20/v1.30 layout with tpAutor 2 (v1.30's).

needs xmllint): 199 single changes to `fixtures/nfe-event-211110.xml` inside `detEvento`
(each element dropped, doubled, swapped with its next sibling, 15 bad values in each leaf,
seven `nItem` values, three `versao` values, a repeated and a second item, the old layout).

```
mutants: 199, agree: 199, disagree: 0
```

The first run disagreed on 3 (leading spaces in `verAplic` and `cCredPres`): the checker
trimmed values before matching, but these are `xs:string` types with whitespace preserved.
Fixed by matching the raw text, and `verAplic` now gets the TString pattern too.
