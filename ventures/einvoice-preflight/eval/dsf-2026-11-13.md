## The Assinatura

Formula from OpenAC's `ProviderISSDSF.GerarCampos` and the schema's own documentation of
`tpAssinatura`: IM (11, zeros left) + SerieRPS (5, spaces right) + NumeroRPS (12, zeros left) +
date yyyyMMdd + Tributacao (2, space right) + SituacaoRPS + (TipoRecolhimento R ? "S" : "N") +
(services - deductions) in cents (15) + deductions in cents (15) + CodigoAtividade (10) +
CPFCNPJTomador (14); SHA-1, lower-case hex. Services = sum of the items' ValorTotal.

55 signed RPS: 47 reproduce with ValorDeduzir as the deduction. Series padded on the left
reproduces none that the right-padded form does not; signing the gross instead of the net
loses `EnvioAssinado01` RPS 106 (12,000.12 less 5.00). One more, `EnvioAssinado02` RPS 2
(the same RPS appears in `EnvioNaoAssinado02`), has `DeducaoPor` Percentual, 10%, and
`ValorDeduzir` 0.00: it reproduces with the deduction taken as 10% of 180.00 = 18.00
(`fe694570...`), and the header's ValorTotalDeducoes is 18.00 too. With that rule, **49 of 55**.
The 6 that do not reproduce: two `ag1fd51g56fsd15h...` placeholders (not hex) in Uninfe's
sample, two in carloslopes/nfse's `test/fixtures/campinas/envio.xml` (copied from a DSF sample,
values and header edited after: its header says 11.00 of services for RPS worth 26.00), and
two in Unimake/DFe's test file (registration 00000000000; no variant tried matches).

## The schema layer against xmllint (libxml 2.9.14)

```
node eval/dsf-xsd-diff.mjs <OpenAC>/src/OpenAC.Net.NFSe/Schemas/ISSDSF --per 120 <21 files> fixtures/dsf-lote-rps.xml <its 1.01 variant>
{"verdicts":{"files":23,"bothValid":19,"bothInvalid":4,"onlyXmllint":0,"onlyUs":0},"byRoot":{"ReqEnvioLoteRPS":18,"RetornoConsultaLote":1,"RetornoConsultaNFSeRPS":2,"RetornoConsultaNotas":2}}

```

What the comparison made the shared checker learn (each disagreement was this tool's error):

1. `xs:union` (13 "value or empty" types in Tipos.xsd, e.g. `tpCEPNulo = tpCEP | nulo`): valid
   when a member accepts it. libxml2 collapses the value first: a space before a dateTime in
   `tpDataHoraNulo` passes, though a bare dateTime with a space fails.
2. Element `default`: `<transacao></transacao>` (xs:boolean, default "true") is valid.
3. `xs:boolean` values (true/false/1/0) and `xs:base64Binary` values were not checked.
4. Text inside an element-only type (`<Deducoes>x</Deducoes>`) was not reported.
5. The libxml2 space rule, remeasured on one-step restrictions of each built-in type:

| base | bare | pattern | enumeration | range | whiteSpace collapse |
|---|---|---|---|---|---|
| byte, unsignedByte, short, int, long, unsignedInt | refused | ok | ok | refused | refused |
| date, dateTime | refused | ok | ok | - | refused |
| integer, nonNegativeInteger, positiveInteger, decimal | ok | ok | ok | ok | ok |
| boolean | ok | ok | refused | - | ok |

   (" 12" and "12 " alike.) The checker had exempted `xs:byte` on an older note; that was wrong.
   The boolean-with-enumeration case is not modelled (no schema read here has one).

After the fixes, ABRASF's differential on this repo's fixtures with every provider copy
(`eval/abrasf-xsd-diff.mjs <dir> --per 300 --providers <Schemas> --retarget 3543402,3509502,4205407`)
still agrees: 15 of 15 verdicts, 3,499 of 3,499 mutants.

## What the published files show

- DSF's own `EnvioNaoAssinado01` holds two RPS with series NF and number 109 (different values,
  both correctly signed). The checker notes a repeated number; it is not called an error.
- `retorno_consultanotas...` (a 2010 reply from Campinas's server, 156 KB) has four
  `ValorCSLL`/`ValorPIS` values its own published pattern refuses: `0.3`, `0.5` (twice), `0.9`.
  The pattern `0|0\.[0-9]{2}|[1-9][0-9]{0,12}(\.[0-9]{0,2})?` wants two decimals below 1 but
  allows one above it. xmllint agrees; the server wrote what its schema forbids.
- carloslopes/nfse's fixture writes `CidadeTomador` 00062910 (eight digits; Campinas is 6291).

Not done: a real city rejection, the batch ds:Signature, IPM 1.0x (OpenAC's folder holds only a
note that IPM published no schema), SimplISS 1.00, DBSeller 1.00.
