E-invoice rule explained · EN 16931

BR-49: Payment instructions have no payment means code

DeutschFrançaisAll rules

Official message

A Payment instruction (BG-16) shall specify the Payment means type code (BT-81).
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BG-16, BT-81

What does BR-49 mean?

Every payment instructions block (BG-16) in the invoice must state the payment means type code (BT-81) from the UNCL 4461 list, for example 58 for SEPA credit transfer, 59 for SEPA direct debit or 30 for credit transfer.

Usual causes

  • Bank details or a payment reference were written, but the code saying how to pay was left out.
  • The payment method was given only as text ("Bank transfer") and not as a code.
  • An empty PaymentMeans block (CII: ram:SpecifiedTradeSettlementPaymentMeans) was generated for a payment method that is not used.

How do I fix BR-49?

  1. Decide which payment method the block describes and add its UNCL 4461 code: cbc:PaymentMeansCode in UBL, ram:TypeCode in CII.
  2. Put the code first in the block, before the payment reference and account details.
  3. Remove payment instruction blocks you do not need instead of leaving them without a code.

Corrected XML (minimal example we wrote)

UBL

<cac:PaymentMeans>
  <cbc:PaymentMeansCode>58</cbc:PaymentMeansCode>
  <cbc:PaymentID>INV-2026-001</cbc:PaymentID>
  <cac:PayeeFinancialAccount>
    <cbc:ID>DE02120300000000202051</cbc:ID>
  </cac:PayeeFinancialAccount>
</cac:PaymentMeans>

CII

<ram:SpecifiedTradeSettlementPaymentMeans>
  <ram:TypeCode>58</ram:TypeCode>
  <ram:PayeePartyCreditorFinancialAccount>
    <ram:IBANID>DE02120300000000202051</ram:IBANID>
  </ram:PayeePartyCreditorFinancialAccount>
</ram:SpecifiedTradeSettlementPaymentMeans>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
