E-invoice rule explained · XRechnung

BR-DE-22: Two embedded attachments have the same file name

DeutschFrançaisAll rules

Official message

Das "filename"-Attribut aller "EmbeddedDocumentBinaryObject"-Elemente muss eindeutig sein
Not all filename attributes of the embeddedDocumentBinaryObject elements are unique
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BT-125

What does BR-DE-22 mean?

Every attachment embedded in the invoice (BT-125) must have a different file name in its filename attribute. The comparison is exact, so report.pdf and Report.pdf count as different, but two report.pdf do not.

Usual causes

  • The software names every attachment the same way, for example attachment.pdf or Anlage.pdf.
  • The same document was attached twice.
  • Files with the same name from different folders were attached, and the folder part was dropped.

How do I fix BR-DE-22?

  1. Give each attachment a distinct file name, for example timesheet-2026-10.pdf and delivery-note-4711.pdf.
  2. Remove an attachment that is an exact duplicate of another.
  3. Check the filename attribute of every cbc:EmbeddedDocumentBinaryObject (UBL) or ram:AttachmentBinaryObject (CII) after export.

Corrected XML (minimal example we wrote)

UBL

<cac:AdditionalDocumentReference>  <cbc:ID>ANL-1</cbc:ID>  <cac:Attachment>    <cbc:EmbeddedDocumentBinaryObject mimeCode="application/pdf" filename="stundenzettel-2026-10.pdf">JVBERi0xLjQK</cbc:EmbeddedDocumentBinaryObject>  </cac:Attachment></cac:AdditionalDocumentReference><cac:AdditionalDocumentReference>  <cbc:ID>ANL-2</cbc:ID>  <cac:Attachment>    <cbc:EmbeddedDocumentBinaryObject mimeCode="application/pdf" filename="lieferschein-4711.pdf">JVBERi0xLjQK</cbc:EmbeddedDocumentBinaryObject>  </cac:Attachment></cac:AdditionalDocumentReference>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
