E-invoice rule explained · EN 16931

BR-CO-09: VAT identifier does not start with a valid country code

DeutschFrançaisAll rules

Official message

The Seller VAT identifier (BT-31), the Seller tax representative VAT identifier (BT-63) and the Buyer VAT identifier (BT-48) shall have a prefix in accordance with ISO code ISO 3166-1 alpha-2 by which the country of issue may be identified. Nevertheless, Greece may use the prefix ‘EL’.
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BT-31, BT-63, BT-48

What does BR-CO-09 mean?

Every VAT identifier on the invoice (seller BT-31, seller's tax representative BT-63, buyer BT-48) must start with a two-letter country code in capitals from the rule's list, for example DE123456789. Surprisingly, the list in the current official rules contains GR but not EL, so a Greek VAT number written with EL fails here even though the message says EL is allowed (the older 1.3.8 rules still accepted EL).

Usual causes

  • The number was entered without its country prefix, for example 123456789.
  • The prefix is in lower case (de123456789) or preceded by a space.
  • A national tax number (Steuernummer, SIREN) was put in a VAT identifier field: in UBL a PartyTaxScheme with tax scheme VAT, in CII a SpecifiedTaxRegistration with schemeID VA.
  • A Greek VAT number uses the prefix EL.

How do I fix BR-CO-09?

  1. Write each VAT identifier with its two-letter country prefix in capitals and no leading space, as it appears on the VAT registration.
  2. Put a national tax number that is not a VAT identifier in its own field (in UBL a PartyTaxScheme with a scheme other than VAT, in CII schemeID FC), not in the VAT one.
  3. For a Greek EL number, check with the receiver which version of the rules they validate against before changing anything.

Corrected XML (minimal example we wrote)

UBL

<cac:PartyTaxScheme>  <cbc:CompanyID>DE123456789</cbc:CompanyID>  <cac:TaxScheme>    <cbc:ID>VAT</cbc:ID>  </cac:TaxScheme></cac:PartyTaxScheme>

CII

<ram:SpecifiedTaxRegistration>  <ram:ID schemeID="VA">DE123456789</ram:ID></ram:SpecifiedTaxRegistration>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
