E-invoice rule explained · EN 16931

BR-CL-14: Country code is not an ISO 3166-1 code

DeutschFrançaisAll rules

Official message

Country codes in an invoice MUST be coded using ISO code list 3166-1
Severity
Error (the invoice is rejected)
Checked in
UBL, CII

What does BR-CL-14 mean?

Every country code in the invoice (seller, buyer, delivery and other addresses, and the item's country of origin) must be a two-letter ISO 3166-1 alpha-2 code in capital letters, such as DE, FR or AT. The list also accepts XI for Northern Ireland and 1A for Kosovo.

Usual causes

  • A country name ("Germany", "Deutschland") or a three-letter code (DEU) was written instead of the two-letter code.
  • The code is in lower case (de) or contains a space.
  • A VAT prefix was used as a country code: EL for Greece (the country code is GR) or UK for the United Kingdom (the country code is GB).

How do I fix BR-CL-14?

  1. Look up the two-letter ISO 3166-1 code of each country on the invoice.
  2. Write it in capitals with no spaces in every country field: cbc:IdentificationCode in UBL, ram:CountryID in CII.
  3. Fix the master data in your customer and supplier records so the next invoice is right too.

Corrected XML (minimal example we wrote)

UBL

<cac:PostalAddress>
  <cbc:StreetName>Musterstraße 1</cbc:StreetName>
  <cbc:CityName>Berlin</cbc:CityName>
  <cbc:PostalZone>10115</cbc:PostalZone>
  <cac:Country>
    <cbc:IdentificationCode>DE</cbc:IdentificationCode>
  </cac:Country>
</cac:PostalAddress>

CII

<ram:PostalTradeAddress>
  <ram:PostcodeCode>10115</ram:PostcodeCode>
  <ram:LineOne>Musterstraße 1</ram:LineOne>
  <ram:CityName>Berlin</ram:CityName>
  <ram:CountryID>DE</ram:CountryID>
</ram:PostalTradeAddress>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
