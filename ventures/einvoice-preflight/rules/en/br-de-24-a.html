BR-DE-24-a: Card payment without payment card information

DeutschFrançaisAll rules

Official message

Wenn BT-81 "Payment means type code" einen Schlüssel für Kartenzahlungen enthält (48, 54, 55), muss genau BG-18 "PAYMENT CARD INFORMATION" übermittelt werden.
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BT-81, BG-18

What does BR-DE-24-a mean?

When a payment means uses a card payment code (48, 54 or 55 in BT-81), it must carry the payment card group (BG-18) with the card details. The official message says exactly one, but the test only checks that the group is there.

Usual causes

  • A card code was chosen but no card details were exported.
  • The card details are only in a free-text note.
  • Code 48 was used for a payment that is actually a transfer or direct debit.

How do I fix BR-DE-24-a?

  1. Add cac:CardAccount inside the same cac:PaymentMeans (UBL) or ram:ApplicableTradeSettlementFinancialCard (CII).
  2. Give only the last four to six digits of the card number, never the full number, plus the card network and, if known, the holder's name.
  3. If the payment is not by card, use the code that matches the real payment method.

Corrected XML (minimal example we wrote)

UBL

<cac:PaymentMeans>  <cbc:PaymentMeansCode>54</cbc:PaymentMeansCode>  <cac:CardAccount>    <cbc:PrimaryAccountNumberID>1234</cbc:PrimaryAccountNumberID>    <cbc:NetworkID>VISA</cbc:NetworkID>    <cbc:HolderName>Erika Mustermann</cbc:HolderName>  </cac:CardAccount></cac:PaymentMeans>

CII

<ram:SpecifiedTradeSettlementPaymentMeans>  <ram:TypeCode>54</ram:TypeCode>  <ram:ApplicableTradeSettlementFinancialCard>    <ram:ID>1234</ram:ID>    <ram:CardholderName>Erika Mustermann</ram:CardholderName>  </ram:ApplicableTradeSettlementFinancialCard></ram:SpecifiedTradeSettlementPaymentMeans>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
