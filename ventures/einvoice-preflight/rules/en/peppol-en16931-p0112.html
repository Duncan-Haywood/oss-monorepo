PEPPOL-EN16931-P0112: Invoice type code 326, 384 or 389 used outside the allowed countries

DeutschFrançaisAll rules

Official message

Invoice type codes 326 and 389 are only allowed when both buyer and seller are German organizations. Invoice type code 384 is only allowed when both buyer and seller are German organizations or both are Slovak organizations.
Severity
Error (the invoice is rejected)
Checked in
UBL
Business terms
BT-3

What does PEPPOL-EN16931-P0112 mean?

The Invoice type codes 326 (partial invoice), 384 (corrected invoice) and 389 (self-billed invoice) are only allowed on Peppol when both seller and buyer are German, judged by the country code in their postal addresses. Code 384 is also allowed when both are Slovak; for that check the country is taken from the VAT number prefix (for the seller, else from the tax representative's VAT number), falling back to the postal address. Other invoices should use a code such as 380.

Usual causes

  • The software uses 326, 384 or 389 for all customers, including foreign ones.
  • Seller and buyer are both German, but a postal address country code is missing or not DE.
  • A corrected invoice (384) was sent between parties in countries other than Germany or Slovakia.

How do I fix PEPPOL-EN16931-P0112?

  1. Check the postal address country codes (cac:Country/cbc:IdentificationCode) of seller and buyer; for two German parties both must be DE.
  2. Otherwise use the commercial invoice code 380 in cbc:InvoiceTypeCode; to correct an invoice, issue a credit note and a new invoice instead of a 384.
  3. If the transaction is self-billing or a partial invoice, ask your Peppol provider how your receiver expects it to be marked.

Corrected XML (minimal example we wrote)

UBL

<cbc:InvoiceTypeCode>380</cbc:InvoiceTypeCode>
