E-invoice rule explained · Peppol BIS

PEPPOL-EN16931-R121: Price base quantity is zero or negative

DeutschFrançaisAll rules

Official message

Base quantity MUST be a positive number above zero.
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BT-149

What does PEPPOL-EN16931-R121 mean?

If a line's price gives a base quantity (BT-149, the number of units the price is for), it must be greater than zero. Leaving it out is fine: it then counts as 1. In CII the rule checks the base quantity of both the net and the gross price.

Usual causes

  • The software writes a base quantity of 0 when no price unit is set.
  • On a credit note or return line the minus sign was put on the base quantity instead of the quantity.
  • A blank field was exported as 0.

How do I fix PEPPOL-EN16931-R121?

  1. Set cbc:BaseQuantity (UBL) or ram:BasisQuantity (CII) to the number of units the price is for, usually 1.
  2. Keep negative signs on the quantity or amount, never on the base quantity.
  3. If the price is simply per unit, you can remove the base quantity altogether.

Corrected XML (minimal example we wrote)

UBL

<cac:Price>  <cbc:PriceAmount currencyID="EUR">25.00</cbc:PriceAmount>  <cbc:BaseQuantity unitCode="C62">1</cbc:BaseQuantity></cac:Price>

CII

<ram:NetPriceProductTradePrice>  <ram:ChargeAmount>25.00</ram:ChargeAmount>  <ram:BasisQuantity unitCode="C62">1</ram:BasisQuantity></ram:NetPriceProductTradePrice>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
