E-invoice rule explained · XRechnung

BR-DE-30: Direct debit without the creditor identifier

DeutschFrançaisAll rules

Official message

Wenn "DIRECT DEBIT" BG-19 vorhanden ist, dann muss "Bank assigned creditor identifier" BT-90 übermittelt werden.
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BG-19, BT-90

What does BR-DE-30 mean?

When the invoice contains direct debit information (BG-19), it must give the bank-assigned creditor identifier (BT-90), the SEPA creditor ID (Gläubiger-Identifikationsnummer) under which you collect. In UBL it is a party identifier with schemeID="SEPA" on the seller or the payee; in CII it is ram:CreditorReferenceID.

Usual causes

  • The creditor ID is set up in the banking software but not in the invoicing software.
  • In UBL the creditor ID was given without schemeID="SEPA", or with another scheme, so the test does not find it.
  • The creditor ID was written only in a note or the payment terms text.

How do I fix BR-DE-30?

  1. Find your creditor ID (in Germany it starts with DE and contains ZZZ, for example DE98ZZZ09999999999); in Germany the Deutsche Bundesbank issues it.
  2. In UBL add cac:PartyIdentification/cbc:ID with schemeID="SEPA" to the seller party (or to cac:PayeeParty if a separate payee collects).
  3. In CII put it in ram:CreditorReferenceID at the start of ram:ApplicableHeaderTradeSettlement.

Corrected XML (minimal example we wrote)

UBL

<cac:AccountingSupplierParty>
  <cac:Party>
    <cac:PartyIdentification>
      <cbc:ID schemeID="SEPA">DE98ZZZ09999999999</cbc:ID>
    </cac:PartyIdentification>
    <cac:PartyName>
      <cbc:Name>Beispiel GmbH</cbc:Name>
    </cac:PartyName>
  </cac:Party>
</cac:AccountingSupplierParty>

CII

<ram:ApplicableHeaderTradeSettlement>
  <ram:CreditorReferenceID>DE98ZZZ09999999999</ram:CreditorReferenceID>
  <ram:InvoiceCurrencyCode>EUR</ram:InvoiceCurrencyCode>
</ram:ApplicableHeaderTradeSettlement>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
