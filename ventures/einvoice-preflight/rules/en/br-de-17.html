BR-DE-17: Invoice type code is not one XRechnung expects

DeutschFrançaisAll rules

Official message

Mit dem Element "Invoice type code" (BT-3) sollen ausschließlich folgende Codes aus der Codeliste UNTDID 1001 übermittelt werden: 326 (Partial invoice), 380 (Commercial invoice), 384 (Corrected invoice), 389 (Self-billed invoice) und 381 (Credit note),875 (Partial construction invoice), 876 (Partial final construction invoice), 877 (Final construction invoice).
Severity
Warning (should be fixed; not a rejection on its own)
Checked in
UBL, CII
Business terms
BT-3

What does BR-DE-17 mean?

XRechnung expects the invoice type code (BT-3) to be one of 326 (partial invoice), 380 (commercial invoice), 384 (corrected invoice), 389 (self-billed invoice), 381 (credit note), 875, 876 or 877 (partial, partial final and final construction invoices). This is a warning, not an error: the file is still valid, but a receiving platform may handle other codes differently or reject them.

Usual causes

  • The software uses another UNTDID 1001 code, such as 386 (prepayment invoice), 383 (debit note) or 393 (factored invoice).
  • A credit note was sent with a credit-note code other than 381.
  • A proprietary or old document type number was mapped straight into BT-3.

How do I fix BR-DE-17?

  1. Use 380 for a normal invoice and 381 for a credit note; use 326, 384, 389 or 875 to 877 only when the document really is that type.
  2. Set the code in cbc:InvoiceTypeCode (or cbc:CreditNoteTypeCode in a UBL credit note) or ram:TypeCode inside rsm:ExchangedDocument (CII).
  3. If you need a different code for a specific buyer, check with that buyer that they accept it.

Corrected XML (minimal example we wrote)

UBL

<cbc:InvoiceTypeCode>380</cbc:InvoiceTypeCode>

CII

<rsm:ExchangedDocument>  <ram:ID>RE-2026-0042</ram:ID>  <ram:TypeCode>380</ram:TypeCode>  <ram:IssueDateTime>    <udt:DateTimeString format="102">20261124</udt:DateTimeString>  </ram:IssueDateTime></rsm:ExchangedDocument>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
