E-invoice rule explained · EN 16931

BR-63: Buyer electronic address has no scheme identifier

DeutschFrançaisAll rules

Official message

The Buyer electronic address (BT-49) shall have a Scheme identifier.
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BT-49

What does BR-63 mean?

If the invoice gives the buyer's electronic address (BT-49), it must say what kind of address it is with a scheme identifier (the schemeID attribute), taken from the EAS code list, for example EM for an email address or 0088 for a GLN. In CII only the first electronic address of the buyer is checked.

Usual causes

  • The address was written without the schemeID attribute, often because the software only stores the bare value.
  • The scheme was written in another attribute or as a prefix in the value (for example "0088:4000001000005").
  • The schemeID attribute is present but empty.

How do I fix BR-63?

  1. Find out which kind of address you are giving: the address the buyer told you to send to, for example a Leitweg-ID (0204), an email address (EM) or a GLN (0088).
  2. Add the matching EAS code as schemeID on cbc:EndpointID in cac:AccountingCustomerParty (CII: on ram:URIID in ram:URIUniversalCommunication).
  3. Keep only the identifier itself in the value, without any prefix.

Corrected XML (minimal example we wrote)

UBL

<cac:AccountingCustomerParty>
  <cac:Party>
    <cbc:EndpointID schemeID="0204">04011000-12345-34</cbc:EndpointID>
  </cac:Party>
</cac:AccountingCustomerParty>

CII

<ram:BuyerTradeParty>
  <ram:URIUniversalCommunication>
    <ram:URIID schemeID="0204">04011000-12345-34</ram:URIID>
  </ram:URIUniversalCommunication>
</ram:BuyerTradeParty>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
