PEPPOL-EN16931-R007: Business process identifier is not an approved value

DeutschFrançaisAll rules

Official message

Business process MUST have an approved identifier.
Business process MUST have an approved profile identifier.
Severity
Error (the invoice is rejected)
Checked in
UBL, CII
Business terms
BT-23

What does PEPPOL-EN16931-R007 mean?

The Business process type (BT-23) must be one of the values Peppol has approved. In this rule set that is urn:fdc:peppol.eu:2017:poacc:billing:01:1.0 or urn:peppol:bis:billing_with_response; the UBL rules also accept the French profiles urn:peppol:france:billing:regulated and urn:peppol:france:billing:non-regulated. Any other text fails, and so does a missing value.

Usual causes

  • A value from another standard was used, for example an XRechnung or Factur-X profile.
  • A typo or a changed version number in the identifier.
  • A placeholder such as "billing" or the specification identifier (BT-24) was copied into the profile field.

How do I fix PEPPOL-EN16931-R007?

  1. Set cbc:ProfileID (UBL) or ram:BusinessProcessSpecifiedDocumentContextParameter/ram:ID (CII) to urn:fdc:peppol.eu:2017:poacc:billing:01:1.0, the usual value.
  2. Use urn:peppol:bis:billing_with_response only if you and the receiver use the invoice response process.
  3. Copy the value exactly; spaces at the ends are ignored but any other difference fails.

Corrected XML (minimal example we wrote)

UBL

<cbc:ProfileID>urn:fdc:peppol.eu:2017:poacc:billing:01:1.0</cbc:ProfileID>

CII

<ram:BusinessProcessSpecifiedDocumentContextParameter>  <ram:ID>urn:fdc:peppol.eu:2017:poacc:billing:01:1.0</ram:ID></ram:BusinessProcessSpecifiedDocumentContextParameter>

Example values only. Put the elements in place of, or beside, what your file has; element order matters in both syntaxes.
