E-factuurregel uitgelegd · EN 16931

BR-CL-23: Eenheid is geen code uit UN/ECE-aanbeveling 20/21

EnglishDeutschFrançaisAlle regels

Officiële melding

Unit code MUST be coded according to the UN/ECE Recommendation 20 with Rec 21 extension
Ernst
Fout (de factuur wordt geweigerd)
Gecontroleerd in
UBL, CII

Wat betekent BR-CL-23?

De unitCode bij de gefactureerde hoeveelheid (BT-130) en bij de basishoeveelheid van de prijs (BT-150) moet een code uit UN/ECE-aanbeveling 20 of 21 zijn, precies zoals daar geschreven. Veelgebruikte codes zijn C62 (een/eenheid), H87 (stuk), HUR (uur), DAY (dag), MON (maand), KGM (kilogram), MTR (meter), LTR (liter) en LS (forfait).

Gebruikelijke oorzaken

  • Er is een label uit de factuursoftware of van de gedrukte factuur gebruikt, zoals "st", "stuks", "u" of "pce".
  • De code is in kleine letters geschreven (hur) of bevat een spatie.
  • Een eenheid is gekoppeld aan een code die aannemelijk lijkt maar niet op de lijst staat.

Hoe los ik BR-CL-23 op?

  1. Koppel elke eenheid in uw software aan haar code uit aanbeveling 20/21, bijvoorbeeld stuk aan H87, uur aan HUR en forfait aan LS.
  2. Schrijf de code exact en in hoofdletters in het attribuut unitCode van cbc:InvoicedQuantity / cbc:BaseQuantity (CII: ram:BilledQuantity / ram:BasisQuantity).
  3. Het leesbare label mag op de pdf blijven staan; alleen de code hoort in het XML-attribuut.

Gecorrigeerde XML (minimaal voorbeeld van ons)

UBL

<cbc:InvoicedQuantity unitCode="HUR">8</cbc:InvoicedQuantity>

CII

<ram:SpecifiedLineTradeDelivery>  <ram:BilledQuantity unitCode="HUR">8</ram:BilledQuantity></ram:SpecifiedLineTradeDelivery>

Alleen voorbeeldwaarden. Vervang of vul de elementen in uw bestand aan; de volgorde van de elementen ligt in beide syntaxen vast.
