BR-DE-17: Rechnungsart-Code ist keiner der von XRechnung erwarteten

EnglishFrançaisAlle Regeln

Offizielle Meldung

Mit dem Element "Invoice type code" (BT-3) sollen ausschließlich folgende Codes aus der Codeliste UNTDID 1001 übermittelt werden: 326 (Partial invoice), 380 (Commercial invoice), 384 (Corrected invoice), 389 (Self-billed invoice) und 381 (Credit note),875 (Partial construction invoice), 876 (Partial final construction invoice), 877 (Final construction invoice).
Schweregrad
Warnung (sollte behoben werden; allein kein Abweisungsgrund)
Geprüft in
UBL, CII
Geschäftsbegriffe
BT-3

Was bedeutet BR-DE-17?

XRechnung erwartet als Code für die Rechnungsart (BT-3) einen von 326 (Teilrechnung), 380 (Handelsrechnung), 384 (korrigierte Rechnung), 389 (Gutschrift im Gutschriftsverfahren), 381 (Rechnungskorrektur/Gutschrift), 875, 876 oder 877 (Abschlags-, Teilschluss- und Schlussrechnung im Bau). Das ist eine Warnung, kein Fehler: Die Datei bleibt gültig, aber eine Empfangsplattform kann andere Codes anders behandeln oder ablehnen.

Typische Ursachen

  • Die Software verwendet einen anderen UNTDID-1001-Code, etwa 386 (Vorauszahlungsrechnung), 383 (Belastungsanzeige) oder 393 (Factoring-Rechnung).
  • Eine Gutschrift wurde mit einem anderen Code als 381 versendet.
  • Eine hauseigene oder veraltete Belegart-Nummer wurde direkt in BT-3 übernommen.

Wie behebe ich BR-DE-17?

  1. Verwenden Sie 380 für eine normale Rechnung und 381 für eine Rechnungskorrektur oder Gutschrift; 326, 384, 389 oder 875 bis 877 nur, wenn der Beleg wirklich diese Art ist.
  2. Der Code steht in cbc:InvoiceTypeCode (bzw. cbc:CreditNoteTypeCode in einer UBL-Gutschrift) oder in ram:TypeCode innerhalb von rsm:ExchangedDocument (CII).
  3. Brauchen Sie für einen bestimmten Käufer einen anderen Code, klären Sie mit ihm, ob er ihn annimmt.

Korrigiertes XML (minimales Beispiel von uns)

UBL

<cbc:InvoiceTypeCode>380</cbc:InvoiceTypeCode>

CII

<rsm:ExchangedDocument>  <ram:ID>RE-2026-0042</ram:ID>  <ram:TypeCode>380</ram:TypeCode>  <ram:IssueDateTime>    <udt:DateTimeString format="102">20261124</udt:DateTimeString>  </ram:IssueDateTime></rsm:ExchangedDocument>

Nur Beispielwerte. Ersetzen oder ergänzen Sie die Elemente in Ihrer Datei; die Reihenfolge der Elemente ist in beiden Syntaxen vorgeschrieben.
