BR-DE-26: Rechnungskorrektur ohne Bezug auf die korrigierte Rechnung

Wenn im Element "Invoice type code" (BT-3) der Code 384 (Corrected invoice) übergeben wird, soll PRECEDING INVOICE REFERENCE BG-3 mind. einmal vorhanden sein.

Was bedeutet BR-DE-26?

Steht im Rechnungsartcode (BT-3) der Code 384 (Rechnungskorrektur), soll die Datei mindestens eine vorausgegangene Rechnung (BG-3) nennen, damit der Käufer erkennt, welche Rechnung ersetzt wird. Es handelt sich um eine Warnung.

Typische Ursachen

  • Die Software setzt Code 384, hat aber kein Feld für die ursprüngliche Rechnungsnummer.
  • Die ursprüngliche Rechnungsnummer steht nur in einer Bemerkung oder im Rechnungstitel.
  • Code 384 wurde für eine normale neue Rechnung statt 380 verwendet.

Wie behebe ich BR-DE-26?

  1. Die Nummer der ursprünglichen Rechnung, am besten mit Datum, in cac:BillingReference/cac:InvoiceDocumentReference (UBL) bzw. ram:InvoiceReferencedDocument (CII) angeben.
  2. Mit dem Käufer klären, wie Korrekturen übermittelt werden sollen; manche bevorzugen eine Gutschrift (381) und eine neue Rechnung.
  3. Ist die Rechnung keine Korrektur, den Rechnungsartcode 380 verwenden.

Korrigiertes XML (minimales Beispiel von uns)

UBL

<cac:BillingReference>
  <cac:InvoiceDocumentReference>
    <cbc:ID>RE-2026-0042</cbc:ID>
    <cbc:IssueDate>2026-10-01</cbc:IssueDate>
  </cac:InvoiceDocumentReference>
</cac:BillingReference>

CII

<ram:ApplicableHeaderTradeSettlement>
  <ram:InvoiceReferencedDocument>
    <ram:IssuerAssignedID>RE-2026-0042</ram:IssuerAssignedID>
  </ram:InvoiceReferencedDocument>
</ram:ApplicableHeaderTradeSettlement>

Nur Beispielwerte. Ersetzen oder ergänzen Sie die Elemente in Ihrer Datei; die Reihenfolge der Elemente ist in beiden Syntaxen vorgeschrieben.
