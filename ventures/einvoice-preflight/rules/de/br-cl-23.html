E-Rechnungs-Prüfregel erklärt · EN 16931

BR-CL-23: Mengeneinheit ist kein Code nach UN/ECE-Empfehlung 20/21

EnglishFrançaisAlle Regeln

Offizielle Meldung

Unit code MUST be coded according to the UN/ECE Recommendation 20 with Rec 21 extension
Schweregrad
Fehler (die Rechnung wird abgewiesen)
Geprüft in
UBL, CII

Was bedeutet BR-CL-23?

Das Attribut unitCode an der berechneten Menge (BT-130) und an der Basismenge des Preises (BT-150) muss ein Code aus der UN/ECE-Empfehlung 20 oder 21 sein, genau wie dort geschrieben. Gängig sind C62 (Einheit), H87 (Stück), HUR (Stunde), DAY (Tag), MON (Monat), KGM (Kilogramm), MTR (Meter), LTR (Liter) und LS (Pauschale).

Typische Ursachen

  • Es wurde eine Bezeichnung aus der Rechnungssoftware oder dem Rechnungsdruck verwendet, etwa „Stk“, „Std“, „h“ oder „pcs“.
  • Der Code ist kleingeschrieben (hur) oder enthält ein Leerzeichen.
  • Eine Einheit wurde einem plausibel aussehenden Code zugeordnet, der aber nicht in der Liste steht.

Wie behebe ich BR-CL-23?

  1. Ordnen Sie in Ihrer Software jeder Einheit ihren Code nach Empfehlung 20/21 zu, etwa Stück zu H87, Stunde zu HUR, Pauschale zu LS.
  2. Schreiben Sie den Code exakt und in Großbuchstaben in das Attribut unitCode von cbc:InvoicedQuantity / cbc:BaseQuantity (CII: ram:BilledQuantity / ram:BasisQuantity).
  3. Die lesbare Bezeichnung können Sie für das PDF behalten; ins XML-Attribut gehört nur der Code.

Korrigiertes XML (minimales Beispiel von uns)

UBL

<cbc:InvoicedQuantity unitCode="HUR">8</cbc:InvoicedQuantity>

CII

<ram:SpecifiedLineTradeDelivery>
  <ram:BilledQuantity unitCode="HUR">8</ram:BilledQuantity>
</ram:SpecifiedLineTradeDelivery>

Nur Beispielwerte. Ersetzen oder ergänzen Sie die Elemente in Ihrer Datei; die Reihenfolge der Elemente ist in beiden Syntaxen vorgeschrieben.
