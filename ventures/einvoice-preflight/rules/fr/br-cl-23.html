Règle de facture électronique expliquée · EN 16931

BR-CL-23: Unité de mesure hors recommandation UN/ECE 20/21

EnglishDeutschToutes les règles

Message officiel

Unit code MUST be coded according to the UN/ECE Recommendation 20 with Rec 21 extension
Gravité
Erreur (la facture est rejetée)
Vérifiée en
UBL, CII

Que signifie BR-CL-23 ?

L'attribut unitCode de la quantité facturée (BT-130) et de la quantité de base du prix (BT-150) doit être un code de la recommandation UN/ECE 20 ou 21, écrit exactement comme dans la liste. Les plus courants : C62 (unité), H87 (pièce), HUR (heure), DAY (jour), MON (mois), KGM (kilogramme), MTR (mètre), LTR (litre) et LS (forfait).

Causes fréquentes

  • Un libellé du logiciel ou de la facture imprimée a été utilisé, comme « pce », « u », « h » ou « forfait ».
  • Le code est en minuscules (hur) ou contient une espace.
  • Une unité a été associée à un code plausible mais absent de la liste.

Comment corriger BR-CL-23 ?

  1. Associez dans votre logiciel chaque unité à son code de la recommandation 20/21, par exemple pièce à H87, heure à HUR, forfait à LS.
  2. Écrivez le code exactement, en majuscules, dans l'attribut unitCode de cbc:InvoicedQuantity / cbc:BaseQuantity (CII : ram:BilledQuantity / ram:BasisQuantity).
  3. Vous pouvez garder le libellé lisible sur le PDF ; seul le code va dans l'attribut XML.

XML corrigé (exemple minimal rédigé par nous)

UBL

<cbc:InvoicedQuantity unitCode="HUR">8</cbc:InvoicedQuantity>

CII

<ram:SpecifiedLineTradeDelivery>  <ram:BilledQuantity unitCode="HUR">8</ram:BilledQuantity></ram:SpecifiedLineTradeDelivery>

Valeurs d'exemple uniquement. Remplacez ou complétez les éléments de votre fichier ; l'ordre des éléments est imposé dans les deux syntaxes.
