BR-DE-17: Le code de type de facture n'est pas l'un de ceux attendus par XRechnung

EnglishDeutschToutes les règles

Message officiel

Mit dem Element "Invoice type code" (BT-3) sollen ausschließlich folgende Codes aus der Codeliste UNTDID 1001 übermittelt werden: 326 (Partial invoice), 380 (Commercial invoice), 384 (Corrected invoice), 389 (Self-billed invoice) und 381 (Credit note),875 (Partial construction invoice), 876 (Partial final construction invoice), 877 (Final construction invoice).
Gravité
Avertissement (à corriger ; pas un rejet à lui seul)
Vérifiée en
UBL, CII
Termes métier
BT-3

Que signifie BR-DE-17 ?

XRechnung attend comme code de type de facture (BT-3) l'un des codes 326 (facture partielle), 380 (facture commerciale), 384 (facture rectificative), 389 (autofacturation), 381 (avoir), 875, 876 ou 877 (situations de travaux partielle, partielle finale et finale dans le bâtiment). C'est un avertissement, pas une erreur : le fichier reste valide, mais une plateforme de réception peut traiter autrement ou refuser d'autres codes.

Causes fréquentes

  • Le logiciel utilise un autre code UNTDID 1001, par exemple 386 (facture d'acompte), 383 (note de débit) ou 393 (facture affacturée).
  • Un avoir a été envoyé avec un code autre que 381.
  • Un numéro de type de document interne ou ancien a été repris tel quel dans BT-3.

Comment corriger BR-DE-17 ?

  1. Utilisez 380 pour une facture ordinaire et 381 pour un avoir ; 326, 384, 389 ou 875 à 877 seulement si le document est réellement de ce type.
  2. Le code se place dans cbc:InvoiceTypeCode (ou cbc:CreditNoteTypeCode dans un avoir UBL) ou dans ram:TypeCode à l'intérieur de rsm:ExchangedDocument (CII).
  3. Si un acheteur particulier vous demande un autre code, vérifiez avec lui qu'il l'accepte.

XML corrigé (exemple minimal rédigé par nous)

UBL

<cbc:InvoiceTypeCode>380</cbc:InvoiceTypeCode>

CII

<rsm:ExchangedDocument>
  <ram:ID>RE-2026-0042</ram:ID>
  <ram:TypeCode>380</ram:TypeCode>
  <ram:IssueDateTime>
    <udt:DateTimeString format="102">20261124</udt:DateTimeString>
  </ram:IssueDateTime>
</rsm:ExchangedDocument>

Valeurs d'exemple uniquement. Remplacez ou complétez les éléments de votre fichier ; l'ordre des éléments est imposé dans les deux syntaxes.
