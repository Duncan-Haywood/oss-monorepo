Does your package.json "exports" map point at files that actually exist?

Paste your package.json and a listing of the files you actually publish (npm pack --dry-run, git ls-files, or a plain find . -type f) and see every literal target in the exports map — across every subpath, every condition (import/require/types/...), every fallback array — that doesn't exist. That's the difference between a package that works on the maintainer's own machine and one that throws ERR_PACKAGE_PATH_NOT_EXPORTED or Cannot find module the moment a stranger runs npm install.

Nothing is uploaded. Both text boxes are parsed in this browser and never leave your device. This checks existence, not behaviour: it never runs your code, resolves an import graph, or reads a file's contents.

Common questions

Why does a bad exports target only show up after publish?

On the maintainer's own machine the build has usually already run, so the file the exports map names is sitting right there and everything works. The gap is between what's on disk right now and what actually ends up in the published tarball — a rename during a refactor, a build script that changed its output directory, or an npm publish run before the build step finished, and the first person to find out is a stranger running npm install, not the maintainer.

What is ERR_PACKAGE_PATH_NOT_EXPORTED?

Node's own error when code tries to import a subpath that either isn't listed in the package's exports map at all, or is listed but the file it points to isn't there. It replaced Node's older, more forgiving file resolution, so a package.json that shipped exports without checking every target actually exists is exactly the failure mode this tool looks for.

Is this a bundler or a publish tool?

No. It never runs your package, never resolves an import graph, and never reads a file's contents — it only checks whether each literal path the exports map names exists. Wildcard subpaths ("./features/*") and bare-specifier re-exports of another package are listed as not checked, not as passing or failing.

Is my package.json uploaded anywhere?

No. The browser page parses the text you paste entirely in your own browser and never sends it anywhere. The CLI reads only local files — no network call, ever.
