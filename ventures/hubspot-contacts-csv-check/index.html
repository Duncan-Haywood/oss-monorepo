Safe fixes

    The rules, and what they leave out

    • Matching. HubSpot matches rows to existing contacts by Email or Record ID. A row with neither is created new, and a second import of the same file creates the same contacts again.
    • Email. One address per cell, no spaces, no mailto:, not in Name <address> form. The tool flags likely domain typos, disposable domains and shared role inboxes. Two rows with one email are merged into one contact, and the later row usually wins on conflicts.
    • Lifecycle Stage defaults: Subscriber, Lead, Marketing Qualified Lead, Sales Qualified Lead, Opportunity, Customer, Evangelist, Other. Lead Status defaults: New, Open, In Progress, Open Deal, Unqualified, Attempted to Contact, Connected, Bad Timing. Portals can customise both lists.
    • Dates in one column should use one order. A column that has both 03/14/2026 and 14/03/2026 cannot be read correctly in either order; YYYY-MM-DD is unambiguous.
    • Phone numbers hold digits and punctuation. Excel turns long numbers into scientific notation and drops leading zeros on ZIP codes.
    • Limits from memory: about 1,048,576 rows and 1,000 columns per file.
    • Safe fixes change only the delimiter, header capitalisation, spaces, capitals and mailto: on emails, a date column that has exactly one possible reading (rewritten as YYYY-MM-DD), and a row that is an exact copy of the row above it. It never edits a name, company, phone, address, title, owner or custom property.
    • Not checked: whether an address actually receives mail, consent or opt-in status, your portal's custom properties, required properties, association to companies, and anything HubSpot changes in its importer. Import a small sample first.

    Common questions

    Why did my HubSpot contact import fail or create duplicate contacts?

    The usual causes are rows with no email and no Record ID, so HubSpot cannot match them to existing contacts; the same email on several rows; more than one address in the Email cell; a Lifecycle Stage or Lead Status value that is not one your portal has; dates that mix month-first and day-first; and an Excel save that turned phone numbers into scientific notation. This tool tests each of them and names the line.

    How does HubSpot match imported rows to existing contacts?

    From memory of HubSpot's public documentation: contacts are matched on the Email property or on Record ID. A row with a matching email updates that contact; a row with neither is created as a new record. Confirm the behaviour on a small file first.

    How do I clean a contact list before importing it into HubSpot?

    Paste the file or drop it onto this page. It reads the header, maps each column to the property HubSpot will probably choose, checks every row, and lists problems with line numbers grouped as errors, warnings and notes. Nothing is uploaded.

    What does Apply safe fixes change?

    Only things with one reasonable reading: the delimiter, header capitalisation, spaces, capitals and mailto: on emails, a date column where every value can only be read one way, and a row that is an exact copy of the row above. It never edits a name, company, phone, address, title, owner or custom property.

    Is it safe to put my contact list into a web page?

    The page runs in your browser, the file is read locally and nothing is uploaded; a test in the code asserts there are no network calls. Contact lists are personal data, so keep that property in mind before using any tool that uploads them.

    What does this not check?

    Whether an address receives mail, whether you have consent to email it, your portal's custom properties and required fields, and whether HubSpot will accept the file today. A clean result is not a promise of success.
