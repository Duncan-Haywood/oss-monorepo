Common questions

What is a duplicate package in package-lock.json?

The same package installed at more than one version, usually one copy at the top of node_modules and others nested under the packages that need a different version. Each extra copy costs disk space, install time and, in a front-end build, bundle size.

Can npm dedupe remove them?

Often, when the copies share a major version. Running npm dedupe lets npm move a compatible version up the tree so one copy satisfies several dependants. Copies at different major versions cannot be merged that way: the dependant has to be upgraded, or you can force one version with an overrides entry in package.json and test that nothing breaks.

Does this tool upload my package-lock.json?

No. The lockfile is read in this page and never leaves your device. The page makes no network calls, and the CLI reads one local file.

Does it measure how many bytes the duplicates cost?

No. A lockfile records versions, not sizes, so the report counts extra copies and shows who requires each one. Use your bundler's analyser to see the byte cost of the ones that reach a browser bundle.

Is a duplicate always a problem?

No. Many are harmless, and a few matter, for example two copies of a library that keeps global state, or two copies of a UI framework in one bundle. The report is a list to review, not a finding that anything is broken.
