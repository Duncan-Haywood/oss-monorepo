    Questions

    Why does [*.{md}] in .editorconfig not match my Markdown files?

    Because braces with a single item and no comma are not a list. EditorConfig reads {md} as the literal text {md}, braces included, so [*.{md}] only matches a file named like notes.{md}. Write [*.md], or list two or more alternatives such as [*.{md,mdx}].

    Can I put a comment after a value in .editorconfig?

    No. Since version 0.15 of the EditorConfig specification, a # or ; after a value is part of the value, so indent_size = 4 # four sets indent_size to the text 4 # four, which editors ignore. Some older cores still strip the comment, so the same file behaves differently in different editors. Put comments on their own line.

    Where does root = true go?

    At the top of the file, before the first [section]. There it stops editors from reading .editorconfig files in parent folders. Inside a section it is an ordinary key: it is reported for matching files and does not stop the search.

    Why does [src/*.js] not match files in src/components?

    Two reasons. A single * stops at a folder separator, so src/*.js only matches files directly inside src. And a section name containing a slash is anchored to the folder of its .editorconfig file. Use [src/**.js] or [src/**/*.js] for every .js file below src, and a name without a slash, like [*.js], to match at any depth.

    Which .editorconfig wins when there are several?

    Editors read every .editorconfig from the file's own folder up to the nearest one with root = true, then apply them from the top down, so a nearer file overrides one further up. Within a file, a later section overrides an earlier one for the same key. The tool shows, for every file, which line won and which values it overrode.
