What you get

One row per requirement with the spec section number and title, the article and paragraph it came from (for example 1.3 ACTION SUBMITTALS, B), the submittal type on one scale (the UFGS SD-01 to SD-11 descriptions most Division 01 sections echo), the phase, the full requirement text and the PDF page. Rows are flagged when the text asks for a delegated design or engineer-sealed calculations, a sustainability (LEED, VOC, recycled content) document, or a submittal only "if requested". The CSV adds blank Status and date columns so it can serve as the working log.

Questions

How do I make a submittal register from a spec book?

Choose the project manual PDF, or every volume at once. The tool finds each SECTION heading, reads the submittal articles in Part 1 (ACTION, INFORMATIONAL, CLOSEOUT and MAINTENANCE MATERIAL SUBMITTALS, or UFGS SD-01 to SD-11 lists) and lists one row per requirement. Download the CSV and open it in Excel, Google Sheets or your project-management tool's import.

Is my project manual uploaded?

No. The PDF is read by code running in this tab; nothing is sent anywhere. A 2,000-page book takes about half a minute on a laptop.

Which spec formats does it read?

CSI SectionFormat books with numbered articles and lettered paragraphs, which is how most commercial and public project manuals are laid out, and UFGS books with SD lists and the G Government-approval mark (kept in the Approval column, with any reviewer code after it). A scanned PDF with no text layer needs OCR first; the tool says so when it sees one.

How accurate is it?

On 690 Unified Facilities Guide Specification sections whose XML tags each submittal, it found 99.3% of the 12,952 tagged items with 99.9% precision. Printed to PDF and read back the way this page reads a book, 98.8% to 99.1%. It has not yet been measured on a commercial (SectionFormat) project manual, so check every section by hand before relying on the list. How it was checked.

Does it find submittals mentioned in Part 2 or Part 3?

Yes, as a separate list under the register. Every sentence outside the Part 1 submittal articles that obliges someone to submit something (in Part 2, Part 3, or a Part 1 article such as Quality Assurance) is listed with its section, article, paragraph, type and any deadline it states, and with the Part 1 row it seems to restate. The ones no Part 1 row covers are the likely missed submittals, and one click adds them to the register. Read by hand on two samples of 40 sentences from 690 UFGS sections, 79 of 80 were real submit requirements and 43 of 49 suggested Part 1 matches were right. Division 01 general requirements still apply on top of every section.

Can it tell me when each submittal is due?

Yes. Open "Submittal schedule" under the register and add the project schedule: a Primavera P6 .xer export, or a CSV with an activity name and a start column. Each spec section is matched to the first activity that installs its work, and Submit by = that start minus any lead time you enter, minus the review period times the review cycles. The review period comes from the book's Division 01 when it states one, else 14 calendar days. Closeout items are due one review period before the last finish. On 80 sections checked by hand against four public P6 schedules, the matched activity was right 72.5% of the time and wrong 25%, so each row shows the activity it used. Check it, and pin a section to the right activity ID where it is wrong.

Can I run it on my own machine or server?

Yes. It is FSL-1.1-MIT-licensed, has no dependencies and runs from a folder: node cli.mjs project-manual.pdf --csv register.csv. Source and instructions are on GitHub.
