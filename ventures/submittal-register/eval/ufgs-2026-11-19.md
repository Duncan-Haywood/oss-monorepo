# UFGS submittal lists vs the register, 2026-11-19

What was measured: how many of the submittal items a UFGS section tags in its
own SpecsIntact XML (each `<ITM>` under an `SD-nn` `<LST>`, `G` from the item's
text) the register finds when the section is read as printed text, and as a
PDF printed by Chromium and read back with `pdf-text.mjs`.

Inputs (not committed; UFGS text is a US Government work, 17 U.S.C. 105):

- UFGS_M: 706 `.SEC` files (690 sections with a number) from
  github.com/mttvnst-HA/secwriter, `reference/UFGS_M` (sparse checkout, 70 MB).
- The 2019-07-30 UFGS data package in github.com/vdubya/Open-Built-Environment-Datasets
  (`datapackages/UFGS-UnifiedFieldGuideSpecs20190730/data/xml`, 101 files).

Rendering (eval/ufgs.mjs) is this repo's own: editor's notes, header and
metric alternates dropped, every bracketed option kept, articles numbered as
SpecsIntact prints them. The text eval joins every section into one book with
form feeds every 55 lines and a "SECTION nn nn nn Page n" footer, so the
section splitter and running-line stripper are exercised too. The PDF eval
prints an even spread of sections (every Nth file) to Letter pages with a page
footer, Arial or Times, and reads the bytes back.

What this does not show: accuracy on a commercial CSI SectionFormat project
manual ("1.3 ACTION SUBMITTALS" / "A. Product Data: ..."). Only the unit-test
fixtures, written for this repo, cover that layout. No public SectionFormat
project manual PDF was reachable from this session (wbdg.org and the agency
hosts found by search refused the proxy); that is the next measurement.

Fixes the eval drove, in order (recall / precision on UFGS_M text unless noted):

1. First run on the 2019 package: 93.0% / 87.2%.
2. "DOCUMENT 00 73 xx" headings; items whose printed text starts with words
   before the tagged name; paragraph numbering in the renderer: 98.5% / 89.0%.
3. Section headings must be upper case ("Section 03 30 00 ..." in prose
   started a new section): 2019 package 99.2% / 96.1%.
4. A numbered sub-article or lettered paragraph ends an SD list: 98.6% precision on 2019.
5. UFGS_M first run 97.1% / 99.4%; "SECTION nn nn nn.nn nn Page n" footers stripped: 97.7% / 99.6%;
   items that begin "Submit ..." kept: 99.0% / 99.6%.
6. PDF path, first run 5.8% recall: the copied PDF reader ordered Chromium's
   lines bottom to top (y-down CTM and y-down Tm both counted as "flipped").
   Fixed in this venture's copy of pdf-text.mjs: 96.0%.
7. A cross-reference wrapped to the start of a line ("SECTION 07 27 26
   FLUID-APPLIED ... , and other") is not a heading: PDF 99.1% / 99.3%.
8. Renderer prints "SECTION" before a bare `<SCN>` number (one file): 99.3% / 99.9%.
