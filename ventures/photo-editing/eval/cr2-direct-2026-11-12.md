# Canon CR2 developed directly (2026-11-12)

## Why

`portfolio/flagships.yaml` (photo-editing `next:`) listed "reading CR2 directly (needs
per-model colour matrices)". Until today every Canon CR2 shooter had to run Adobe's DNG
Converter before `shootflow develop`. The sensor stream was already decoded sensel-for-sensel
as LibRaw does (`eval/ljpeg-decoder-2026-11-11.md`); what was missing were the facts a DNG
states in tags and a CR2 leaves to the reader, and a colour matrix.

## What changed

`src/shootflow/cr2.py` reads a CR2 into a `RawImage` whose raw IFD carries DNG-equivalent tags
(ActiveArea, CFAPattern, BlackLevel with a 2x2 repeat, WhiteLevel, AsShotNeutral) and whose IFD0
gains UniqueCameraModel, so `raw_develop.develop` runs its DNG path unchanged. `parse_raw`
dispatches on the 'CR' marker at byte 8.

| fact | where it comes from |
| --- | --- |
| sensor | raw IFD's lossless JPEG, Canon's slices (0xC640) put back side by side (numpy when present) |
| image area | maker note SensorInfo (0x00E0): left/top/right/bottom borders |
| black level | median of the masked columns left of the image, per 2x2 position (first and last 4 skipped) |
| white level | 2^precision - 1 (16,383 at 14 bits) |
| as-shot balance | ColorData (0x4001) WB_RGGBLevelsAsShot; index by ColorData version (array length), from ExifTool's documented layouts |
| CFA phase | from the picture: the green diagonal agrees most across a 12 x 8 grid; red vs blue from the as-shot balance; refused (asks for `--cfa`) when unclear |
| colour | the user's `.dcp` profile (`--dcp`); refused without one |

No camera table is copied from LibRaw or dcraw: the colour comes from the photographer's own
profile (Adobe's DNG Converter installs one per camera), which is also why the white level is
the stream's precision rather than LibRaw's per-model value.

A first attempt read the CFA phase by matching the small uncompressed RGB thumbnail (IFD 2)
against each phase. On the 5D Mark II it failed: the thumbnail is framed differently from the
sensor's image area and still carries the black level (channel minimums about 1,000 of 16,383),
and the best phase scored 0.46 against 0.27 for the runner-up on chroma correlation. It was
removed; the data rule found the right phase on the first try.

## Check against LibRaw

Real file: `RAW_CANON_5DMARK2_PREPROD.CR2` from rawpy's test folder (Canon EOS 5D Mark II,
ISO 3200, a dim blue-lit street scene). `tools/cr2_develop_check.py` builds a `.dcp` at run time
from LibRaw's matrix for the camera (rawpy's `rgb_xyz_matrix`, never committed) so both sides
use the same matrix, develops half size with ShootFlow (`default_tone="never"`, plain sRGB
curve) and compares with LibRaw's `postprocess(use_camera_wb=True, half_size=True,
no_auto_bright=True, gamma=(2.4, 12.92), user_sat=16383)`.

| | ShootFlow | LibRaw |
| --- | --- | --- |
| image area (top, left, height, width) | 56, 168, 3744, 5616 | 56, 168, 3744, 5616 |
| black level per position | 1028, 1026, 1028, 1027 | 1027, 1026, 1026, 1027 |
| CFA at the image origin | GBRG (from the data rule) | GBRG |
| white balance R, G, B | 2.4619, 1, 1.3691 | 2521/1024, 1, 1402/1024 (same) |
| white level | 16,383 | 15,600 (its table) |
| render difference, 8-bit steps | median 0.61, mean 0.85, 99th percentile 3.94 | |
| channel means (0..1) | 0.0683, 0.0745, 0.1569 | 0.0663, 0.0724, 0.1517 |

The two renders align at a shift of (2, 5) half-size pixels, the gap between LibRaw's visible
origin (52, 158) and SensorInfo's (56, 168). The remaining difference is the colour model (the
DNG specification's, with white balance through the profile, against dcraw's camera-space
multipliers) and demosaic edges; the frame has 0.0012% clipped sensels, so the white level
difference does not show here.

Speed (build container, Python 3.11, numpy, native Huffman reader): read 1.0-1.1 s; half-size
develop 1.3 s; `shootflow develop` full size to a 126 MB 16-bit TIFF, 4.3 s end to end.

## Tests

`tests/test_cr2.py`, 12 tests on CR2s written by the test (a TIFF with the 'CR' marker, an Exif
maker note holding SensorInfo and a 1,250-entry ColorData, a sliced 14-bit lossless JPEG of a
known scene with masked borders at known per-position blacks): every tag read exactly; all four
CFA phases found; a tungsten balance (red gain below blue) still found; near-neutral balance and
unknown ColorData refused with a request for `--cfa`, and accepted with it; no SensorInfo falls
back to the whole sensor with a note; sRAW refused; a grey patch renders neutral within 1%;
pure-Python and numpy engines byte-identical; the CLI stops without `--dcp` and develops with it.
Full suite: 661 tests pass (venv with numpy); ruff and mypy clean.

## Not done

- Real files from other Canon bodies (other ColorData versions, other phases): raw.pixls.us
  and rawsamples.ch answer 403 from the build container.
- A real Adobe `.dcp` for the 5D Mark II (not in the container); the render with it will differ
  from LibRaw by the profile's tables and tone curve, as intended.
- The per-model white level (highlights near clipping can be up to about 5% darker than
  LibRaw's on bodies that saturate below 2^14).
- sRAW/mRAW, CR3, and CR2 in the pipeline's grade stage (it still asks for DNG; it would need a
  per-camera profile setting).

    curl -LO https://raw.githubusercontent.com/letmaik/rawpy/main/test/RAW_CANON_5DMARK2_PREPROD.CR2
    PYTHONPATH=src:tests /tmp/v/bin/python tools/cr2_develop_check.py RAW_CANON_5DMARK2_PREPROD.CR2
