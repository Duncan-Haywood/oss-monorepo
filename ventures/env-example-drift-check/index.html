Prefer a CLI, or want this as a CI gate?

Same logic, zero dependencies, one file — and it can walk a whole source tree in one pass, skipping node_modules, .git, and similar:

node cli.mjs check --example .env.example src               # one directory, human-readable
node cli.mjs check --example .env.example . --json             # whole tree, machine-readable
node cli.mjs check --example .env.example src app.py           # a mix of directories and files
node cli.mjs check --example .env.example src --strict          # also fail on unused declared vars

Get cli.mjs — Node 18+, nothing to install. It reads only the local files/directories you name: no network call, ever. Exits 1 if any variable is read in code but missing from the example file, so it works as a PR gate on the same review that adds the read.

Common questions

Why does a missing .env.example variable matter so much?

It is usually the very first command a new contributor or a CI runner executes after cloning: copy the example file to .env, then start the app. A variable the code reads but the example file never mentions means that first run crashes immediately, and it reads as "this project is broken" rather than as what it actually is, a doc that fell one pull request behind.

Why would the example file and the code ever disagree?

A pull request adds a new process.env.FOO read (a new API key, a new feature flag) and nobody remembers to add FOO to .env.example in the same review. Nothing mechanical keeps the two in sync unless something checks -- the same reason lockfiles and changelogs drift, just with a sharper, more immediate failure the moment someone new clones the repo.

Is this a secrets scanner?

No. It never reads or reports a value on either side, only variable names -- whether a name is declared in the example file and whether that same name is read anywhere in the scanned code. It cannot see, and does not want to see, what a real .env file (which this tool never asks for) actually contains.

Is my code uploaded anywhere?

No. The browser page parses the text you paste entirely in your own browser and never sends it anywhere. The CLI reads only local files -- no network call, ever.
