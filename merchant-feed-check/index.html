Common questions

Does this guarantee my products will be approved?

No. It checks feed data-specification conformance — required fields, formats, GTIN checksums, enum values — which is one documented category of disapproval reason. It cannot see your Merchant Center or Commerce Manager account, your website's trust signals, or Shopping policy review, so it cannot detect misrepresentation, prohibited-product, or landing-page-mismatch disapprovals. Read the full scope on the docs page before relying on a clean report.

Is my product feed uploaded anywhere?

No. The browser page parses a pasted or locally loaded file entirely in your own browser and never sends it anywhere. The CLI reads only a local file — no network call, ever.

What feed formats does it accept?

CSV or TSV with a header row (Google's text feed format, or an export from Shopify, WooCommerce, or BigCommerce), or a JSON array of item objects (or {items:[...]}), the shape Meta's Catalog API and many feed tools already use. Column names are matched by common aliases (id/sku/item_id, image_link/image_url, and so on).

How is the GTIN checked?

With the real GS1 check-digit algorithm used for UPC-A, EAN-13, and GTIN-8/12/14 — the same arithmetic barcode scanners use to reject a mistyped code. A GTIN that is the right length but fails the checksum is very likely a typo, not a real product identifier.
