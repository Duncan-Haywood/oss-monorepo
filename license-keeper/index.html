    Sell your app with Stripe. Let the license keys take care of themselves.

    Questions

    Why not just use Keygen, Lemon Squeezy or Gumroad license keys?

    Hosted licensing services are good and quick to start, and Lemon Squeezy and Gumroad hand you a key as part of checkout. The catch is that the license data, the activation endpoint and the fees live on someone else's platform, and a random key can only be checked by calling that platform. License Keeper runs in your own account, signs keys with your own Ed25519 key so the app can verify them offline, and charges no per-license fee. If a hosted service already does the job for you, keep it.

    Does the app need to call the server on every launch?

    No. A license token is signed, so the app verifies it with the public key you embed and no network at all. It only calls the server to activate a machine, to refresh a token that is about to expire (subscriptions), and to learn about a revocation. Between those calls your customers can work offline.

    What happens if I lose the signing key or the server goes down?

    Tokens already issued keep verifying offline for as long as they are valid, because verification needs only the public key. Back up the state file: it holds the signing key unless you supply your own with SIGNING_PRIVATE_KEY, and without that key you cannot issue or refresh licenses that your embedded public key accepts.

    How are refunds and chargebacks handled?

    A full refund or a dispute on the original payment revokes the license. Apps that validate online see the revocation on their next check; a token already cached offline works until it expires, so use short-lived tokens for subscriptions and treat perpetual offline tokens as honour-system after a refund.

    Is it safe to try?

    It starts in dry-run mode: it issues and logs licenses but sends no email until you set DRY_RUN=false. Try it with a Stripe test-mode key first. It never writes to Stripe.
