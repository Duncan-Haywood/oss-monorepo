WORKFLOW AUDIT · FREE GITHUB ACTION · READ-ONLY

One step that checks your workflows for twelve known risks

Pwn requests, script injection, cache and artifact poisoning, secrets leaking into logs, write-all tokens, fork-reachable self-hosted runners and more. Workflow Audit runs twelve focused checkers over .github/workflows, merges their findings into one severity-ranked report, and writes it to your job summary, with optional Code Scanning alerts.

It reads files in the checkout and makes no network calls of its own. Your workflows are never uploaded.

Add it in four lines

- uses: actions/checkout@v5
  with: { persist-credentials: false }
- uses: Duncan-Haywood/oss-monorepo/ventures/workflow-audit@main
  with: { fail-on: high }

Pin to a commit SHA once you have read the code, as you should for any action. Prefer a CLI? python3 audit.py path/to/repo --format markdown (Python 3.8+, no dependencies).

Upload to Code Scanning

- uses: Duncan-Haywood/oss-monorepo/ventures/workflow-audit@main
  with: { sarif-file: audit.sarif }
- uses: github/codeql-action/upload-sarif@v3
  with: { sarif_file: audit.sarif }

FAQ

What does Workflow Audit check?

Twelve documented patterns: pwn-request checkouts and script injection, secret leaks into logs, artifact and cache poisoning, self-hosted runners reachable from forks, secrets: inherit on untrusted triggers, write-all or missing permissions, checkout credentials persisted in .git/config, deprecated action runtimes, jobs with no timeout-minutes, action references not pinned to a commit SHA, and deploy jobs with no concurrency group (an older commit can finish last and go live).

How is this different from zizmor?

zizmor is a broader, more mature static analyser and is the better choice for deep coverage. Workflow Audit is a smaller, dependency-free option that runs as a one-step Action with no install, ranks findings by severity, and writes the job summary and SARIF for you. Running both is reasonable.

Does it send my workflows anywhere?

No. It reads files in the checkout on the runner and makes no network calls of its own.

Does a clean report mean my workflows are secure?

No. It matches twelve specific patterns line by line. It is not a security audit and cannot see what a called action or reusable workflow does.
