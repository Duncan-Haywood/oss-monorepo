How to choose a search API by records and queries

Put your record count, searches per month and growth rate into the calculator to price Algolia, Meilisearch Cloud, Typesense Cloud, Elastic Cloud and a self-hosted engine side by side. These are the questions to settle before you trust the answer.

Why do search APIs bill so differently for the same app?

Per-request vendors such as Algolia charge for every thousand searches and every thousand records past a free tier, so a busy autocomplete box can cost far more than the index it queries. Cluster-priced engines such as Typesense Cloud and Elastic Cloud charge a flat fee for a memory size and nothing per search, and a self-hosted engine costs a small server plus your time. The same 500,000 records and 2 million searches a month can land more than a thousand dollars apart in the calculator.

What matters more than the list price?

Your query pattern and index size. Search-as-you-type fires a request per keystroke unless you debounce it, which multiplies searches several times over. Flat-cluster plans only work while the index fits in memory, and record size, replicas and re-indexing change the answer. Features priced separately, such as vector or AI search, are not modelled.

When should I switch providers?

When the 12-month spend under your growth rate differs enough to pay for the migration: re-indexing, changing the client library and query syntax, and rebuilding relevance tuning. Run the calculator with your own volumes and growth, and confirm the cluster fits your real index before deciding.
