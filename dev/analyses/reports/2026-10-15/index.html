Findings by root cause

  1. Shared sorted files are edited by parallel branches (4 repairs in one day). platform/pages/launched.json has a byte-for-byte sort test (launched.test.mjs:124). Four merges on 2026-10-14 repaired order or missing dates after sibling venture PRs landed. The commit messages say the entry was "appended out of order", which fits a hand edit instead of node platform/pages/launched.mjs --write (the command PRODUCT_PLAYBOOK.md names). I did not confirm the hand-edit cause from the diffs.
  2. Duplicate venture PRs (at least 3 venture pairs and 1 fix pair, 8 closed unmerged). Same slug opened twice within hours. This is the failure CLAUDE.md "Duplicate PRs" already describes; the check there reads open PRs, which cannot see a sibling that opened minutes earlier.
  3. Venture page defects that block the Pages publish (5 PRs). Titles name a [hidden] panel that renders anyway (#6558, #6645) and a dead inline script (#6265, #6266). platform/webcheck/page-integrity and inline-script-braces.test.mjs exist for these, so the open question is whether they run on every new venture before merge or only afterwards.
  4. High venture volume, little measurement. at least 77 "new venture" subjects on main in the window (lower bound: partial local history) versus no recorded visitor numbers (portfolio/usage/, live_url_visitors: null). Throughput is not the problem the evidence shows; whether any of it is used is unmeasured.

Evidence is thin on causes for 1 and 3: I read titles and two commit bodies, not diffs.
