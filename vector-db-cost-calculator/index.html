    Common questions

    How much storage does a vector index actually use?

    Raw bytes are vectorCount × dimension × 4 (float32) plus any metadata stored per vector. A million 1536-dimension embeddings (OpenAI's text-embedding-3-small size) is about 5.7 GiB of raw vectors before any index structure is built. The index itself — an HNSW graph, quantization bookkeeping, replication — adds overhead on top of that, and how much varies by engine and tuning, so this calculator asks for an overhead multiplier you set rather than assuming one for you.

    Why doesn't this calculator show live Pinecone, Weaviate, or Qdrant prices?

    Because a wrong number is worse than no number, and vendor pricing changes. This calculator does the arithmetic — storage sizing and the cost formula — from rates you paste in from each provider's own current pricing page. It never fetches or asserts a vendor's price on its own.

    What is a reasonable index overhead multiplier to use?

    There is no single correct number — it depends on the index type and its build parameters. Start at 1.0 to see the raw vector size alone, then check your chosen provider's own documentation or measure your actual deployed index size and set the multiplier so the calculator's storage estimate matches what you observed. See what is index overhead for the longer version.
