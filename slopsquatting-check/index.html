Did an AI assistant just suggest a package that doesn't exist?

LLM code generators regularly suggest npm install commands for packages that were never published. A May 2025 USENIX Security study found 19.7% of packages recommended by 16 code-generating models did not exist at all. Attackers know this: they pre-register the exact names models are likely to hallucinate, so the next developer who copies the suggestion installs the attacker's package instead of getting an install error — a technique now called slopsquatting.

Paste your package.json below. Nothing is uploaded -- this page has no network call of any kind, on purpose. It flags names that look like a typo of a famous package; it cannot check whether a name actually exists on the registry right now. Get the free CLI below for that.

Common questions

What is slopsquatting?

Registering a package name that a large language model hallucinates in generated code. A May 2025 USENIX Security study found 19.7% of packages recommended by 16 code-generating models did not exist at all. If a developer copies an AI's install suggestion without checking, and an attacker has already registered that exact hallucinated name, the install silently succeeds against the attacker's package instead of failing.

Does this page check the live npm registry?

No, and deliberately so. This page never sends anything anywhere -- it only compares the names you paste against a short built-in list of about 130 extremely well-known packages, entirely in your browser. For the real question -- does this exact name exist right now, and if so how new and untrusted does it look -- use the companion CLI, which is the only part of this tool that touches the network, making one read-only request per dependency to registry.npmjs.org.

Is a flagged name proof of anything?

No. A near-miss of a famous package name can be a coincidence, an unrelated real package, or a genuine typosquat -- this tool cannot tell those apart, on the browser page or in the CLI. A flag means "read this one before you trust it", the same framing this portfolio's other supply-chain checkers use, never a verdict.

Is my dependency data uploaded anywhere?

No. The browser page parses the package.json you paste entirely in your own browser and never sends it anywhere -- there is no fetch call in this page at all. The CLI reads your local file and sends only each dependency's name (never the whole file, never your code) to the public npm registry, one request per name.
