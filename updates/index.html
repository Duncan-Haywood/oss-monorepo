The mission

  • Ventures ventures/: software products strangers can use for free, with real business potential, measured by use.
  • Research research/: a research portfolio that supports PhD applications in ML/AI, robotics and autonomy, operations research or industrial engineering.
  • The platform platform/, portfolio/, prompts/: the agents, checks and prompts that do the work above.
  • Free choice about 5% of effort: in the spirit of Google's "20% time", about one run in twenty works on whatever the agent finds most interesting, with its own approach (prompts/explore/).
  • The web presence added 2026-10-14: one website, hosted on GitHub (GitHub Pages), from which all of the work above can be easily checked out visually.

Sales, marketing and business tools

Direction · set 16 Oct 2026

A direction, not a mandate for volume. Tools for selling and marketing (B2B, B2C and consumer), each with a deterministic core and AI on the user's own key from any provider (platform/llm/). Each can be deployed as a business of its own, embedded in someone's SaaS, or run as part of a suite. Extending the sales and marketing ventures that already exist comes before adding new ones. Spec, guardrails and definition of done: portfolio/sales-tools/README.md.

Local models as an option beside API keys

Direction · set 18 Oct 2026

Every AI feature that takes a key also takes a model running on the user's own machine or network (Ollama, LM Studio, llama.cpp; for images and video, a local server such as ComfyUI), at no per-call cost and with the data staying local. The deterministic path stays the product. How: platform/llm/ and PRODUCT_PLAYBOOK.md §3.

Voice, chat and agents as primary ways in

Direction · set 20 Oct 2026

Every tool is reachable four ways: the visual form, a typed sentence, the voice, and an AI agent. Output can be read aloud, and voice-only use must work. Nothing heavy loads until the visitor opts in, and the opt-in names the download size and where their words go. Quality is measured and published next to the limitations, not asserted. The shared implementation is the site assistant (platform/pages/assistant.mjs, the Ask page on the public site). Rules for products: PRODUCT_PLAYBOOK.md §4, "Every way in".

Depth over calculators

Direction · set 20 Oct 2026

So a run with a free choice picks research, a research-adjacent tool or a flagship milestone before a new small product. A new calculator, or new work on an existing one, needs an engine that fails two tests: a chatbot can reproduce it in one reply, and a maths graduate follows it at a glance. A published model, a solver or a proof passes; rates times quantities does not. Comparison pages on arithmetic calculators are not progress. Where to find such engines: "Research algorithms as tools" above. The posts: docs/posts/2026-10-20-fewer-calculators-harder-problems.md and docs/posts/2026-10-20-if-its-a-calculator-make-it-hard.md.

How it is built

  1. A session starts from one prompt. Every AI agent run reads the master prompt, prompt.md, which routes it to a track: products, research, process or review. The owner's goals and guardrails, summarised above, bind every track.
  2. It ships something real. A run must land a useful change on main: a tool, a fix, a research result, a page. Nothing is fabricated; every figure on the site traces to a file.
  3. Checks, not ceremony. Each change goes up as a pull request, runs CI (tests, the site checker, accessibility and link checks), is cross-reviewed by other agents, and is merged when green. Changes are fixed forward, not held.
  4. Every run is recorded. Each session commits a run record: track, outcome, what it cost and what slowed it down. 1,766 are in the repository so far, in prompts/runs/.
  5. The process improves itself. A review track reads those records, proposes changes to the prompts, measures them and keeps what works. Experiments and their verdicts are on the development analyses page.

Go deeper: the development dashboard (merges, CI and cost per day), the engineering status page, essays on how it is built, and the source on GitHub.
