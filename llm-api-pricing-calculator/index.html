    Common questions

    Why does this calculator ask for cached input tokens separately from fresh input?

    Because modern LLM APIs bill them at very different rates. A cached input token — one the provider has already processed recently, such as a repeated system prompt or the prior turns of an agentic loop — is commonly billed at a fifth to a tenth of the fresh-input rate. Agentic and long-context workloads that resend the same context on every turn can have cached tokens be the majority of all billed input, so a single blended "$X per million input tokens" estimate can be badly wrong for exactly the workloads where cost matters most. See why cached tokens usually dominate an agentic workload's bill.

    Why doesn't this calculator show live Claude, GPT, or Gemini prices?

    Because a wrong number is worse than no number, and API pricing changes often. This calculator does the arithmetic — multiplying your token volumes by the rates you paste in — from each provider's own current pricing page. It never fetches or asserts a vendor's price on its own.

    What is a reasonable cached-input rate to use?

    There is no single correct number and it varies by provider and by cache mechanism (prompt caching, context caching, implicit vs. explicit caching). Check the provider's own current pricing page for its cached/cache-read input rate, and use that — the example rates preloaded on this page are illustrative starting points, not a claim about any provider's current price.

    Does this calculator upload my token counts or rates anywhere?

    No. Every field runs in your browser; nothing is sent to a server. An optional anonymous local counter records which buttons get used, never the numbers you typed, and can be turned off.
