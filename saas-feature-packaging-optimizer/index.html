    Questions founders ask

    Which features should go in which SaaS pricing tier?

    Survey a sample of customers or prospects on what each feature is worth to them per month, paste one row per person, and the tool tests which plan each feature should first appear in and what each plan should cost. Plans are nested (higher plans include everything in lower ones), a customer is assumed to buy the plan with the most surplus, and the result is the packaging and prices that earn the most profit on your survey.

    Why not put every feature in every plan?

    Because one flat price leaves money on the table: it is too high for light users and too low for heavy ones. Holding back the features only some customers value lets the cheap plan stay cheap while the people who value those features pay more. The tool shows what a single flat plan would earn so you can see the gap.

    How do I ask about feature value in a survey?

    Ask each person the most they would pay extra per month for each feature on its own, and record 0 or leave it blank where it has no value to them. Add a core-product column if you want to price the base product too, and mark it with an asterisk so it stays in the cheapest plan.

    Is the answer exact?

    The prices are exact for the placement chosen. The placement is found by local search from several starting points, which matches exhaustive search on small test surveys but is not guaranteed on every survey with eight features. Treat the output as a ranking of packaging options to test with real signups. This is arithmetic on your survey, not pricing or financial advice.
