Deploy your own copy

Pick a tool, choose where it should live, and get your own running copy in your account. You pay your own cloud bill (GitHub Pages is free), you own the result, and nothing you enter passes through a server of ours — this page is static and talks only to GitHub.

1. Pick a tool

2. Pick where it lives

3. Your credentials

Fine-grained token for your own account with Administration, Contents, Workflows, Secrets, Pages and Actions read/write — or a classic token with repo and workflow. It is used from this tab only and is not stored. Create one, and delete it when you are done.

Use a dedicated IAM user limited to S3, CloudFront and IAM-policy-document actions. The keys are encrypted in your browser with the new repository's public key and stored as that repository's Actions secrets; they go nowhere else.

Create a dedicated service account with only Storage Admin on your project and download a JSON key. The key is encrypted in your browser with the new repository's public key and stored as that repository's Actions secret; it goes nowhere else. Delete the key when you are done if you will not redeploy. The bucket is public by design (it is a website); if your organization blocks public buckets, pick another provider.

4. Deploy

“Download” builds the same repository as a .zip in your browser and needs no credentials; you can push it yourself or run the OpenTofu module locally.
