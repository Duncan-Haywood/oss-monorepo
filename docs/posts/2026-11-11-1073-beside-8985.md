The stat row at the top of [the research index](https://marisstella.app/research/) read **1073** research projects, **8,985** unit tests, **31** themes. Two numbers of the same size, side by side, in two styles. The hub said "Search 1338 tools and 1073 research projects". The blog's filter chip said "All 3591".

None of this is wrong, exactly. It is the kind of thing that makes a page look assembled rather than made, and the stat row is one of the first things a visitor sees.

## Why it happened

Each count is written by whichever template needs it, and each template interpolated the raw number: `${surfaces.length} tools`, `${total} free calculators`, `str(len(by_slug))`. The one count that had a separator, the research tests total, went through Python's `:,` format because someone wrote it that way once. Nothing made the others follow.

While the site had fewer than 1,000 tools and projects the difference could not show. It showed when the counts crossed four digits.

## What changed

- One helper, `formatCount` in `platform/pages/count.mjs`, writes every count a reader sees with en-US grouping: `1073` becomes `1,073`. It uses en-US rather than the visitor's locale because the page is built once and served to everyone, in English.
- The hub, category pages, all-tools page, guides index, About page, blog index and its live filter count, the engineering status page, the voice assistant page's description, the web app manifest and `llms.txt` all call it. So does the research index's Python build.
- The hub's count-up animation now ends on `1,073` rather than `1073`. Before, it would have overwritten the server's formatted number with an unformatted one once it finished.
- `check.mjs`, which runs on every site build, now fails if one of the seven site-owned index pages prints a four-digit count without a separator. The pattern only looks at the nouns those templates count (tools, projects, posts, pages, sessions), so "Form 1099" and "the 2026 calculator" on tool pages do not trip it.

## Measured

The new check, run over the live site before the change and over a local build after it:

| page | ungrouped counts on marisstella.app before | local build after |
|---|---|---|
| hub | 6 | 0 |
| research index | 5 | 0 |
| about | 5 | 0 |
| category index (`/c/`) | 3 | 0 |
| engineering | 3 | 0 |
| writing index | 2 | 0 |
| guides index | 2 | 0 |

Counts under 1,000 look exactly as they did. Nothing here changes a number, only how it is written.
