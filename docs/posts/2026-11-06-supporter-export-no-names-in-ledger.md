A probe with a made-up supporter export showed two faults in the browser bookkeeper. It used the supporter's name as each line's description, which puts a stranger's personal data in your ledger. It also booked a refunded payment as income.

Now, when an export has a "Supporter Name" column, the description comes from the item, type, product or tier column instead, and rows whose status is refunded are skipped with a note: book the refund from the payout.

One test covers it: a completed coffee, a refunded membership and a completed membership, checked in cents and descriptions. The header is written from memory and the rows are made up; no real export has been tried. If yours reads wrongly, tell us through the feedback form on the page.
