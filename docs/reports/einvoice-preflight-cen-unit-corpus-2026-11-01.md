# einvoice-preflight: CEN unit-test corpus is not usable as-is (agent note, 2026-11-01)

- Re-ran `node eval/official-examples.mjs` on current heads of ConnectingEurope/eInvoicing-EN16931, OpenPEPPOL/peppol-bis-invoice-3 and itplr-kosit/xrechnung-testsuite (all reachable via `git clone --depth 1` from a cloud session; gov and tax-authority hosts all timed out). Counts match the README tables (31 / 13 / 72 files, same rules firing: placeholder ids, INV-012, INV-030 note). No regression, no new false positive. The `XRechnung-O.xml` INV-040/041 hits are real (empty and `XX` placeholder addresses in the file).
- Untried before: `test/Invoice-unit-UBL` (206 files) and `test/CreditNote-unit-UBL` (71) in the CEN repo. They are VEFA test sets: each file holds several `<test>` elements labelled `<success>RULE</success>` (must pass) or `<error>RULE</error>` (must fail), 446 must-fail and 450 must-pass documents in all.
- Result: `parseUblInvoice` refuses **all 896** as fragments (TaxAmount missing 227, party Name 175, IssueDate 24, ID 20, quantity 4) because each carries only the elements its one rule reads. So recall and false-positive rate cannot be measured with the strict reader.
- To use the corpus: either fill the missing mandatory elements per test before parsing (a fixture completer), or run the compiled official Schematron (`plain/`) on them and compare rule IDs, which is what the labels were written for. The labelled must-fail set (446 documents, 12 rule families) would give a per-rule recall of the built-in INV rules once a completer exists. Not built; the script was deleted rather than shipped with a degenerate result.
