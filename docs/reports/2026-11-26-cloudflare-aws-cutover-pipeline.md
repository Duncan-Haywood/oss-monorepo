# The Cloudflare -> AWS cutover pipeline: state for the next session (2026-11-26)

Built, tested, not run: there is no AWS account yet. Owner's direction, 2026-11-26: "get
everyyyything in tf or similar and i give full access tokens and it runs once then expire the
tokens", refined the same day by the orchestrating session's relay of "secrets etc gets managed in
aws not in gh" and "it's a quick switch over". Design and checks:
`platform/aws/cutover/README.md`. The owner's steps and calendar: `docs/runbooks/aws-cutover.md`,
"The Cloudflare move".

## What landed

- `platform/aws/stacks/cloudflare`: the Cloudflare account as OpenTofu (provider 5.29.0).
  `switch.tf` moves each hostname between its exported shape (Workers custom domain or record)
  and a DNS-only CNAME to CloudFront/API Gateway; the rest is generated by the export
  (`imports.generated.tf`, `resources.generated.tf`, both still to come from the first real
  export). 8 `tofu test` runs.
- `platform/aws/stacks/cutover-access`: `github-cutover-plan` / `github-cutover` (path
  `/cutover/`, one GitHub environment subject each), and `cutover-read` / `cutover-operate` in
  shared-infra and apps. Added to the AWS plan/apply stack lists. 4 test runs.
- `platform/aws/cutover/cutover.py`: stages export, prepare, switch, verify, rollback, retire,
  delete-secrets; `--plan`; resumable run state in S3; `fakes.py` + `fixtures/` for dry runs;
  39 pytest tests.
- `saas-starter` db-admin: `inspect`/`import`/`finish`/`checksum` actions
  (`runtime/src/data-copy.mjs`), tested against a real Postgres 16.
- `.github/workflows/priv-cutover.yml`; `github/configure.sh` creates `cutover-plan` and
  `cutover` (owner as required reviewer).

## Decisions worth knowing

- **Default path keeps DNS on Cloudflare** and repoints records; Route 53 is the optional
  full-exit track. Reason: no registrar transfer or nameserver change, so it fits one day and a
  rollback is an apply, not a propagation wait.
- **The AWS side is not provisioned by the cutover.** `prepare` checks that each app's AWS stack
  is applied and healthy; provisioning stays with the existing apply pipeline (one applier per
  account, its own reviewed roles). The brief's "provision AWS" step became this check.
- **Endpoints come from AWS, not from state or config**: the CloudFront distribution that has
  the alias, the API Gateway domain's target. `switch.tf` refuses non-AWS targets.
- **Write freeze at Cloudflare's edge** (a custom rule blocking non-GET for the app's hosts),
  so it needs nothing from the app. While it exists the zone's custom-rules ruleset differs from
  code, which is why the switch applies only the switch resources (`-target`).
- **Workers scripts, Pages projects and API tokens are not imported**: their state would hold
  secret values, and the plan roles read state. They are inventoried by name; retire deletes
  Workers through the API.
- **Copy checksum is type-erased** (canonical text per value; `canon_vectors.json` asserted in
  Node and Python), so D1's integers match Postgres's int8 strings and blobs match bytea.
