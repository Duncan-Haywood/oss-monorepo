# Job Shop Quote: the quote reply keeps the RFQ's References chain (2026-11-26)

Bet #2 (`portfolio/monetization/bets.md`). Private-monorepo PR #197, ROADMAP item 6, claim
`claim/jobshop-quote/email-references-chain`.

## What landed
- `shared/mime.ts` `ParsedEmail.references` (the header, unfolded).
- `rfqs.thread_references` (migration 0024, generated by drizzle-kit): intake stores
  `threadChain(references, inReplyTo)`, the RFQ's References, else a lone In-Reply-To
  (RFC 5322 § 3.6.4). The parent's own Message-ID stays in `message_id` and is not repeated.
- `quoteEmailThread` sends `References = chain + messageId`. `messageIdsIn` keeps only
  `isSafeMessageId` ids, with no repeats. `limitReferences` caps at 20 ids and 900 chars,
  keeping the root and the newest.

## Decisions
- The column is `thread_references`, not `references`, because REFERENCES is an SQL keyword.
- Ids are filtered again at send time (not only at intake), so a row written by older code or
  by hand cannot inject a header.
- No backfill: older RFQs thread on their Message-ID alone, as before.
