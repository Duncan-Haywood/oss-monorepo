# jobshop-quote: the Worker's cold start, Anthropic SDK loaded on first use (2026-11-28)

Perf track, "what visitors wait on" (`prompts/perf/prompt-0.md`, item 4). The perf backlog had no
agent-workable item (P063, P064 and P086 are owner rows). Bet #2 (`portfolio/monetization/bets.md`)
had app first-load and worker-test passes (2026-11-27), but nobody had measured the startup of its
Cloudflare Worker (`apps/jobshop-quote/src/worker/index.ts`). The payapps and einvoice-pro runs the
same day (`payapps-worker-cold-start-perf-2026-11-28.md`,
`einvoice-pro-worker-cold-start-perf-2026-11-28.md`) used the same method.

## Readings

**The bundle.** `npx vite build` in `apps/jobshop-quote` (the Cloudflare Vite plugin writes
`dist/jobshop_quote/`). Code the entry loads statically, before and after:

| | `index.js` | static chunks | eager total | lazy chunks |
|---|---:|---|---:|---|
| before | 2,935 KB (681 KB gzip) | `factory` 298 KB, `promise` 27 KB | **3,260 KB** | `dist` 16 KB |
| after | 1,879 KB (484 KB gzip) | `json-schema-processors` 134 KB, `factory` 169 KB | **2,183 KB** | `sdk` 1,095 KB, `zod` 6 KB, `values` 12 KB, `dist` 16 KB |

Generated bytes by source (each source-map segment's length, summed), before: our own code
691 KiB, **`@anthropic-ai/sdk` 574 KiB**, better-auth 257 KiB, @better-auth/core 127 KiB,
drizzle-orm 105 KiB, jose 74 KiB, hono 41 KiB. The SDK was the largest dependency, and it is
used by one file, `src/worker/ports/anthropic-llm.ts`, which only runs when a request calls a
model (RFQ extraction, drafting). Sign-in, quotes, the rate card and every other API route never
touch it.

**The profile.** Node with `--cpu-prof --cpu-prof-interval 50`, importing the built `index.js`,
self time mapped through the source map: of ~75 ms, **707 of 1,502 samples (~35 ms) were V8's
`compileSourceTextModule`**, i.e. parsing the bundle. Evaluation was spread thin: zod's class
factory ~7 ms, drizzle's table definitions and Better Auth's error codes a few samples each. No
single statement like payapps' `Intl.NumberFormat`. So the lever was the amount of code parsed at
startup, and the SDK was the biggest piece of it that most requests do not need.

**Startup in workerd.** `npx wrangler check startup -c <dist>/wrangler.json` (wrangler 4.165.0,
the app's pin), "Active" CPU, 7 runs with old and new bundles interleaved, 4-core cloud container:

| | runs (ms) | median |
|---|---|---:|
| before | 67.7, 75.5, 88.8, 58.4, 60.5, 53.3, 68.7 | **67.7** |
| after | 58.9, 57.2, 69.2, 65.3, 54.6, 74.9, 59.9 | **59.9** |

An earlier set of 7 on the old bundle alone: median 66.1 ms.

**Node import of the built `index.js`** (`await import()`, wall clock, includes Node's loader),
7 interleaved pairs: before median **128.1 ms**, after **105.3 ms**.

## Change

`src/worker/ports/anthropic-llm.ts`:

- `import Anthropic from "@anthropic-ai/sdk"` became `import type`, and the zod helper import is
  gone from the top. A module-level `loadSdk()` does `import("@anthropic-ai/sdk")` and
  `import("@anthropic-ai/sdk/helpers/beta/zod")` once per isolate; a failed import is not cached,
  so the next call retries.
- `AnthropicLlm`'s constructor no longer builds the client. `sdkClient()` awaits `loadSdk()` and
  builds it on the first `generateText` / `generateStructured` call, with the same options
  (`apiKey`, `maxRetries: 3`). `started` (the latency clock) is taken after that, so
  `latencyMs` still measures the API call only.

Rolldown puts the SDK in its own chunk (`assets/sdk-*.js`), which the Worker only evaluates
when a model is called. The first model call in an isolate pays the import, a few tens of ms
against a model call that takes seconds.

## Verification

- **Same answers.** `anthropic-llm.test.ts` gains four tests: `generateText` and
  `generateStructured` through the real SDK with `fetch` stubbed (the request's URL, model,
  fallback flag and Zod `json_schema` output format; the parsed reply; usage reporting; the client
  reused across calls), a refusal still raising `LlmRefusalError`, and a source check that the
  only top-level SDK import is `import type`. The three behaviour tests pass against the old
  file too (checked by swapping it back); only the source check fails there, as intended.
- `pnpm test:unit`, `pnpm test:worker`, `pnpm typecheck` and `biome check .`: results in the run
  record (`prompts/runs/`) for this PR.

## What this says

The cold start was not a problem: 60 to 70 ms against Cloudflare's 1 s startup limit. This takes
about 12% off it in workerd (18% in Node) and a third off the code a cold isolate parses
(3.26 MB to 2.18 MB). What is left is V8 compiling our own 691 KiB and Better Auth, drizzle and
zod's set-up, none of which is one statement to move.
