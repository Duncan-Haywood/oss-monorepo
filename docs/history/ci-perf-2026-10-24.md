# CI performance pass (2026-10-24): the agent-permission-harness probe

The owner asked again whether CI is worth performance-engineering, perhaps
with Rust rewrites. This continues `ci-perf-2026-10-21.md` and takes item 2 of
its "Not changed" list. The answer matches the 2026-10-20 one
(`pages-build-perf-2026-10-20.md`): the time went into an algorithm, not into a
slow language. A Rust port of the same algorithm would have made the same 3.5
million filesystem calls.

## Where the probe's time went

`python3 -m cProfile -s cumulative harness.py` on the cloud container:

| | |
|---|---|
| wall time, `harness.py` | 54.7s (user 20s, sys 33s) |
| inside `instruction_closure` | 78.1 of 82.2s profiled |
| `glob.select_recursive_step` calls | 3,570,134 |
| `posix.lstat` calls | 3,552,287 |
| `posix.scandir` calls | 3,541,001 |

R7's instruction closure resolves each backticked path a document names
(`_expand_prompt_path`). Every bare filename (`package.json`, `AGENTS.md`)
called `Path.rglob`, and every glob called `Path.glob`. Each call walked the
38,800-file tree again. The closure resolves about 1,400 specs, so the probe
walked the whole repository about 1,400 times. The test suite builds the
closure against the real repository several times
(`TestHeadlineNumbersAgainstThisRepo`), which is why the CI step took about 5
minutes a run.

## The change

`instruction_closure` now walks the tree once (`_file_index`: `os.walk`,
skipping `PRUNED_DIRS` instead of descending into `node_modules` and
filtering afterwards) and passes the sorted file list to
`_expand_prompt_path`. There:

- a bare filename is a basename match on the list, then the nearest-scope
  prefix filter, as before;
- a glob becomes a regex (`_glob_regex`) with `Path.glob`'s rules: `*` stops
  at `/`, a whole `**` segment is zero or more directories, dotfiles match.
  Patterns it does not model (an empty, `.` or `..` segment, or a trailing
  `**`, whose meaning changed in Python 3.13) fall back to the old walk;
- called without an index (the unit tests, any outside caller), the function
  behaves exactly as before.

## On the Rust question

Three passes have now looked for code that is slow because of its language,
and none found any. The costs were a compression level (zlib was already C),
a pure-Python YAML parser with libyaml installed, full-history clones, and here
a tree walk repeated 1,400 times. A rewrite becomes worth discussing when a
profile shows the time inside our own tight loop, with the work already
minimal. Profile first: `node --cpu-prof`, `python3 -m cProfile -s cumulative`,
and `ci_profile.py` for the pool.
