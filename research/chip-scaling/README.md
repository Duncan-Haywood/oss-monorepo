# chip-scaling: how does generic-gate area grow with bit width for adders, shifters, popcount and multipliers?

New question for the LLM chip-design-loop track (`PROJECTS.md`, track 3), asked because the recent chain of `chip-*` follow-ups had narrowed to variants of one result. This one measures something the earlier projects assumed: how cell count and logic depth scale with width W, so a result at 16 bits can be extrapolated, or not. No LLM is used. Produced with AI assistance (Claude). Preliminary and small: seven behavioural blocks, one tool version, one generic-gate script, no technology library.

**Live page:** https://duncan-haywood.github.io/monorepo-projects/research/chip-scaling/

**Builds on.** `chip-toolchain` and `chip-abc-sweep` in this repository (same author, MIT): the scoring wrapper `chip_abc_sweep.flow.score` is imported unchanged. Tools: Yosys and its integrated ABC (<https://yosyshq.net/yosys/>). Nothing from the CU Boulder groups in `prompt.md`; no connection to them is claimed.

## Method
- Blocks written as plain Verilog operators, generated by `src/chip_scaling/blocks.py`: `a+b`, `a<b`, `a==b`, logical right barrel shift, popcount (a loop of 1-bit adds), `a*b`, and a 4:1 word mux.
- Widths 4, 8, 16, 32, 64 (multiplier 4 to 32 in seven steps; its cost is quadratic).
- Score: `synth -flatten -noabc; abc -g AND,NAND,OR,NOR,XOR,XNOR,ANDNOT,ORNOT,MUX` (Yosys 0.33), cells = gate count (not um&sup2;), depth = Yosys `ltp -noff` longest path.
- Fit `cells = c * W^p` by least squares on log-log, over all widths and over the largest three only.

## Reproduce
```bash
sudo apt-get install -y yosys iverilog
python3 experiments/run.py        # writes results.txt (about 5 s)
python3 experiments/figure.py     # writes cells_vs_width.svg
python3 -m unittest discover -s tests   # 4 tests
```

## Results (all from `experiments/results.txt`)
| block | exponent p (all widths) | p (largest three) | cells at W=64 (mul: 32) | depth at W=4 &rarr; 64 |
|---|---|---|---|---|
| mux4 | 1.00 | 1.00 | 192 | 2 &rarr; 2 |
| eq | 1.04 | 1.02 | 127 | 3 &rarr; 7 |
| add | 1.08 | 1.03 | 344 | 7 &rarr; 125 |
| cmp_lt | 1.13 | 1.01 | 318 | 5 &rarr; 16 |
| popcount | 1.26 | 1.12 | 304 | 4 &rarr; 27 |
| shift | 1.35 | 1.27 | 389 | 2 &rarr; 6 |
| mul | 2.19 | 2.06 | 6144 (W=32) | 12 &rarr; 120 (W=32) |

- Cell counts for the adder, comparator, equality and mux are essentially linear in W (exponent 1.0 to 1.1; r&sup2; &ge; 0.99). The multiplier is quadratic (2.19 overall, 2.06 on the top three widths).
- The barrel shifter's exponent of 1.27 to 1.35 is what W&middot;log W growth looks like over this range; I did not fit that form separately.
- **Cells and depth scale differently.** The default-script `+` has linear depth (7 at W=4, 125 at W=64: about 2W, a ripple-like carry chain), while `<` has logarithmic-looking depth (5 &rarr; 16) at the same linear cell count. A cell-count estimate says nothing about the critical path, which is why the earlier projects score cells&times;depth.
- Fits use 5 points (7 for the multiplier) and one synthesis script; exponents are descriptive, not tight estimates, and I give no confidence intervals.

## Limitations
Generic gates are not library cells (`chip-pnr` showed a flop alone is ~20 um&sup2;, and none of these blocks is sequential); ABC's result depends on its script (`chip-abc-sweep`), and a different script would change depth most. One Yosys version. Behavioural operators only: Yosys picks the architecture, so this measures its defaults, not the best adder possible.
