# Choosing the detector does not fix the twin: CA, OS and log-t CFAR calibrated in a Gaussian-clutter simulator

*Stylised: square-law power, `N=16` reference cells, unit-mean gamma texture of shape ν independent per cell (K-distributed power), design false-alarm probability (Pfa) set in a Gaussian-clutter twin. Pure Python; every number is from `experiments/results.txt` (300k reference windows per estimate; Monte Carlo standard errors are in that file, at most 2% of the estimate), formulas and estimators are checked against direct simulation (`tests/`, section 2 and 7 of the results).*

## Question
`radar-clutter-twin` showed that the CA-CFAR threshold set in a Gaussian twin is too low once clutter texture decorrelates inside the window. Radar practice offers other window statistics, so the natural question is whether a different detector makes the twin-calibrated threshold safe: order-statistic CFAR (Rohling 1983) is robust to interfering targets in the window, and a log-t detector is a common choice for heavy-tailed clutter. This asks whether the sim-to-real gap is a property of the detector or of the twin.

## Model
Cell power is `τ·e`, `e~Exp(1)`, `τ~Gamma(ν,1/ν)` (ν=∞ is the twin). Detection is `X > α·S(Y_1..Y_N)` with `S` = mean (CA), the 12th smallest (OS75), the 8th smallest (OS50), or the geometric mean (LOG). The test cell is integrated out: given `S`, `Pfa = h(αS)` with `h(T)=E_τ[e^{−T/τ}]` (twin: `e^{−T}`), so only reference windows are simulated. For a Rayleigh target of mean power `s` added to the test cell, `P(τe0 + s e1 > T) = (τe^{−T/τ} − s e^{−T/s})/(τ−s)`, integrated over `τ` the same way. The twin threshold `α_twin` gives Pfa 1e-2 or 1e-4 in Gaussian clutter (exact for CA and OS via Rohling's `k·C(N,k)·B(k, N−k+1+α)`, which the Monte Carlo calibration reproduces to 0.05–0.8%; LOG has no closed form here and is calibrated by Monte Carlo, checked on independent windows to within 2%).

## Results
1. **The estimators are right.** Rao-Blackwell versus 400k-trial direct simulation at design 1e-2: OS75 0.0364 vs 0.0361 (ν=2), 0.0215 vs 0.0211 (ν=5); LOG 0.0450 vs 0.0446, 0.0229 vs 0.0224. Pd table versus direct simulation (ν=5, 20 dB): 0.8330 vs 0.8325 (CA), 0.8153 vs 0.8151 (LOG).
2. **No detector escapes the inflation.** Real/design Pfa when the threshold is set in the twin (CA / OS75 / OS50 / LOG). Design 1e-4: ν=2: 30.1 / 34.9 / 41.0 / 44.2×; ν=5: 9.1 / 9.2 / 8.3 / 9.4×; ν=20: 2.34 / 2.23 / 1.94 / 2.19×. Design 1e-2: ν=2: 3.02 / 3.64 / 4.74 / 4.50×; ν=5: 1.95 / 2.15 / 2.36 / 2.29×. The order flips with ν and design rate: OS50 is slightly better at 1e-4, ν≥5 (by 9–17%) and worst at ν=2; CA is best at 1e-2 for every ν shown. Nothing here supports "use OS or log-t to survive a Gaussian twin" for iid texture.
3. **Why: the test cell's own texture.** Reference cells are independent of the test cell's texture, so no window statistic can track it. A known-scale oracle with no window noise (fixed threshold `−ln(design)` on clutter of known mean) inflates by 2.88 / 1.95 / 1.28× at 1e-2 (ν=2, 5, 20) against CA's 3.02 / 1.95 / 1.26×. At 1e-4 the oracle is worse (36 / 12.5 / 3.1× vs 30 / 9.1 / 2.3×) because its threshold `−ln p` is below the CA twin threshold `α·mean`, so this is a comparison, not a bound. The reading is that most of the miscalibration is a *marginal-distribution* error of a single cell, which is a twin-fidelity property, not something a smarter estimator of the local level removes. (This is an explanation consistent with the numbers, not a proved theorem.)
4. **Repair costs are similar; CA is cheapest.** Extra threshold to restore the design Pfa in real clutter, dB (CA / OS75 / OS50 / LOG): 1e-4, ν=2: 3.70 / 4.07 / 4.53 / 4.33; ν=5: 1.93 / 2.05 / 2.11 / 2.07; ν=20: 0.60 / 0.61 / 0.57 / 0.61. 1e-2, ν=2: 1.95 / 2.40 / 3.07 / 2.83. Each repaired threshold hits the design rate on independent windows within ~3%.
5. **At equal real Pfa 1e-4, CA detects best.** Rayleigh target, Pd (CA / OS75 / OS50 / LOG). ν=2: 15 dB 0.431 / 0.393 / 0.354 / 0.409; 20 dB 0.758 / 0.732 / 0.703 / 0.744; 25 dB 0.915 / 0.904 / 0.892 / 0.909. ν=5, 20 dB: 0.833 / 0.813 / 0.787 / 0.815. ν=20, 20 dB: 0.876 / 0.859 / 0.833 / 0.857. The real ordering CA > LOG > OS75 > OS50 holds at every point computed. The twin agrees on the best and worst (20 dB: 0.892 / 0.876 / 0.849 / 0.872) but swaps the middle pair (twin: CA > OS75 > LOG > OS50), so it ranks the detectors approximately right in *this* clutter model even though it mis-sets their thresholds.
6. **The twin's promise is overstated after repair.** Twin Pd at its own threshold versus real Pd at the repaired threshold, CA, 15 dB: 0.700 vs 0.431 (ν=2), 0.567 (ν=5), 0.662 (ν=20). At 20 dB: 0.892 vs 0.758, 0.833, 0.876. The unrepaired detector has higher Pd than the repaired one but at a Pfa 2–30× the design; the twin's Pd claim is only meaningful together with a true Pfa.

## Limitations
No measured clutter, no interfering targets or clutter edges (OS-CFAR's home ground, so its disadvantage here is exactly the usual CFAR loss of robust detectors and may reverse in multi-target windows), iid texture only, single-pulse Rayleigh target added independently of texture, a single window length `N=16`, and OS ranks fixed at two values. The LOG twin threshold has no closed-form check. The ordering may differ for other textures (e.g. lognormal, Weibull). Not evidence about any real radar.

## Next steps
Add interfering targets to the window (where OS should win) and measure whether the twin's ordering of detectors survives there; correlated texture of intermediate length; randomizing ν in the twin (`randomized-twin`); a public radar dataset.
