Common questions

Does this connect to my Snowflake account?

No. It reads the rows you paste and never contacts Snowflake. It cannot see your contract, so every dollar figure is the credits you pasted times a credit price you can edit.

How do I get the numbers?

Credits per warehouse: SUM(CREDITS_USED) grouped by WAREHOUSE_NAME over 30 days from SNOWFLAKE.ACCOUNT_USAGE.WAREHOUSE_METERING_HISTORY. Size and AUTO_SUSPEND: SHOW WAREHOUSES. Queries and average runtime: ACCOUNT_USAGE.QUERY_HISTORY. Resumes: RESUME events in WAREHOUSE_EVENTS_HISTORY.

What AUTO_SUSPEND should I use?

Snowflake bills a 60-second minimum each time a warehouse resumes, so 60 seconds is the practical floor. Anything longer pays for idle time after each burst; the default of 600 seconds on a warehouse that wakes hundreds of times a month is a common silent cost. A shorter setting means a colder cache and a short resume wait.

Will a smaller warehouse be cheaper?

Credits per hour halve with each size down, but a long or memory-hungry query can run more than twice as long and cost the same or more. Short queries that do not speed up on a bigger size are the safe candidates. The advisor reports this only as an upper bound and never counts it in the saving.

Is my data uploaded anywhere?

No. The browser page analyses the text in your own browser and never sends it anywhere. The CLI reads a local file or stdin and makes no network call.
