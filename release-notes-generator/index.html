    Common questions

    How do I generate release notes from git commits?

    Run git log between two tags with the format this tool documents, or just run the CLI, which calls git for you. Commits are grouped by Conventional Commit type (feat, fix, perf and so on), breaking changes are pulled to the top, and non-conventional subjects are classified by their first word so an older history still produces something usable.

    How does it decide the next version number?

    By Semantic Versioning: any breaking change suggests a major bump, otherwise any feat suggests minor, otherwise patch. Before 1.0.0 a breaking change suggests minor. It is a suggestion from commit messages only; you decide the release.

    Does this upload my commit history?

    No. Everything runs in this page. The page makes no network calls and your commit text is never uploaded. The CLI runs git on your machine and prints to your terminal.

    What output formats are supported?

    Keep a Changelog style Markdown for CHANGELOG.md, GitHub release style notes with a What's changed heading, and plain text for emails and store listings. Pass a repository URL to link pull requests and commits.

    Is this a replacement for release-please or git-cliff?

    It overlaps with them on purpose. Use it when you want the notes now, without installing anything or configuring a pipeline, or to preview what your history will produce. It does not publish releases or edit files for you.
