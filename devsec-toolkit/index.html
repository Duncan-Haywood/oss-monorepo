    DEVSEC-TOOLKIT · FREE AND OPEN SOURCE · MIT

    Every DevSecOps check, one command

    Supply-chain and CI security tooling is mostly paid, or scattered across a dozen single-purpose scanners with a dozen output formats. devsec-toolkit runs your repository through 23 open-source checks (GitHub Actions, Docker, Compose, Kubernetes, dependency manifests, application code and AI coding-agent configs) and gives you one report: one severity scale, one baseline, SARIF for GitHub code scanning.

    Zero dependencies: Python 3.9+ (and Node.js 18+ for six of the checks). Nothing is uploaded and no check makes a network call. The report viewer below reads your file in this browser only.

    Run it

    git clone --depth 1 --filter=blob:none --sparse https://github.com/Duncan-Haywood/oss-monorepo.git devsec-src
cd devsec-src && git sparse-checkout set ventures/devsec-toolkit \
  $(python3 ventures/devsec-toolkit/devsec.py list --paths) && cd ..

python3 devsec-src/ventures/devsec-toolkit/devsec.py scan .                       # text report
python3 devsec-src/ventures/devsec-toolkit/devsec.py scan . --format json -o devsec.json
python3 devsec-src/ventures/devsec-toolkit/devsec.py scan . --fail-on high         # CI gate: exit 2

    For GitHub Actions, copy github-workflow.yml to .github/workflows/devsec.yml: it fetches about 3 MB, writes a summary to the job page, uploads SARIF to code scanning and fails on new high findings. Every action in it is pinned to a commit SHA.

    Already have hundreds of findings? devsec.py scan . --write-baseline .devsec-baseline.json once, then CI fails only on findings that are new. See the README for .devsec.json (skip checks, ignore paths, override severities).

    What it checks

    Each check is its own open-source tool in the same repository, with its own tests and its own page. devsec-toolkit runs the ones that apply to your repository and says which did not apply, so a repository with no Dockerfile never reads as a clean Docker scan.

    How it compares

    Paid platforms

    Snyk, GitGuardian, Socket, Aikido and Wiz bundle scanning with dashboards, triage and support, priced per developer or per repository. If you need those, buy them. devsec-toolkit is the free, local layer: no account, no upload, and output you own.

    Free single-purpose scanners

    zizmor (Actions), Trivy, Checkov, Semgrep, gitleaks and OSV-Scanner are excellent; keep running them. Each has its own install, output format and suppression scheme. devsec-toolkit covers ground they leave open, such as Actions cache and artifact poisoning, secrets: inherit, secrets re-encoded past log masking, AI-agent permissions, ReDoS and JWT misuse, behind one report and one baseline.

    Linter aggregators

    MegaLinter and Super-Linter run many tools from a large Docker image. devsec-toolkit is security-only, needs no Docker, fetches about 3 MB, and normalises every finding onto one schema rather than concatenating each tool's log.

    Questions

    Does a clean scan mean my repository is secure?

    No. A clean report means these 23 checks found nothing. It is not a security audit, a penetration test or a compliance attestation, and it does not look for vulnerable dependency versions, leaked credentials in git history, or flaws in your application logic.

    Does anything leave my machine?

    No. Every check reads files already on disk and none makes a network call. The report viewer on this page reads the file you open in your browser and never uploads it.

    Why not just run zizmor, Trivy, Checkov or Semgrep?

    Run them: they are excellent and free. devsec-toolkit covers checks they do not (Actions cache and artifact poisoning, secrets: inherit, secret re-encoding past log masking, AI-agent permission configs, hidden Unicode in instruction files, ReDoS, JWT misuse) in one zero-dependency command with one report and one baseline. Adapters that run those tools and merge their findings into the same report are on the roadmap.

    How do I adopt it on a repository that already has hundreds of findings?

    Write a baseline once with --write-baseline, commit it, and point .devsec.json at it. CI then fails only on findings that are new, and known ones stay suppressed even when their line numbers move.

    Do I need Docker or a package install?

    No. It needs Python 3.9 or later and, for the six checks written in JavaScript, Node.js 18 or later. Without Node those six are reported as skipped, never as passing.
